# 安全审计 —— 桂林医科大学教务适配器（`glmu`）

- 上游：`shiguang_warehouse` 的 `GLMU/glmu.js`（MIT，作者 **xhh李**；`adapters.yaml` 里 `adapter_id: GLMU_01`，
  `import_url: https://ejwc.glmc.edu.cn/`，描述写明「本校开发者适配」）
- 移植者：**NullClass**　日期：**2026-09-12**
- 审计对象：本目录 `extract.js` / `parse.js` 全文（`parse.js` 不碰网络，`extract.js` 只发同源请求）

## 1. 请求了哪些域

| 主机 | 用途 | 怎么声明的 |
|---|---|---|
| `ejwc.glmc.edu.cn` | ① `POST /xsgrkbcx!getDataList.action` 取课表行（分页，每页 100）<br>② `GET /xsgrkbcx!getKbRq.action?xnxqdm=…&zc=1` 取第 1 周日期（**探测**：404 / 非 JSON / 超长响应都直接放弃） | `loginUrl` 同源（两个都是相对路径），所以 `allowHosts` 为空 |

静态扫法的结论：上游脚本里唯一的绝对 URL 是 `https://ejwc.glmc.edu.cn/xsgrkbcx!getDataList.action`；
本目录 `extract.js` 里**一个绝对 URL 都没有**（`grep -nE "https?://" extract.js` 只命中文件头注释里的仓库地址），
两个请求都写成相对路径，落在 `loginUrl` 的同源域上。全程没有 CAS、WebVPN 或任何第三方域。

## 2. 逐条过移植手册 §5

| # | 检查项 | 结论 |
|---|---|---|
| 1 | **不碰凭据** | ✅ 不读 `password` / 登录表单值 / `localStorage` / Cookie；登录全程由用户在 WebView 里手工完成，脚本只用同源相对路径的 `fetch`（`credentials: 'include'` 是让浏览器带上会话，脚本自己不接触令牌）。提问接口只用于选学期，不问任何账号信息。 |
| 2 | **不外发** | ✅ 全脚本只有两处 `fetch`，都在本校教务域；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src`，没有统计或 CDN 上的业务接口。 |
| 3 | **请求域可控** | ✅ 唯一主机 `ejwc.glmc.edu.cn`，两个请求都是相对路径（同源），`allowHosts` 无需任何条目，**没有通配**。 |
| 4 | **只读课表** | ✅ 只调课表查询接口与同模块的排课日期接口；不请求成绩、学籍、个人信息、缴费等任何其它接口。 |
| 5 | **不埋点** | ✅ 无统计 / 上报 / 遥测；脚本里没有任何 `console` 输出，也没有向外部发送日志的行为。 |
| 6 | **不 eval 远程代码** | ✅ 无 `eval` / `new Function`；教务返回的字符串只做 `JSON.parse` 与字段读取。 |
| 7 | **不写页面** | ✅ 不写 DOM、不改表单、不触发提交、不点击页面元素（也不做上游那种「切到课表页」的跳转 —— 本适配器取数只走接口）。 |
| 8 | **不依赖用户输入之外的秘密** | ✅ 无硬编码密钥 / 令牌 / 他人学号。脚本里的常量只有接口路径、分页参数、学期候选个数与作息时间。 |

## 3. 读了什么

- `getDataList.action` 返回的行对象。适配器只使用 `kcmc`（课程名）、`teaxms`（教师）、`jxcdmc`（教室）、
  `zc`（周次）、`xq`（星期）、`jcdm`（节次）六个字段；
- **主动丢弃**行里的 `xh` / `xm` / `sfzh`（学号 / 姓名 / 身份证号）等个人字段：载荷用不到它们，
  也顺带让 fixture 天然脱敏（见 `extract.js` 的 `withoutPersonal`，这是本适配器对教务数据的**唯一**删改）；
- `getKbRq.action` 只取「第 1 周星期一的日期」，用来算开学日，不落库、不外发。

## 4. 与 hbmu 同平台的对照片：那四处差异逐条核对

上游 `GLMU/glmu.js` 与 `HBMU/hbmu.js` 逐字克隆，`diff` 只有四处差异。逐处核对结果：

| # | 差异 | 核对结果 |
|---|---|---|
| 1 | **文件头注释** | `HBMU/hbmu.js` 只有「功能：从湖医药教务系统…」一行；`GLMU/glmu.js` 多一行「文件: guilin_medical.js」。纯注释，不影响行为。✅ |
| 2 | **URL 主机** | `https://jw.hbmu.edu.cn/xsgrkbcx!getDataList.action`（湖医药）→ `https://ejwc.glmc.edu.cn/xsgrkbcx!getDataList.action`（桂医）。**路由与参数完全一致**，只有主机名不同。`ejwc.glmc.edu.cn` 与 `adapters.yaml` 的 `import_url` 同域，登录页可达。已按它写 `loginUrl`，并改成相对路径。✅ |
| 3 | **作息时间表（第 1–5 节）** | 见 §5 专章 —— 这是本适配器与 hbmu 唯一的**行为性**差异，已单独查证。⚠️ |
| 4 | **登录提示语** | 「请确保您已登录**湖医药**教务系统…」→「请确保您已登录**桂医**教务系统…」；学年输入提示语两校一致。这条对应上游的 `showAlert`，移植时整段被丢掉了（我们不做「点确定继续」的弹窗，改成按日期推算学期），所以不影响产物。✅ |

**三处纯文本差异之外，取数与解析逻辑是逐字相同的**：同一个接口路径、同样的
`xnxqdm=<4 位学年><2 位学期>` + `page` / `rows` 参数、同样的头部、同样的分页循环、
同样的 `kcmc/teaxms/jxcdmc/zc/xq/jcdm` 字段、同样的 `parseWeeks` / `parseSections` / `runImportFlow`。
所以 `parse.js` 的转换逻辑可以照 hbmu 的移植件走，**唯一不能照抄的就是作息表**。

## 5. 作息时间表专章（差异 3）

把 hbmu 的作息表照抄过来是错的：湖医药第一节课 08:00，**桂医是 08:30**。
两个独立来源已经对上了早晨时段：

| 节次 | 上游 GLMU 脚本 | 网上可查的「桂林医学院临桂校区作息时间表」 | 一致？ |
|---|---|---|---|
| 1 | 08:30–09:10 | 第一节课 8:30—9:10 | ✅ |
| 2 | 09:20–10:00 | 第二节课 9:20—10:00 | ✅ |
| 3 | 10:10–10:50 | 第三节课 10:10—10:50 | ✅ |
| 4 | 11:00–11:40 | 第四节课 11:00—11:40 | ✅ |
| 5 | 11:50–12:30 | 第五节课 11:50—12:30 | ✅ |
| 6 | 14:30–15:10 | 第六节课 14:00—14:40 | ❌ 差 30 分钟 |
| 7 | 15:20–16:00 | 第七节课 14:50—15:30 | ❌ |
| 8 | 16:10–16:50 | 第八节课 15:40—16:20 | ❌ |
| 9 | 17:00–17:40 | 第九节课 16:30—17:10 | ❌ |
| 10–12 | 19:00–19:40 / 19:50–20:30 / 20:40–21:20 | 同左 | ✅ |

**为什么要用上游那张表，而不是把下午改回 14:00**：第 6–12 节的值与 hbmu **逐字相同** ——
也就是说这两张表只差早晨那五节，下午与晚上共用的是一份模板。这意味着「14:30–17:40」这一段
**可能是两校共用的作息，也可能 hbmu 的作者就是从桂医那份抄走的**，从脚本本身分辨不出来。
而 `adapters.yaml` 写明 GLMU 是「本校开发者适配」：这三张表在桂医学生手机上真跑过，学校的公告
（含那份「临桂校区作息时间表」）反而可能不是教务处当前执行的那版。所以取数处
**照上游原样给**，不擅自改成一个我无法验证的第三方口径。

**代价已经写进载荷的 `warnings`**：每条 GLMU 载荷都会带一句「上下课时间取自适配器内置的桂医作息表
（第一节 08:30），下午与晚上的时间未能与学校公开作息表核对一致，请在『学期管理』里核对一遍」。
作息表决定课表里每节课显示的时间，不说用户没有任何机会发现。

> **拿不到权威口径 ≠ 猜**：这里没有推断成分，只是「照上游给 + 明说没核对上」。
> 谁哪天拿到教务处当学期的作息表，改 `parse.js` 的 `PERIOD_TIMES` 并重跑门即可，`warnings` 那行同时删掉。

## 6. 移植时逐条对照（批次审查清单 8 条）

| # | 项 | 结论 |
|---|---|---|
| 1 | **单/双写在「周」之后**（`1-16周(双)`） | ✅ `weeksOfText` 把「周」整个删掉再切段，单/双标记不会丢；`1-16周(双)`、`双周1-16`、`1-8周(单),9-16周(双)`、`单双周` 四种写法各有用例（`weeks-parity`）。**变异测试：把删除改成替换成空格 → 该用例变红。** |
| 2 | **括号里的纯数字序号 `(1)` 不是周次** | ✅ 本平台的 `zc` 只用「区间 + 单/双」，上游也没有把「括号里的数字」当周次读（`parseWeeks` 只按逗号切、按 `-` 展开）。`odd-week-text` 用例里有 `1-16周(1)`，期望值仍是整整 1–16 周 —— 把括号数字拼进判定会让它塌成 1–1，**变异测试确认该用例会变红**。 |
| 3 | **读不出节次的行不许静默丢** | ✅ `sectionRangeOf` 读不出的行计入 `missing.period`，逐条计数进 `warnings`；带文字的写法（`第9节`）也能认。另有一条更严的：**周次栏里有认不出的段落**（如 `第周`）单独计数并进 `warnings` —— 而且这个计数**不只在「一条周次都没解析出来」时才触发**（上游式实现里，单/双标记段合并后会连同它旁边的周次段一起消失，只在全丢时才记的话会被静默吞掉）。`odd-week-text` + 变异测试盖住。 |
| 4 | **连堂 → `periodTimes` 覆盖每一节** | ✅ 载荷的 `periodTimes` 是 12 节全天表（1–12 节连续、无缺号），任何 `startPeriod..endPeriod` 的连堂都落在表内，不存在「缺的补出来」的场景。三节连堂（`jcdm="05-07"`）在 `basic` 用例里，**变异测试：把区间展开收成两节 → 该用例变红**。 |
| 5 | **分页：没回 `total` 也不能只取第一页** | ✅ `extract.js` 的 `fetchRows` 不再沿用上游「`collected >= total` 才停」（`total` 为 `undefined` 时该条件永不成立）；改成「回总数按总数停、没回总数按『这一页取满了吗』停」，最多 10 页，并把 `total` / `truncated` 一起交给 `parse.js`。`no-total`（取全）与 `no-total-truncated`（翻到上限）两个用例分别验两种收尾，**变异测试：把 `truncated` 分支关掉 → 用例变红**。 |
| 6 | **总周数被更晚的周次抬高要出声** | ✅ `totalWeeks = max(maxWeek, 20)`，`maxWeek > 20` 时走另一句 `warnings`（「课表里最晚排到第 N 周，已把学期总周数按 N 周计」），`late-week` 用例（1-25 周）专门盖这条，**变异测试：把总周数钉死 20 → 该用例变红**。 |
| 7 | **`AUDIT.md` 与代码一致** | ✅ 本文档 §1 的主机表、§3 的读取字段清单都是从 `extract.js` / `parse.js` 正文抄出来的；`allowHosts` 为空与代码里「只有相对路径」一致；上表每一条都在代码里有对应实现，没有写得比代码窄。 |
| 8 | **fixture 期望值独立推出 + 变异测试** | ✅ 6 个用例的期望值都按 `docs/jw-adapter-spec.md` §4 手推（周次切段规则、连堂起止、开学日、`totalWeeks` 下限），**不是**把 `parse.js` 的输出贴进去。8 处变异全部被用例抓住（表格见 §7）。 |

## 7. 变异测试记录（证明用例真的在看着代码）

在 `parse.js` 的**副本**上逐处改坏、重跑全部 6 个用例（不碰仓库里的源文件）：

| 变异 | 变红用例 |
|---|---|
| 「周」删掉 → 换成空格（差分单双会丢） | `weeks-parity`、`no-total-truncated` |
| 节次区间收成两节（`05-07` → 只占 5、6） | `basic` |
| 连续段步长 2 不标单双（全当 `ALL`） | `basic`、`weeks-parity`、`no-total`、`no-total-truncated` |
| 总周数钉死 20（不随课表抬高） | `late-week` |
| 没回 `total` 也不出声 | `no-total-truncated` |
| 带文字标签的节次读不出来 | `odd-week-text` |
| 认不出的周次原文不收集（静默丢课） | `odd-week-text` |
| 周次里括号数字参与判定（`1-16周(1)` → 1–1 周） | `odd-week-text` |

**「盖不住的变异」为空**（先前的两处盲区 —— 单段 `1-16周(双)` 盖不住第 1 条、两节区间盖不住第 2 条 ——

## 8. 与上游的差别（只列安全性 / 隐私相关的）

1. 上游把课表数据交给 `window.shiguangBridge*` 桥（拾光的宿主接口）；这里改成 **return 一个 JSON 字符串**，
   不触碰任何页面全局；
2. 上游用 `showAlert` / `showPrompt` / `showSingleSelection` 弹窗问学年与学期；这里改成按日期推算学期，
   只有推算结果取不到课时才用 `__ncSelect` 问一次（桥不存在就直接降级，不阻塞）；
3. 上游直接把整个行对象往上传；这里先剔掉个人信息字段；
4. 上游把作息时间写给「预设时间段」；这里作为载荷的 `periodTimes` 交给应用，不写任何全局状态。

## 9. 明确没做到的（如实记录）

- **fixture 是合成的**（`fixtures/*.extracted.json` 顶部有 `_note` 注明）：手上没有该校账号，
  只按上游脚本实际读取的字段形状编造。它只保证「同样输入 → 同样输出」，**不保证在真实教务上解析正确**；
- 真实环境才能验的：接口路径与参数是否仍有效、`zc` / `jcdm` 的真实写法、`getKbRq.action` 是否真的存在、
  分页行为、开学日探测的成败（失败会走「最近的周一」推算并在载荷 `warnings` 里说明）；
- **`getKbRq.action` 是猜的**：上游 GLMU 脚本里没有这个请求（它只调 `getDataList.action`），
  这个路径是从同平台、同前缀的部署推出来的探测请求。失败即放弃并退回推算，所以最坏结果是
  「开学日按最近的周一推算 + 载荷里说明」，不会把错的日期写进库；
- 拿不到的字段：**开学日与总周数**教务接口不给。开学日优先用探测接口，拿不到就按最近的周一推算
  并在 `warnings` 里如实说明；总周数按「不早于最晚周次、不少于 20 周」给（学校作息是 20 周），
  同样进 `warnings`（这两条推算值在库里跟真值长得一模一样，不说用户没有机会发现）；
- **下午与晚上的作息时间没能与学校公开口径核对一致**（§5），照上游给并在 `warnings` 里说明；
- 上游作者写这段时是否真的在桂医跑过、跑的是哪个学期 —— 无法验证；`adapters.yaml` 只写了
  「本校开发者适配」。`zc` / `jcdm` 的真实取值范围同样没有样本；
- 上游快照：本适配器移植的是 `shiguang_warehouse` 在 `2026-09-12` 的 `GLMU/glmu.js`
  （`adapters.yaml` 里 `adapter_id: GLMU_01`、`maintainer: xhh李`）。上游日后修 bug 时按测试方案 §5
  重新移植，不打补丁；
- manifest **不写 `scheduleUrlHint`**：取数只走接口，用户停在教务站任意一页都能提取，写一个没验证过的
  课表页路径反而可能把人带到 404。
