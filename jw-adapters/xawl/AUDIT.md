审计对象：`jw-adapters/xawl/` 下的 `extract.js` / `parse.js`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `XAWL/xawl_01.js`（快照 commit
`e62554a4034386b893bcd6813c7b2b64f8c730a3`，2026-09-12 12:50:29 +0800，MIT，
上游 commit 作者 / `adapters.yaml` 的 maintainer 均为 `星河欲转`）。

审计方式：逐行读上游脚本 + 逐行读移植件，并跑移植手册 §5 给的静态扫描
（绝对 URL 扫描、`fetch` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` / `EventSource` /
`.src =` / `eval` / `new Function` / `localStorage` / 写入 DOM 的调用扫描），
另外把上游那段 `parseWeeks` **原样跑了一遍**，用它自己的输出当对照（见 §5）。

## 1. 请求域与请求清单（本节必须与代码一致，不许写得比代码窄）

上游脚本里**只有两个绝对 URL，都是同一个主机**（`grep -oE` 扫出来的结果：
`http://jwgl.xawl.edu.cn` 出现 2 次），两条 `fetch` 里只有一条真的会发出去
（另一条是 `isLoginPage()` 里用来做字符串比较的常量）。

移植件把主机名换成了**运行时从 `window.location` 拼出来的当前源**，所以脚本里
**一个绝对请求地址都没有**（`grep` 命中的两个 `https://github.com` 都在文件头的出处注释里，
不是请求）。全部请求落在用户当前所在的那一个教务主机上，即 `loginUrl` 的主机
`jwgl.xawl.edu.cn`。**`allowHosts` 留空**，不写通配。

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | POST | `<当前页面 origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151`，body `xnm=<四位起始学年>&xqm=<3 第一学期 / 12 第二学期>` | 取该学期的全部排课行（JSON） | 报错并提示重新登录 / 去课表页确认 |

- **就这一条请求。** 与同族的 `cfec` 不同，移植件**没有**另取作息接口（`xskbcx_cxRjc.html`）
  与学期周次校历接口（`xskbcxZccx_cxZcByXnxq.html`）—— 上游 XAWL 脚本不请求那两个接口，
  本校部署上有没有它们无从验证（没有账号），所以不臆造请求。作息用上游自己那张表（见 §3），
  开学日按学期序号推算并**在 warnings 里说明**（见 §4 第 4/7 条）。
- `manifest.scheduleUrlHint` 指向课表查询页
  `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default`。
  它是**应用**给「一键刷新」用的落地页，不是脚本发的请求；菜单号 `N2151` 与上游请求课表数据用的
  `gnmkdm` 完全相同（同一菜单模块），但这条地址**没有在真机上验证过**（见 §8）。
  `JwOriginRules` 会把它也加进桥的 origin 白名单，仅此而已。
- 请求头只带 `Content-Type` / `X-Requested-With` / `Accept`，**不带任何自定义令牌**；
  Cookie 由 WebView 按同源规则自己带上，脚本既不读也不写它。
- `parse.js` **不发任何请求、不碰页面**（CI 里用 Rhino 实跑）。

## 2. 读了什么

- `window.location.origin` / `window.location.pathname` —— 只用来拼上面那条同源地址
  （页面挂在门户 / 网关前缀下时跟着当前地址里的 `/jwglxt` 那一段走）。
- 当前文档里 `#xnm`（学年）与 `#xqm`（学期）两个下拉框的 **value 与选中项文本**。
  只读，不写、不改、不提交；页面上没有这两个框就跳过（不是错误）。
- 课表响应的 JSON：优先读 `kbList`（上游就是读它），退化认 `items` / `rows` / `list`，
  并把**实际用的键名**带进载荷（不是 `kbList` 时 `parse.js` 会在 warnings 里说明）。
  四个都没有就交空行数组，`parse.js` 据此报错。
- 每条排课行**只带走 8 列**：`kcmc`（课名）/ `xm`（教师）/ `cdmc`（场地名）/ `cdbh`（场地编号）/
  `xqj`（星期）/ `jcs`（节次）/ `jc`（节次，兜底）/ `zcd`（周次）。上游 `parseJsonData` 读的是前 6 列
  加 `zcd`；`jc` 是**防御性**多留的一列 —— `parse.js` 的节次解析本来就是「先读 `jcs`、读不到再读 `jc`」，
  少数同族部署只给 `jc` 不给 `jcs`（同批的 `taru` / `zcmu` 也记了这条）。投影里若不带上 `jc`，
  那条兜底永远拿不到值，这些部署的**每一行**都会因「缺节次」被跳过、整个学期解析不出任何课程；
  而 `extract.js` 不进 CI（门只跑 `parse.js`），这个错门看不见。
  课表响应里夹带的 **`xh`（学号）等个人信息一律不带出**，也不进 fixture。
- 记录总数（`total` / `totalResult` / `totalCount` / `count`），只用来对账（见 §4 第 6 条）。
- `parse.js` 另外会在 `data.today` 缺失或不是日期时读一次本机时钟（`localTodayIso()`），
  以及学年字段读不出来时按「今天的周一」推算开学日。**三个 fixture 都提供了 `today`**，
  所以 CI 里这两条分支不会走到、结果是确定的。

## 3. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。两个脚本都没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` / `document.cookie` 访问（静态扫描无命中）。唯一的「凭据」是浏览器自带的会话 Cookie，脚本既不读它也不把它发到别处。上游的 `showPrompt`（问学年）没有被移植，**不存在借弹窗索要信息的可能**：移植件连提问桥都没用 |
| 2 | 不外发 | **过**。全部 `fetch` 只有 `extract.js` 里那一处，地址由 `window.location` 拼成；没有 `XMLHttpRequest` 对象 / `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单 / 动态插 `<script>`。唯一的第三方域名是文件头注释里的 `github.com`（出处链接，不是请求）。上游脚本里也只有本校一个域 |
| 3 | 请求域可控 | **过**。请求主机只有一个：`loginUrl` 的主机 `jwgl.xawl.edu.cn`（`loginUrl` 给的是 http，应用会显示「不安全连接」标记）。脚本里**没有硬编码主机名**，按当前 origin 拼；因此即使学校换到 https 或挪到别的子域，也不用改脚本。`allowHosts` 留空，不写通配 |
| 4 | 只读课表 | **过**。唯一一条请求落在 `/jwglxt/kbcx/xskbcx_cxXsgrkb.html`（课表查询模块），**不碰成绩（`/cjcx/*`）、学籍、个人信息、缴费、选课**等任何其它接口。响应体里夹带的学生信息（正方放在 `xh` / `xsxx` 之类的字段里）在 `extract.js` 里就被**按列过滤掉**，不进载荷也不进 fixture |
| 5 | 不埋点 | **过**。没有任何统计 / 上报 / 遥测，也没有图片打点 |
| 6 | 不 eval 远程代码 | **过**。两个脚本都没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse`（包在 try 里，失败就报「登录可能已失效」） |
| 7 | 不写页面 | **过**。`extract.js` 只**读** `#xnm` / `#xqm` 两个字段的值；没有 `document.write` / `innerHTML` / `appendChild` / `.submit()` / `.click()`。上游那套桥调用（`showToast` / `showAlert` / `showPrompt` / `showSingleSelection` / `saveImportedCourses` / `savePresetTimeSlots` / `notifyTaskCompletion`）**一个都没有移植** |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码密钥、令牌、他人的学号或固定会话。脚本里的常量只有正方的菜单号 `N2151`、上下文路径 `/jwglxt` 与两张作息表，都是公开的页面参数 / 学校公开的作息时间 |

**结论：可以进内置库。** 一条请求、只读课表、不碰凭据、不外发、不埋点、不写页面。

## 4. 本批（批次三）10 条检查表逐条

1. **周次编码四写法**：**过**，且**每一种都有独立用例**（`weeks-parity`）：
   `1-16周(单)`（标记在「周」后）/ `(单)1-16周`（标记在前）/ `1-16(单周)` / `1-3,5-9周`（混排），
   双周侧同样三写法 + 混排。实现上是**先把「周」整个删掉、再切段**，所以四种写法归一成同一件事，
   不会出现「标记落进另一段被丢掉」。
   **上游这里是真的会错**（把它的 `parseWeeks` 原样跑一遍的实测结果，见 §5 表）：
   `1-16(单周)` → 空数组（这门课**静默消失**）、`1-3,5-9周` → 只剩 5-9（前一段**静默丢失**）、
   `1-16周,双周` → 1..16（双周标记**静默丢掉、塌成每周都上**）。移植件把这三处都补上了，
   并且认不出的标记会**计数写进 warnings**（`orphanMarkers`）。
   **破折号两侧的空白**是同一族的第五个坑，已复现并修掉（`week-spacing` 用例）：
   切段前先剥空白，`1 -16周(单)` 曾经被切成 `1` + `16周(单)`（只剩第 1 周、「单」跟着后半段跑掉），
   `1- 16周` 曾经被切成 `1-` + `16`（两块孤立的 1 周与 16 周，中间 14 周静默丢失）。
   做法是**先把破折号（半角 / 全角 / 波浪 / 减号 / 汉字「至」）连同它两侧的空白归一成半角 `-`**，
   再把剩下的空白当段分隔补成逗号 —— 区间再也不会被切开，而空白仍保留分段语义
   （`1-16周 双`、`1-3周 5-9周` 都还是两段）。
2. **括号内纯数字不是周次**：**过**。`(1)`、`(1-2)`、序号写在前（`(1-2)1-16周`）都有用例。
   规则是：**括号外还有周次数字**就把括号里的序号摘掉；**整串只剩括号里的序号**（`zcd` 就是 `(1)`）
   则判定「这一行没有可用的周次」—— **不猜成第 1 周**，单独计数（`serialOnlyRows`）并写进 warnings
   说明原因（「只有括号里的教学班序号…已跳过」）。两种情况都在 `weeks-parity` 里有用例。
3. **无星期表头兜底**：**不适用，但规则遵守**。这个适配器走的是 **JSON 接口**（上游读 `kbList` 行的
   `xqj` 字段），页面上没有表格，所以不存在「按数组长度猜列」的问题 —— 全文件没有任何一处在
   用 `length - 7` 之类的算术推列号，星期一律取 `xqj` 字段本身（`1..7` 之外按「缺星期」计数并警告）。
   上游返回 HTML 表格形态的可能性：上游脚本自己读的是 JSON，**以它读的为准**，移植件不做 HTML 解析。
4. **时间合法性**：**过**。写进 `periodTimes` 的每个时间都来自两张**字面量表**（上游的
   `Non_summerTimeSlots` / 空课内建表），并且**每个都过一遍 `sanitizeSlots()` 校验**：
   必须匹配 `HH:mm` 且落在 00:00-23:59、结束晚于开始；不合格的替换成空课内建节次表的对应节
   并写进 warnings，而**不是**让整个载荷被应用拒收。课表用到第 11-12 节（超出学校 10 节的作息表）时
   按内建表补齐并单独说明 —— `dirty-rows` 有用例。
5. **`warnings` 上限**：**过**。条数上限 20、单条 200 字。`warn()` 里对每条做了**先截断再入数组**
   （超过 200 字截到 199 字加省略号）。这条链上**最多产生 13 条**（学期来源 / 开学日 / 总周数 /
   作息 / 节次补足 / 作息兜底替换 / 字段名 / 记录总数 / 跳过行 / 只有序号 / 超限周次 / 孤儿标记 /
   多段节次），离 20 条上限有 7 条余量。四个用例实测 4 / 10 / 7 / 4 条。
6. **分页**：**此接口没有分页**（上游请求里没有页码参数，一次返回整学期）。仍然对账：
   `extract.js` 把响应里的记录总数带出来，`parse.js` 发现它**大于实际取到的行数**时写进 warnings
   （「课表可能不完整，请重试或反馈」）。`dirty-rows` 有用例（说 20 条、回 13 条）。
7. **学期名**：**过**。用教务自己的学年学期 —— `#xnm` 下拉框的文本（如 `2026-2027`）
   拼上「学年第 X 学期」，`X` 取 `#xqm` 的文本 / 代号（3→一、12→二、16→三）。
   拿不到下拉框文本时用学年代号拼「2026-2027学年第一学期」。**没有用适配器名当学期名**。
   开学日这个接口给不出来，按学期序号推算（第一学期 = 9 月 1 日所在周的周一、第二学期 = 2 月 20 日
   所在周的周一、第三学期 = 7 月 1 日所在周的周一），**推算值和推算依据都写进 warnings**。
8. **`teacher` 拿不到就留空**：**过**。上游写的是 `rawCourse.xm`（没有兜底词，这点上游是对的），
   移植件仍然显式做 `text(row.xm) || null`，教师 / 教室为空就是 `null`，不写「未知」「暂无」。
   `basic` 的「大学物理」、`dirty-rows` 的「自习」都是教师为空的用例（后者教室也为空）。
9. **`allowHosts`**：**过**。留空数组 —— 只放行 `loginUrl` 的同源主机（`JwAdapter.allowedHosts`
   会自动把 `loginUrl` 的主机加进去）。不写 `*.` 通配，也不硬编码主机名；路径全是相对当前 origin 拼的。
   **本适配器不用 OCR 桥也不用提问桥**（源码里不出现 `__ncOcr` / `__ncOcrGrid` / `__ncSelect` /
   `__ncConfirm` / `__ncPrompt`），所以「通配拿不到桥」这条对它不适用。
10. **每件都要做变异测试**：**做了，8 处**，其中 6 处变红（见 §7）。
    一处不红的是「作息表时间校验失效」—— 那两张表是字面常量，本来是合法的，
    这个守卫是为了**以后有人手改表时不至于让整个载荷被拒**，所以它在当前 fixture 上无法通过输入触发。
    这不是覆盖缺口，是守卫的作用域；已如实记在这里而不是含糊过去。
    另一处（M8，`extract.js` 的 `KEEP` 去掉 `jc`）**CI 根本验不到** —— 门只跑 `parse.js`，
    所以它是用 CI 之外的桩（假 `window` / 假 `fetch`，把 `extract.js` 的投影直接喂给 `parse.js`）
    证明变红并写进 §7 的，**不能算进 CI 的覆盖里**。

## 5. 与上游 XAWL 脚本的对照片（本批「同族 ≠ 同编码」的实证）

`XAWL/xawl_01.js` 与同族的 `CFEC/CFEC.js` 同平台（正方新版 `jwglxt`），但**取数路径与编码都不同**，
所以两段脚本都是按 XAWL 自己的数据重写的，没有照抄 `cfec` 的 `parse.js`：

| 层 | 能不能复用 | 本次结论 |
|---|---|---|
| 接口信封（POST 表单 + `{kbList:[...]}`） | **能** | 与 cfec 同一套。移植件沿用「响应必须是对象、`kbList` 是数组」的判据，并额外容忍 `items` / `rows` / `list` |
| 行字段名（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd`） | **能** | 上游 XAWL 读的就是这 6 列（cfec 多读 `cdbh` / `jc` / `xqh_id`）。移植件多留了 `cdbh` 当教室兜底，另外**防御性**留下 `jc` 当节次兜底（`parse.js` 本来就是「先读 `jcs`、读不到再读 `jc`」；投影不带 `jc` 的话那条兜底是死分支），其余不读 |
| **取数路径** | **未必 —— 确实不同** | cfec 的 body 多带 `kzlx=ck&xsdm=&kclbdm=&kclxdm=` 四项，XAWL 上游只发 `xnm` + `xqm`；cfec 另外请求作息与校历两个接口，**XAWL 上游一个都不请求**。移植件按 XAWL 自己的写法：**只发一条请求、只带两个参数**，不臆造另外两条 |
| **周次 / 节次编码** | **未必 —— 确实不同** | 见下表（把上游 `parseWeeks` 原样跑出来的实测结果）。节次上游用 `jcs.split('-')` 取首尾，`0102` 这种会算出「第 102 节」；移植件改成逐段解析并限制在 1-12 节 |
| 分页行为 | **不适用** | 两边都没有分页参数；移植件仍对账记录总数 |

上游 `parseWeeks` 的实测（把 `xawl_01.js` 里那个函数抽出来在 node 里跑）：

| 输入 | 上游输出 | 说明 |
|---|---|---|
| `1-16周` | 1..16 | 对 |
| `1-16周(单)` | 1,3,5,…,15 | 对 |
| `(单)1-16周` | 1,3,5,…,15 | 对（标记在前它也能认） |
| `1-16周(双)` / `2-16周(双)` | 2,4,…,16 | 对 |
| `1-16(单周)` | **[]** | **整门课静默消失** |
| `1-3,5-9周` | **[5,6,7,8,9]** | **前一段 1-3 静默丢失** |
| `1-16周,双周` | **1..16** | **双周标记静默丢掉，塌成「每周都上」**（正是测试方案 §3.1 点名的那类 bug） |
| `1-16周 双` | **1..16** | 同上 |
| `1-16周(1)` / `1-16周(1-2)` / `(1-2)1-16周` | 1..16 | 对（它的正则要求「数字紧跟周字」，序号不会被吃成周次） |
| `(1)` / `单周` / `1-16` | **[]** | 这门课被 `if (weeksArray.length === 0) continue;` 静默丢掉，**不留痕迹** |

移植件对这 11 种输入的输出全部可接受：能认的照认，认不出的（`单周`）计数进 warnings，`(1)`
单独计数说明「只有括号里的序号」，`1-3,5-9周` 与 `1-16周,双周` 按真实语义切段。

## 6. 移植时对上游做的删改（都不牵涉安全问题，但审阅者要知道）

1. **ES6 → ES5**：`async/await` 改成 `then` 链，不使用模板串、箭头函数与块级声明关键字。
2. **不问用户**：上游用 `showPrompt` 问起始学年、用 `showSingleSelection` 问第几学期
   （再映射成 xqm 3 / 12），用 `showSingleSelection` 问夏季 / 非夏季作息。移植件全部去掉：
   学年学期**先读课表页当前选中的下拉框**（用户自己切过的那个优先），读不到才按今天的日期推定
   （8 月起到次年 1 月算第一学期、2-7 月算第二学期）；作息**直接按非夏季作息写入**
   （这正是上游在用户取消选择时的默认值），并把夏季作息的差异写进 warnings。
   两种取的来源都记在 `term.source` / `warnings` 里，用户看得见，不是静默选择。
3. **切两段**：上游在同一个脚本里取数、算周次、拼课程、存作息、弹 toast；移植件把取数留在
   `extract.js`（只交出 7 列排课行 + 学期信息 + 记录总数），周次解析、节次解析、课程合并、
   开学日与总周数、作息补齐全部落在 `parse.js`，这段逻辑因此在 CI 里有真回归。
4. **教师 / 教室为空不再有兜底词**：上游 `saveCourses` 之前没有兜底词（这点它是对的），
   移植件保持留空（`null`）。
5. **脏数据不再静默丢**：上游 `if (!rawCourse.kcmc || ... ) continue;` 与
   `if (weeksArray.length === 0) continue;` 都是静默丢课；移植件按缺课名 / 缺星期 / 缺节次 /
   缺周次四类计数，另外单列「只有括号序号」「周次超出 1-30」「孤儿单双标记」三类，全部进 warnings。
6. **重复排课行去重**：上游不去重（同一门课同一时间的重复行会存两遍）；移植件按
   「星期 + 节次 + 周次段 + 教室」去重。

## 7. 变异测试记录（改坏哪一处 → 哪条用例变红）

做法：把 `parse.js` 里的目标行改坏 → 跑四个用例 → 记下哪条红 → 还原 → `diff` 与备份逐字节比对。
**每一轮都还原并校验通过**（还原后 sha256 与备份一致，四个用例回到全 MATCH）。

`basic` / `weeks-parity` / `dirty-rows` 是移植时写的三份用例；**`week-spacing` 是对抗式验收
复现出 B9 / B12 之后补的**，专盖那两条 —— 下面的 M7 / M8 就是它的反向对照。

| 变异 | 改坏的地方 | 结果 |
|---|---|---|
| M1 | 括号里的教学班序号不再摘掉、也不再判定「没有周次可用」（整段摘号逻辑短路） | `weeks-parity` **DIFF**；`basic` / `dirty-rows` 仍 MATCH。具体：「序号不是周次一」的 block 从 `1-16周` 变成 `1-30周`、「序号写在前面」变成 `1-21周`、「只有括号序号」冒出一门第 1 周的课，另有 3 条 warning 消失 → **证明这条用例盖的是 basic 盖不到的那条路径** |
| M2 | 单/双周标记整体失效（`onlyOdd` / `onlyEven` 的跳过分支短路） | `basic` **DIFF** + `weeks-parity` **DIFF**。具体：`大学英语(1)` 从 ODD(1-15) 变成 ALL(1-16)，`计算机导论` 从 EVEN 变成 ALL → **就是「塌成每周都上」那个 bug** |
| M3 | 整串只有 `(1)` 时返回 `[1]`（把教学班序号猜成第 1 周） | `weeks-parity` **DIFF**：凭空多出「只有括号序号」这门第 1 周的课，且少一条 warning |
| M4 | 记录总数大于实际行数时不再出声 | `dirty-rows` **DIFF**：少一条「课表可能不完整」的 warning |
| M5 | 自己成段的单/双标记不并回周次段（并段逻辑删掉） | `weeks-parity` **DIFF**：「标记自己成段」「标记用空格分开」两门从 EVEN 变成 1-16 全周，且孤儿标记 warning 消失 |
| M6 | 作息表的时间校验短路 | **四个用例都没红** —— 见 §4 第 10 条的说明：两张表是字面常量，本来就合法，这个守卫在 fixture 上无法通过输入触发（它防的是「以后有人手改表」）。如实记录，不当成覆盖 |
| M7 | **（B12）去掉切段前的破折号归一**（`cleaned = cleaned.replace(/\s*[-~至—－−–～]\s*/g, '-')` 整行删掉） | `week-spacing` **DIFF**；`basic` / `weeks-parity` / `dirty-rows` **仍全 MATCH**。具体：「破折号前有空格」的 block 从 `ODD 1-15` 变成 `ALL 1-1`（**整门课塌成只上第 1 周**）、「破折号后有空格」从 `ALL 1-16` 变成两块 `1-1` + `16-16`、「破折号两侧有空格」从 `EVEN 2-16` 变成 `ALL 1-1`、「汉字至」从 `ALL 1-16` 变成两块 → **三份旧用例对这条路径零覆盖，正是它当初没被发现的原因** |
| M8 | **（B9）`extract.js` 的 `KEEP` 里去掉 `jc`**（`'jcs', 'jc', 'zcd'` → `'jcs', 'zcd'`） | **CI 验不到**（门只跑 `parse.js`，`extract.js` 永不执行）。用 CI 之外的桩验：假 `window` / 假 `fetch` 跑 `extract.js` → 投影后 `row0` 的键里**没有 `jc`**；再把这份投影喂给 `parse.js` → 只有 `jc` 的那门课**整门消失**，warnings 里只多一条「有 1 行课表数据不全（缺节次…）」。对照未变异的 `extract.js`：同一份输入解析出 2 门课。→ 这类部署**整个学期解析不出任何课程**，而门看不见 |

另外：**期望值是独立推出来的**，不是把 `parse.js` 的输出贴进 `expected.json`。
四个用例的 `expected` 都是先按规范手算（周次文本 → 周次集合 → 极大段 + 单双周类型；
开学日按学期序号回退到周一；总周数取课表最大周次；节次取字段本身），算完才去跟脚本输出比，
不一致就查是哪边错。日期只用 `python` 的日历算过一遍（2026-09-01 是周二 → 所在周周一 2026-08-31；
2026-02-20 是周五 → 2026-02-16；2025-09-01 是周一 → 它自己）——**没有拿脚本输出反推期望**。
`week-spacing` 的 12 门课全部先手推出周次段与节次（`1 -16周(单)` 手推为单周 1-15、
`1- 16周` 手推为 1-16、`1- 16周(双)` 手推为双周 2-16、`1-3周 5-9周` 手推为两段 1-3 与 5-9），
**第一次跑就全 MATCH，没有回改过任何一个期望值**。

## 8. 没能确定的事（交接给下一位）

- **fixture 是合成的**：按上游实际读取的字段形状编出来的形状正确的数据，**不是真实抓取**，
  课程 / 教师 / 教室 / 日期均为虚构。它只保证「同样的输入永远得到同样的输出」，
  **不保证真实数据上解析正确**（测试方案 §3）。拿到真实 dump 后请替换 fixture 并重跑门。
- **`scheduleUrlHint` 那条课表查询页地址没有验证过**：没有账号，进不去。判断依据是它和上游实际
  请求的数据接口**用同一个菜单号 `N2151`**，属于同一个菜单模块（同族的 `cfec` 也是这两个地址成对出现）。
  万一这个部署没有这个页面，后果是**轻的**：「一键刷新」打开一个 404，而 `extract.js` 的流程不受影响
  —— 它读不到 `#xnm` / `#xqm` 就按日期推定，那条同源 POST 在任何一个正方页面上都能发出去。
  真机上如果发现**学期总是推定的**，先查这里。
- **学年学期推定在学期交界处会不准**：8 月算下一学年的第一学期、2-7 月算第二学期，是按中国大陆
  高校的普遍校历定的。如果教务里学期还没发布、或者和日期推定打架，`parse.js` 会在
  「没有返回任何排课记录」时明确报错，并提示用户去课表页确认 ----- 那时用户在课表页上，
  下一次提取就能读到 `#xnm` / `#xqm`，自然就对了。
- **第三学期（xqm=16，夏季学期）**：上游只支持 3 / 12 两个代号，移植件额外认了 16
  （学期名写「第三学期」、开学日锚点取 7 月 1 日所在周的周一）。**这个消息在移植件里没有用例覆盖**
  （上游脚本不产生它，我们也没有真实数据能造），属于防御性容忍。
- **作息只有非夏季一张表进载荷**：学校真实的夏季作息在 5-9 月生效，而一个学期里学校会换表，
  所以任何单张表都对不上一整个学期。移植件的处理是：写非夏季表 + **在 warnings 里写明夏季表差多少**
  （第 5 节 14:30 起、第 9 节 19:30 起），让用户在学期管理里自己换。上游是让用户在导入时二选一，
  移植时按移植手册 §3 第 1 步去掉了这次打断。
- **`extract.js` 的正确性没有任何自动覆盖**（测试方案 §1：门只跑 `parse.js`）。
  本轮修掉的 B9（投影漏 `jc`）就是这类错：它只在「学校把节次写在 `jc`」时才发作，
  而**发作时是灾难性的**（整个学期一门课都解析不出来），CI 却全程绿色。
  目前只能靠：代码静态核对 + CI 之外的桩（假 `window` / 假 `fetch`，见 §7 的 M8）。
  **桩不在门里**，改动 `KEEP` 时务必手动重跑一遍。
- 需要真实环境才能验的：登录后的会话是否被这条接口接受、课表页里是否真有 `#xnm` / `#xqm`
  两个选择框、菜单号 `N2151` 是否仍然有效、`loginUrl` 给的是 http（应用会显示「不安全连接」标记，
  学校如果也开了 https，维护者可以直接换成 https）。
