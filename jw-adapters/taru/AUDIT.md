## 1. 请求了哪些主机与路径（手册 §5 第 3 条、检查表第 9 条）

上游 `taru_01.js` 里硬编码了一个绝对地址：

```
POST https://jwgl.taru.edu.cn/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151
     body: xnm=<起始学年>&xqm=<3|12>
```

移植件沿用同一路径与同一 body，另外两处（读当前学年学期、读节次时间）是移植时加的：

| 谁 | 方法 | 地址 | 干什么 |
|---|---|---|---|
| extract.js | GET | `<教务主机>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期下拉框（`#xnm` / `#xqm`）。**用户已经在课表页时这一步跳过**，直接读页面上的这两个字段 |
| extract.js | POST | `<教务主机>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表（JSON，`kbList` 排课行）；body 与上游一致：`xnm=&xqm=` |
| extract.js | POST | `<教务主机>/jwglxt/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151` | 取节次时间（JSON 数组）；body `xnm=&xqm=`。**取不到不算失败**，交给 parse.js 回落内置节次表并写进 warnings |

- `<教务主机>` = `jwBase()`：地址里带 `/jwglxt/` 时用**当前页面同源**，否则回落到常量
  `https://jwgl.taru.edu.cn`。**实际请求的主机只有一个**：`jwgl.taru.edu.cn`
  （本校正方 `jwglxt` 的部署主机）。本件两个脚本的绝对 URL 扫描
  （`grep -oE "https?://[A-Za-z0-9._:%-]+" jw-adapters/taru/*.js`）只有三处命中，
  没有一处是别的域：`extract.js` 里注释中的上游仓库地址、`extract.js` 里的课表主机常量、
  `parse.js` 里注释中的上游仓库地址。
- 请求头只有 `Content-Type` / `X-Requested-With` / `Accept` 三个固定值，**不带任何自定义令牌**；
  Cookie 由 WebView 按同源规则自己带上，脚本不读也不写它。

### `allowHosts` = `["jwgl.taru.edu.cn"]`，为什么是这一个

本校的登录是学校统一 CAS：上游 `loginUrl` 指向 `auth.taru.edu.cn`，而课表本体在
`jwgl.taru.edu.cn` —— **两者不同源**。所以「要不要把 CAS 登录域写进 `allowHosts`」这个问题，
答案是：**只写课表主机，不写 CAS 域**，依据是这两段代码：

1. **网络闸门只认 `loginUrl` 的主机 + `allowHosts`**
   （`feature/settings/src/main/kotlin/com/nullclass/feature/settings/jw/JwWebViewStep.kt:173-177`：
   `gate.allowedHosts += adapter.allowedHosts(hostOf(adapter.manifest.loginUrl))`，
   而 `JwAdapterPackage.allowedHosts` = `loginHost + manifest.allowHosts`）。
   提取期间 `JwNetworkGate.intercept` 会拦掉白名单之外的**一切**请求
   （同文件 `:119-126`，`frozen` 期间非白名单直接返回空响应；判定用 `:99-102` 的 `allows()`）。
   `loginHost` 是 `auth.taru.edu.cn`，**`scheduleUrlHint` 不参与闸门** ——
   所以不写 `jwgl.taru.edu.cn` 的话，取课表的 POST 会被自己的宿主拦掉，适配器 100% 失败。
2. **桥的 origin 白名单来自 `loginUrl` + `scheduleUrlHint` + `allowHosts`**
   （`importer/src/main/kotlin/com/nullclass/importer/jw/JwOriginRules.kt:15-27`）。
   写**精确主机名**才会在课表页上注入桥（`*.` 通配会被 `JwOriginRules` 跳过，见手册 §5）。
   本件不用 OCR / 提问，但精确主机名同样让 `__ncInput` / `__ncDone` 在课表页上可用。
3. **不写 `auth.taru.edu.cn`**：适配器**从不请求** CAS 域 —— 登录全程由用户在 WebView 里手工完成，
   脚本不碰登录表单、不提交、不读令牌。而它作为 `loginUrl` 的主机**已经被自动放行**，
   再写一条只是重复（清单越短越好）。
4. **不写通配 `*.taru.edu.cn`**：那会一并放行 `hall.taru.edu.cn`（服务大厅）等本适配器
   一个都不请求的主机；而且通配项拿不到桥。

`parse.js` **不发任何请求**（CI 用 Rhino 实跑，是纯函数；里面唯一的绝对 URL 是注释里的上游仓库地址），
所以 `allowHosts` 只与 `extract.js` 有关。

## 2. 读了什么

- **页面**：只读两个**下拉框的值/文本** —— 当前课表页的 `#xnm`（学年）与 `#xqm`（学期）；
  不在课表页时先取一次课表页 HTML，用 `DOMParser` 读**离线文档**里同样两个字段，不插进当前页面。
  另外读 `window.location` 拼请求地址。
  **不读** `localStorage` / `sessionStorage` / `document.cookie` / 登录表单 / 任何密码字段
  （静态扫描无命中，见 §1 的 grep）；**不写 DOM、不改表单、不点提交、不注入脚本**。
- **接口**：只有课表接口的返回体（课名、教师、教室、星期、节次、周次、教学班名、学分）与节次时间
  接口的返回体（第几节、起止时间）。正方课表响应里夹带的 `xsxx`（学号姓名等学生信息）
  **一律不带走、不进 fixture**：`extract.js` 只把 `kbList` 交出去。
- **输出**：`extract.js` 交出的就是一张原始数据清单 —— `term`（xnm / xqm / 两个文本）、
  `raw.kbList`（排课行原样）、`timeSlots`、`reportedTotal`、`today`（日期字符串，只在
  「学年读不出来」时用于推算第 1 周；脚本里读当前时间的话这条分支没法写 fixture）。
- **载荷里只有排课信息**：课名 / 教师 / 教室 / 星期 / 节次 / 周次 / 学期名 / 开学日 / 总周数 / 节次时间。

## 5. 与文华学院（`wenhua`）的对照片：同族能复用多少

两份上游脚本请求的是同一个接口路径、同一套正方 `kbList` 字段，所以**骨架**（`/jwglxt` 上下文路径、
`N2151` 菜单号、`xnm`/`xqm` 表单、`kcmc`/`xm`/`cdmc`/`xqj`/`jcs`/`zcd` 行字段）是共用的。
按测试方案 §3.2 的四层分开说：

| 层 | 对 taru 成立吗 | 依据 |
|---|---|---|
| 接口信封（路径、请求头、`{kbList:[…]}` 返回结构） | ✅ 成立 | 上游 taru 用的就是 `/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151`，与 wenhua 逐字相同 |
| 行字段名（`kcmc`/`xm`/`cdmc`/`xqj`/`jcs`/`zcd`） | ✅ 成立 | 上游 taru 逐个读这六个字段 |
| **周次编码** | ⚠️ **部分不同** | 上游 taru 的正则比 wenhua 那份窄：只认「数字紧挨着『周』」的两种写法，`1-16(单周)` / `1-3,5-9周` 会整段丢；移植件按检查表把四种写法补齐，**并拿 taru 自己的用例锁住** |
| **取数路径（要哪些参数、要不要先取学号）** | ⚠️ 不同 | 上游 taru 的 body 只有 `xnm=&xqm=`（本件照它），wenhua 那份多带 `kzlx=ck&xsdm=&kclbdm=&kclxdm=`；另有两处是移植时加的（读课表页 `#xnm`/`#xqm`、`xskbcx_cxRjc` 取节次时间） |
| **节次 / 作息** | ⚠️ 不同 | wenhua 有节次时间接口；上游 taru **没有**，它写死「夏季/非夏季」两张表再让用户选一张 |
| 分页行为 | ✅ 都没有分页 | 正方 `xskbcx` 一次返回整学期 |

**本件与上游的行为差异（都有意为之，逐条有理由）**：

1. **不问用户三件事**（上游 `showPrompt` 学年、`showSingleSelection` 学期 / 作息）：
   学年学期改成读课表页上的 `#xnm` / `#xqm`（用户自己切过的那个学期优先），要别的学期就在教务页面里切；
   作息改成向教务的节次时间接口要。
2. **作息时间不搬上游那两张写死的表**：哪一套（夏季 / 非夏季）现在生效只有教务知道，
   脚本里挑一张就是猜；取不到教务的节次时间时回落**应用内置默认表**并在 warnings 里说清楚
   （还点了「塔里木大学分夏季 / 非夏季两套作息」），用户去学期管理里改。
3. **教师、教室为空不再整行丢课**：上游 `if (!kcmc || !xm || !cdmc || !xqj || !jcs || !zcd) continue;`
   会把「没排教师」或「没排教室」的课**整门丢掉且不报警**。
4. **节次写法**：上游按 `-` 切、取首尾两段，遇到 `3-4节(2)` 末节是 `NaN`、整行静默丢；
   本件取数字的**最小值/最大值**，并认「两位一节」（`0102`、`0910`）。

再跑一次原始源码，五条用例仍全 `MATCH`。变异只在内存里做，`parse.js` 从未落盘改动。

## 7. 已知边界与没做的事

- **fixture 是合成的**（测试方案 §3 为移植件开的例外）：形状照上游脚本实际读取的字段编，
  每份 fixture 文件的 `_note` 都写明了这一点。它只保证「同样的输入永远得到同样的输出」，
  **不保证在真实教务页面上解析正确**。谁拿到真实 dump 请替换并重跑门。
- **没有真机验证**（维护者没有该校账号）：取数路径（`xskbcx_cxXsgrkb` 的 body、
  `xskbcx_cxRjc` 是否存在、课表页上的 `#xnm`/`#xqm`）来自上游脚本与同族正方件的经验，
  真机上可能与本件假设不同 —— 出了偏差会以「取不到课表」「学年学期读不出来」这类
  带提示的错误暴露，不会静默导错。
- **没有移植上游的三次交互**（学年输入、学期选择、作息选择），理由见 §5。
- **`extract.js` 不做解析**：周次、节次、合并、开学日推算全在 `parse.js`，
  `extract.js` 只把原始行交出去（CI 跑不到 `extract.js`，逻辑放那里等于没有回归）。
- **开学日是推算的**：正方课表接口不给开学日期，按「第一学期 = 9 月 1 日所在周的周一 /
  第二学期 = 2 月 20 日所在周的周一」推算，并且**每次都写进 warnings**（推算值和真值在库里
  长得一模一样，不说用户就没有机会发现）；学年也读不出来时退回「今天所在周的周一」并换一句说明。
- **没有碰**：`index.json`（由主 agent 统一加）、任何 Kotlin、任何既有适配器、任何文档。
