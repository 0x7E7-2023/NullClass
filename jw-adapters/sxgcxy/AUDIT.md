- 移植者：NullClass　审计日期：**2026-09-12**　审计依据：[移植手册 §5](../docs/jw-adapter-porting.md)

## 1. 请求了哪些域（手册 §5 第 3 条）

| 用途 | 地址 | 主机 |
|---|---|---|
| 登录页（用户手工登录，适配器不参与） | `https://sxevc.jw.chaoxing.com/admin/login` | `sxevc.jw.chaoxing.com` |
| **唯一的取数请求**：学生课表 | `/admin/pkgl/xskb/sdpkkbList?xnxq=<学年学期>&xhid=<学生标识>`（**相对路径**） | 同源 = 上面那一台 |

- 上游脚本里的绝对 URL 只有 `https://sxevc.jw.chaoxing.com/...`（它的 `dynamicUrl` 拼的就是这一台主机）。
  我方**改成相对路径**，请求目标由当前页面决定 —— 结构上就不可能漂到别的域。
- `allowHosts` = **`[]`**（空）。理由：宿主已经把 `loginUrl` 的主机自动放进白名单
  （`JwAdapterPackage.kt` 的 `allowedHosts(loginHost) = loginHost + manifest.allowHosts`），
  同源请求本来就允许；再写一条 `sxevc.jw.chaoxing.com` 只是重复，写任何别的都会**多**放行一台主机。

### 第三方托管域的白名单风险（这一条是本适配器的重点）

`chaoxing.com` 是**超星（第三方厂商）**的域，学校只是把教务托管在超星的租户子域
`sxevc.jw.chaoxing.com` 上。判断不受影响 —— 白名单要放行的是**这台教务**，不是「超星」。

**因此没有写 `*.chaoxing.com`，也没有写 `*.jw.chaoxing.com`**：

- `*.chaoxing.com` **应用根本不接受**：通配后缀必须至少三段（`JwHostAllowlist.errorOf` 要求后缀
  里至少两个点），`chaoxing.com` 只有一段，会被判「通配范围过大」直接拒绝安装。
- `*.jw.chaoxing.com` 能过校验，但放行的是超星 jw 平台上**所有学校的租户子域** ——
  白名单会从「这台教务」退化成「超星全部租户」，**形同虚设**：任何一台 `*.jw.chaoxing.com`
  上的接口（别的学校的课表、成绩）都会被放行。共享域上的专属子域，白名单就该只写那一台主机。
- 反面情形也想过：万一学校换到别的租户子域（例如 `sxevc2.jw.chaoxing.com`），适配器**会失败**，
  沙箱报「禁止访问白名单之外的地址」，而不是静默地在别的租户上跑。这正是想要的失败方式，
  改 `manifest.loginUrl` 即可。

## 2. 读了什么

- **页面**：只读一个隐藏输入的值 `#encodeId`（超星 jw 页面上的学生标识，仅作本校接口的查询参数）。
  不写 DOM、不改表单、不点提交、不读 `localStorage`／`document.cookie`／登录表单。
  （请求带 Cookie 是 WebView 的同源登录态，适配器自己不碰 Cookie 内容。）
- **接口**：只有课表接口的返回体 —— 课名、教师、教室、星期、节次、周次。
- **输出**：`xhid` **不写进** extract 的输出（学生标识不外流，fixture 因此天然脱敏）；
  载荷里只有排课信息，没有姓名、学号、成绩、学籍。

## 3. 手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | ✅ 不读 password / 登录表单 / localStorage 令牌。`xhid` 是页面给的学生标识，只当同源接口的查询参数，**不外发**；且不写进输出。 |
| 2 | 不外发 | ✅ 除课表接口外没有任何 `fetch` / `XHR` / `sendBeacon` / `WebSocket` / `new Image().src`；脚本里出现的域名只有上游那一台，且改成了相对路径。 |
| 3 | 请求域可控 | ✅ 唯一请求同源（相对路径）；`allowHosts` 为空；无通配。见 §1。 |
| 4 | 只读课表 | ✅ 只请求 `sdpkkbList`（学生课表）。不请求成绩、学籍、个人信息、缴费。 |
| 5 | 不埋点 | ✅ 没有统计 / 上报 / 遥测代码。`warnings` 只在导入预览里显示给用户本人，不离开设备。 |
| 6 | 不 eval 远程代码 | ✅ 没有 `eval` / `new Function` / 动态插 script。 |
| 7 | 不写页面 | ✅ 不插入或修改 DOM、不触发提交。唯一与应用交互的是**宿主自己的提问弹窗**（问校区），属于应用 UI，不是教务页面。 |
| 8 | 不依赖用户输入之外的秘密 | ✅ 无硬编码密钥 / 他人学号 / 固定令牌；`xhid` 现场从页面取，取不到就**明确报错**，不填占位符。 |

## 4. 相对上游的改动（都会影响行为，逐条列出）

1. **切成两段**：上游的取数与解析混在一个文件里，现在取数在 `extract.js`、解析在 `parse.js`
   （核心逻辑 = 上游 `parseJsonData`：连堂合并、周次切段、HTML 清洗）。
2. **学年学期不再问用户**：上游把「当前学期」当默认项让用户在 3 年 × 2 学期里挑；
   这里按当前日期推算（9 月–次年 1 月 = 第一学期，2–8 月 = 第二学期），取不到就退**上一个学期**，
   两个都没有才报错 —— 报错信息里带上教务自己返回的话。`terms[].name` 用学期代码写成
   「2026-2027 学年第一学期」，不是适配器名。
3. **校区改成问一句**：上游让用户在两个作息表里挑（`showSingleSelection`）；
   这里用 `__ncSelect` 问「你在哪个校区」，只带一个代号走，作息表本身在 `parse.js` 里。
   用户取消 / 提问桥不可用 → **不写** `periodTimes`（应用补默认节次表）并写进 `warnings`，不猜。
   刻意**不用** `__ncCapabilities` 判断：脚本里出现这个名字会让宿主把本适配器当成「要用 OCR」的，
   每次都先等一遍 OCR 引擎探测；改成直接查 `__ncSelect` 是否存在，效果一样（桥没注入时同样拿不到）。
4. **不丢数据**：解析不了的行、超出 `1..30` 的周次、补到 20 周的学期总周数，一律写进 `warnings`。
5. **排序不用 `localeCompare`**：Node 与 CI 的 Rhino 对中文的排序可能不同，会毁掉 fixture 比对；
   改成按码位比较，两边输出逐字节一致（已在 Rhino 1.8.0 上实跑核对）。
6. 教室为空时写 `null`（上游写「待定」——那是教务的占位符，会被当成真教室名显示）；
   教师为空也写 `null`（不写「未知」）。

## 5. fixture 是合成的（必须说清楚）

两份 fixture **都不是真机抓取**，是按上游脚本实际读取的字段形状编造的（测试方案 §3 为移植件
开的例外，与内置 `universal` 同一档位）。只保证「同样的输入永远得到同样的输出」，
**不保证真机解析正确**。

**`fixtures/basic` —— 基本表格（连堂 / 逗号枚举周次 / 脏行）**，覆盖：连堂合并（2 节与 4 节）、
**逗号枚举**的单周 / 双周（`1,3,5,7,9,11` 与 `2,4,6,8,10,12,14,16`）、单周次、区间写法 `1-16`、
HTML 课名 / 教师 / 教室、教师职称括号、空教室、不可解析的行（计数上报）、
超范围周次（计数上报）、学期总周数补到 20 周。

**`fixtures/odd-even` —— 单双周写法**（2026-09-12 补），覆盖「单 / 双写在区间之后」这一条路径
（`weeksOf` 里的 `onlyOdd` / `onlyEven` 两个分支）：`1-16周(双)`、`1-15周(单)`、`2-16周(双)`、
`2-15周(单)`（区间起点与单双对不上，真正的起点要往后挪一格），以及单双周区间与连排区间的混排
`1-16周(双),17-18`（切出 EVEN + ALL 两块）。

这一份是**必须的回归保护**，原因是：在那之前 `basic` 里**一个 `单` / `双` 都没有**，
上面那两个分支是零覆盖的（逗号枚举走的是另一条路径）。**反向对照**（2026-09-12 实跑）：
把区间分支里那两条按单双 `continue` 的语句删掉（复现同一批次 `hbmu` 的错误 ——
`1-16周(双)` 被解析成「每周都上」且不报警），`basic` 仍然 MATCH、`odd-even` 变 DIFF。
也就是说这份用例补上之前，这个错误在 `sxgcxy` 上不会被任何用例拦住。

**谁哪天拿到真实 dump，替换这两份文件并重跑门是最高优先级的贡献。**

## 6. 只能真机确认的事（没验证的都写在这里）

- 字段名 `kcmc` / `tmc` / `croommc` / `xingqi` / `djc` / `zcstr`，以及「`xingqi` 是 1–7 数字」
  「`zcstr` 是逗号分隔的周次数字」—— 全部来自上游脚本，没有真机 dump 佐证。
- `1-16` 区间与 `1-16周(单)` / `1-16周(双)` 都是**本次移植自己加的写法**（上游只有逗号枚举，
  连区间都不认）—— 上游没有这段逻辑，也就没有「它确实这么下发」的证据。真机上超星若用别的
  单双写法（`隔周`、`1-16周(1)` 之类**不含「单」「双」两个字**的写法），这里会**静默**当成每周都上
  （不报警、不计数）；`odd-even` 那份 fixture 锁的只是「含单/双时算得对」，锁不住这一条。
- `#encodeId` 在登录后的哪一页上（上游在课表页读它）。这里另兜了 `input[name=encodeId]`、
  `window.encodeId`、URL 上的 `xhid` 三种取法；都不中时**明确报错**让用户先打开课表页，不猜。
- **请求没有分页参数**（上游也没传）：如果教务端对 `sdpkkbList` 分页，这里会漏课。
  真机上要核对课程条数与教务页面是否一致。
- 校区作息表（10 节制）来自上游脚本，没有与学校最新作息表核对过。
- 教务接口不提供校历，`firstDay`（开学日）与 `totalWeeks` 都是**推算**的，已在 `warnings` 里说明。
