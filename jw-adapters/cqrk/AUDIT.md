## 1. 脚本实际请求了哪些域

### 上游脚本（`cqrk_01.js`）

```bash
$ grep -oE "https?://[A-Za-z0-9._:-]+" cqrk_01.js | sort -u
http://jwxt.cqrk.edu.cn:18080
$ grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*=|localStorage|eval\(|new Function|password|pwd|document\.cookie|document\.write" cqrk_01.js
188:        const response = await fetch("http://jwxt.cqrk.edu.cn:18080/jsxsd/xskb/xskb_list.do", {
```

全脚本**一个绝对 URL、一处 fetch**，写死内网/校内的 `http://jwxt.cqrk.edu.cn:18080`。没有存储、没有 `eval`、没有凭据相关标识符。

### 这所学校的特殊之处：登录入口是 WebVPN + 非默认端口

`adapters.yaml` 的 `import_url` 是

```
https://https-auth-cqrk-edu-cn-443.webvpn.cqrk.edu.cn:8480/cas/login?service=http%3A%2F%2Fportal.cqrk.edu.cn&rewrite=1
```

主机名里那个 `https-auth-cqrk-edu-cn-443` 是**被网关转义进主机名的内网地址**：
把 `-` 换回 `.`、`443` 当作端口，得到 `https://auth.cqrk.edu.cn:443`，也就是学校自己的
统一身份认证（DNS 实测：`auth.cqrk.edu.cn` → `222.198.176.50`，与 `jwxt.cqrk.edu.cn`
同一台公网 IP，两者都是公网可解析的）。网关本身是 `webvpn.cqrk.edu.cn`（→ `222.179.134.60`）。
**端口 8480 是网关服务端口**，不是教务的端口（教务上游写的是 18080）。

所以本适配器的真实场景有三条路，**教务页面在哪条路上，课表请求就该落在哪条路上**：

| 用户的走法 | 页面所在的主机 | 端口 |
|---|---|---|
| 校外经 WebVPN（`import_url` 那条路） | `https-auth-cqrk-edu-cn-443.webvpn.cqrk.edu.cn`（或网关给教务重写出的别的子域） | 8480 |
| 校内直连教务学生端 | `jwxt.cqrk.edu.cn` | 18080 |
| 学校自己的门户 | `portal.cqrk.edu.cn` | 默认 |

### 本适配器怎么请求

**只有一个网络调用点，且是相对路径 + `same-origin`**：

```js
fetch('/jsxsd/xskb/xskb_list.do', { method: 'GET', credentials: 'same-origin' })
                                        // 见 extract.js 的 requestHtml()
```

脚本里**没有任何主机名字面量**，所以「请求哪个域」= 用户当前页面所在的那个域：
经网关进教务就落在网关域上（网关转发给内网教务），校内直连就落在 `jwxt.cqrk.edu.cn` 上。
上游那条写死的 `http://jwxt.cqrk.edu.cn:18080` **没有搬过来** —— 它在 WebVPN 场景下
既不解析也过不了白名单，而它本来就是上游「校园网内直连」的写法。

另外两个读取点也都在页面内存里、不出本页（详见 §4「读取面」）。

## 2. manifest 取值

- **`loginUrl` = `https://https-auth-cqrk-edu-cn-443.webvpn.cqrk.edu.cn:8480/cas/login?service=…&rewrite=1`**
  —— **逐字搬上游 `adapters.yaml` 的 `import_url`**。理由：那是上游与校方一致的开箱入口
  （用户先在这里完成统一身份认证，再进教务系统），我不该在没验证过的情况下自己造一个入口 URL。
  这一条同时是宿主 origin 规则的来源之一（见下）。
- **不写 `scheduleUrlHint`**（与 `neau` 同一个取舍）：课表页在网关后面，重写后的主机名/路径
  我只能推断、无法验证，写死一个猜测的地址反而会在「一键刷新」时把用户送到 404。
  不写时一键刷新会打开**上次成功提取的那一页**（宿主记的是 `webView.url`），比猜的准。
- **`allowHosts` = `["*.cqrk.edu.cn"]`**，理由：

  1. 脚本请求的是**当前页面同源**，而页面可能是
     `https-auth-cqrk-edu-cn-443.webvpn.cqrk.edu.cn`（网关）、网关重写出的教务子域
     （形如 `<站点>.webvpn.cqrk.edu.cn`，`neau` 那所学校就是这种写法）、
     或校内直连的 `jwxt.cqrk.edu.cn`。**这几个都在 `cqrk.edu.cn` 下面**，一个后缀通配
     正好覆盖「用户从哪条路进来都能用」。
  2. 规范允许「至少三段」的后缀通配（`*.cqrk.edu.cn` 正好三段，`*.edu.cn` 会被拒），
     内置信的 `ustc`（`*.ustc.edu.cn`）与同批次的 `neau`（`*.neau.edu.cn`）都是这个写法。
  3. **写法是「并集」，不是二选一**（2026-09-12 订正）：原先这里写「没有更窄又能工作的写法」，
     那是个假二选一 —— 只比较了单条写法（只写 `jwxt` 会让 WebVPN 落空；只写 `*.webvpn` 又漏掉
     校内直连），**没考虑并集**。同批的 `upc` 面对同类多入口问题用的正是并集。
     现在收窄为 `["*.webvpn.cqrk.edu.cn", "jwxt.cqrk.edu.cn", "portal.cqrk.edu.cn"]`：
     网关通配覆盖网关域与它重写出的教务子域，两个精确主机覆盖校内直连与门户落点。
     三段的 `*.webvpn.cqrk.edu.cn` 符合规范（`*.edu.cn` 那种会被拒），且**远窄于原来的整校 `*.cqrk.edu.cn`**。
  4. **不含任何第三方**：统计、CDN 上的业务接口、加速器 —— 一个都没有（§1 的静态扫描为证）。

  > **需要点名的代价**：白名单是**主机级**的，而 WebVPN 网关是个代理 ——
  > 放开 `*.cqrk.edu.cn` 等于放开「网关能把请求转发到的任何校内服务」。
  > 本适配器只发一个课表路径、脚本全文对用户可见，但这条口子天然比非 WebVPN 学校粗。
  > 移植 WebVPN 学校时，审计要盯的是「**脚本要了哪条路径**」，而不是「域名是不是本校的」。

## 3. 非默认端口 8480 对 origin 规则的影响（这次实测出来的结论）

宿主里有**两套互不相同**的判定，端口只在其中一套上有分量：

| | 判定什么 | 带端口吗 | 本适配器 |
|---|---|---|---|
| `JwNetworkGate` / JS 沙箱白名单 | 请求**能不能发出去**（按 `Uri.host` / `location.host`） | **不带**（`allowHosts` 只收主机名） | `*.cqrk.edu.cn` 覆盖全部三条路，**端口不影响放行** |
| `JwOriginRules.forAdapter` | 桥（`__ncOcr` / 提问）**注不注入**到这个 origin | **带**（`scheme://host:port`，省略端口只等于默认端口） | 只有 `loginUrl` 这一条精确 origin，`…:8480` 被正确带上了 |

具体到本适配器：

- `loginUrl` 带端口 8480 → 规则里有 `https://https-auth-cqrk-edu-cn-443.webvpn.cqrk.edu.cn:8480`，
  **桥在登录页上会注入**。这一条正是 `JwOriginRulesTest` 里「非默认端口必须写进 origin 规则」
  那个用例的形状。
- 但**用户在同一个网关域的**别的**子域（网关重写出的教务子域）上点提取时，桥不会注入**
  ——`allowHosts` 里的 `*.` 项被 `JwOriginRules` 跳过（注释写明「origin 规则不接受 `*.host` 通配」），
  而精确的 `loginUrl` origin 又对不上那个子域。**结果是：本适配器在 WebVPN 场景里大概率拿不到
  `__ncOcr` / `__ncAsk`。** 这是可接受的 —— 本适配器**不使用**这两个能力（不用 OCR、不问用户），
  取数与解析全在 DOM/字符串上。**要写**用到 OCR 的 WebVPN 学校时，必须写精确主机名
  （或改宿主的 origin 规则，那是 Kotlin，不在本次改动范围内）。
- 想给校内直连那一侧也补上 `:18080` 的 origin 规则，只能靠 `scheduleUrlHint`
  （写 `http://jwxt.cqrk.edu.cn:18080/jsxsd/xskb/xskb_list.do`）。**没有写**：那个地址校外打不开，
  写进「一键刷新」会把用户送到打不开的页面，而换来的只是桥在直连页面上的注入 ——
  本适配器不需要桥。这个取舍写在这里，免得以后有人以为漏了。

## 4. 有没有绕过白名单的写法 —— 逐类点名

| 写法 | 有没有 |
|---|---|
| 把目标地址塞进 URL 参数（`?url=` / 网关的 `/proxy?target=` 之类） | **没有**。请求只有一条固定路径，无参数。 |
| 非同源 iframe / `<img>` / `<script>` 拉取 | **没有**。脚本不创建任何元素。 |
| 重定向把数据带走 | **没有**。没有导航、没有 `location=` 赋值；也不依赖重定向取数。 |
| `fetch(u, {mode:'no-cors'})` / `credentials:'include'` 暗示跨域 | **没有**。唯一一处 fetch 是**相对路径** + `same-origin`。 |
| 把主机名拼出来（域名分片、base64 拼串、从 `location.href` 里抠） | **没有**。脚本里连主机名字面量都没有，只有一条以 `/` 开头的路径。**没有**搬 `neau` 那种 `/http/<token>/` 前缀兜底：本网关是子域重写式（见 §1），相对路径已经够了，加前缀反而多一处可能被引偏的写法。 |
| WebSocket / Service Worker 侧信道 | **没有**。 |
| 凭据 | **没有**。不读 `password` / 登录表单 / `localStorage` / `document.cookie`；网关登录由用户在 WebView 里手工完成，课表请求只带同一站点的 cookie（`credentials:'same-origin'`，本站 cookie 交本站接口）。 |

> 补充：宿主规范 §3.3 明说「重定向后续 URL、WebSocket、Service Worker 不经过请求拦截」——
> 所以这几类只能靠**读脚本**来审，本适配器一类都不涉及。

## 5. 逐条（移植手册 §5）

1. **不碰凭据** — 不读 `password`/`pwd`/登录表单/`localStorage`/cookie，提取全程在用户已登录的页面里发生。
   上游让用户手输的是**起始学年**（不是账号密码），移植后连这个也不问了（§6①）。
2. **不外发** — 唯一请求是本校教务的课表路径。没有 `sendBeacon`/`WebSocket`/`EventSource`/`new Image().src`，
   没有重定向后二次外发；`parse.js` 完全不联网（纯转换，CI 的 Rhino 里也跑）。
3. **请求域可控** — 见 §1/§2：`allowHosts: ["*.cqrk.edu.cn"]`，脚本本身不写任何主机名。
4. **只读课表** — 只请求 `/jsxsd/xskb/xskb_list.do`（课表页）。不碰成绩、学籍、考勤、缴费、个人信息。
   `extract.js` 读的页面内容**只有**下面「读取面」列出的那几处。
5. **不埋点** — 无统计、无上报、无遥测，也没有任何「回传失败原因」的请求。
6. **不 eval 远程代码** — 无 `eval` / `new Function`；取回的 HTML 只交给 `DOMParser`
   （惰性文档，不执行脚本）；`parse.js` 只对字符串做正则。
7. **不写页面** — 不写 DOM、不改表单、不触发提交、不点页面元素。
   上游往页面写过两个全局函数（`window.validateYearInput`）与一串 `showToast`/`showAlert`，
   移植后**全部删掉**（连提问桥都没用），两个脚本对页面只读。
8. **不依赖用户输入之外的秘密** — 没有硬编码密钥、令牌、他人学号；`xnxq01id` 不再由用户手输，
   改成读课表页「学年学期」下拉框的选中项，读不到就让教务用它自己的默认学期。

## 6. 读取面（`extract.js` 到底读了页面上的什么）

第 4 条说的是「读什么」，这里说「怎么读」。本节与代码逐条对齐（给函数名，不给行号 —— 行号会漂）。

| # | 读什么 | 代码位置 | 取出的值 | 去处 |
|---|---|---|---|---|
| 1 | 课表表格：`#kbtable` / `#timetable`，都没有时含 `.kbcontent` 的那张 `<table>` | `findTable()` → `gridOf()` → `partsOf()` | 每个 `<td>` 的文字 + `div.kbcontent` 的**原始 HTML** + 它在网格里的**列号** `col`（rowspan/colspan 感知），外加表宽 `cols` | 载荷 `cols` / `rows[]`（列号与内容都由 `parse.js` 解释） |
| 2 | 「学年学期」下拉框：id 或 name 含 `xnxq` 的 `<select>` | `readTerm()` | **只取选中项**的 value（`2026-2027-1`）与选项文字（学期名） | 载荷 `term` |
| 3 | 当前页地址 `window.location.href` | `payloadOf()` | 整串 URL | 载荷 `pageUrl`（供真机抽验辨认「用户是从网关进的还是直连的」，**不含个人信息**） |
| 4 | 提取时刻（浏览器本地时间） | `todayIso()` | `YYYY-MM-DD` | 载荷 `now`（只在教务给不出开学日时用于推算第 1 周） |

**没有**读 `document.body`、没有读页面标题之外的文字、没有遍历页面其它元素。
**上游的读取面比这宽**：它把整块 `div.kbcontent` 的 HTML 建成临时节点再取第一个文本节点，
读的是同一块内容，但用的是页面自己的 DOM API；移植后由 `parse.js` 在字符串上做同一件事
（CI 里能真跑），因此**没有**在页面上创建节点。`pageUrl` 是移植时新加的，写在这里以免
「审计文本比代码窄」。

## 7. 移植时删掉/改掉的上游行为

- **弹窗与 toast**（`showAlert` 确认已登录、`showPrompt` 输起始学年、`showSingleSelection`
  选第一/第二学期、一串 `showToast`）：空课的导入流程自己会确认；学期改成从课表页下拉框
  取**选中的那一项** —— 用户在页面上切学期，适配器就跟着他走，比弹窗更清楚。
  上游那个 `window.validateYearInput`（为了让它的弹窗校验输入而写进页面的全局函数）一并删掉。
- **上游硬编码的 `semesterTotalWeeks: 20` / `firstDayOfWeek: 1` / `savePresetTimeSlots`**：
  20 周与 12 节作息表在 `parse.js` 里保留为**载荷字段**（`totalWeeks` / `periodTimes`），
  并在 `warnings` 里说明它们是适配器内置值而不是教务给的。
- **上游的 `mergeAndDistinctCourses()`**：它按课名排序、把相邻节次合并成一整块。
  **没有搬** —— 合并会改动教务给出的节次边界，而按名字重排会让课程顺序与页面无关。
  同一门课的重复块由 `parse.js` 里的块级去重负责，排序交给应用。
- **上游的 `parseWeeks()`**：`weekStr.split('(')[0]` 会把 `1-16周(双)` 的「双」整串丢掉
  （变成每周都上），而且把整串数字都当周次。重写成**分段判单双 + 括号序号不当周次**
  （单双写在哪都算、`(周)` 是正常形态、`(1)`/`(1-2)` 是教学班序号、认不出的进 warnings），
  见 §10 与 `parse.js` 里 `weeksIn()` 的注释。

## 8. 与 `hynu`（同平台，相似度 0.760）的逐条对照

相似度偏低是有原因的：**两者只共用「接口路径前缀 + 行字段名」这一层**，
取数路径、星期定位、周次/节次编码、学期来源、休息表都不同（正是测试方案 §3.2 那张分层表的形状）。

| 维度 | `hynu` | `cqrk` |
|---|---|---|
| 请求域 | 写死 `https://hysfjw.hynu.edu.cn/jsxsd/xskb/xskb_list.do` | **相对路径**，落在当前页面同源（WebVPN 网关域或 `jwxt.cqrk.edu.cn`） |
| 取数 | 三级兜底：当前页面 → GET → **POST 指定 `xnxq01id`** | 两级：当前页面 → GET（不 POST） |
| 学期来源 | 页面上 `xnxq` 下拉框的选中项 → 拼 `xnxq01id` 再 POST | 页面上 `xnxq` 下拉框（只作为学期名），**不参与取数** |
| 星期定位 | 认表头里的「星期N」标签，按标签所在列取 | 表头用来认「星期 d 在第几列」，课表格子按**网格列号** `col` 对齐（`extract.js` 的 `gridOf()` 把 rowspan/colspan 还原成列号）；表头认不出时按偏移推断、整张表认不出时按「第 1 列 = 星期一」兜底，都进 warnings |
| 课名来源 | font 之前的裸文本 | 同上游：font 之前的裸文本（第一个文本节点），另补 `font[title=课程]` 兜底 |
| 周次/节次位置 | 一条 `font[title=周次(节次)]`，方括号前周次、方括号里节次 —— 与 cqrk **相同** | 同左 |
| 教师/教室 title | `教师` / `教室` | `老师`、`教师` / `教室`（上游选择器是 `font[title="老师"], font[title="教师"]`，本适配器两个都认） |
| 周次编码 | `1-16(周)[01-02节]` —— 「周」字在**括号里**、节次在方括号里 | `1-16(周)[01-02节]` —— 「周」字在**括号里**（上游 `cqrk_01.js` 的 `parseWeeks` 注释就是 `1-9,11-17(周)[01-02节]` / `12-15(周)`）；单双写在「周」字后面（`1-16周(双)`）、写在数字**前面**（`双周2-16`）、被空白隔开（`1-16周 双`）三种都认 |
| 作息表 | 12 节（08:30–23:00） | 12 节，**时刻不同**（08:30–21:25，全年统一） |
| WebVPN | 无 | **有**（网关 + 端口 8480） |

**共同点**（同平台确实能复用的那层）：`/jsxsd/xskb/xskb_list.do`、强智学生端课表页的
`#timetable`/`#kbtable` + `div.kbcontent` + `font[title=…]` 选择器结构、`xnxq01id` 这套命名。
