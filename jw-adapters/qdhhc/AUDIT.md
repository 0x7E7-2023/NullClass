## 1. 请求域与请求清单（本节必须与代码一致，不许写得比代码窄）

上游脚本里只有**一个**绝对 URL：`http://jwxt.qdhhc.edu.cn`（两条 `fetch` 都把主机名写死）。
移植件**没有**沿用绝对地址，改成按当前页面的 origin + 上下文路径 `/jwglxt` 拼（`originOf()` + `jwBase()`），
所以两个脚本请求的主机都只有**用户当前所在的那一个教务主机**
（`http(s)://jwxt.qdhhc.edu.cn`，即 `loginUrl` 的主机）。**`allowHosts` 留空**，不写通配。

`jwBase()` 会在当前地址里找 `/jwglxt/` 这一段并保留它之前的前缀 —— 万一学校把教务挂在门户 / WebVPN
前缀下（例如 `/webvpn/jwglxt/...`），请求跟着用户实际打开的那个前缀走，脚本不替教务系统写死主机。

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `<origin><前缀>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期字段（`#xnm` / `#xqm`）。**用户已经开在课表页时这一步跳过**，直接读页面上的这两个字段。**这一条是本件新增的接口，上游 QDHHC/qdhhc.js 里没有**（见下面的说明） | 报错并提示重新登录（没有学期名就没法查课表） |
| extract.js | POST | `<origin><前缀>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表数据（JSON：`kbList` 排课行、可能的记录总数）。请求体与上游逐字一致：`xnm=&xqm=&kzlx=ck&xsdm=&kclbdm=` | 报错并提示重新登录 |
| extract.js | POST | `<origin><前缀>/jwglxt/kbcx/xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154` | 取**学期周次校历**（`xnm` / `xqm`），用来定开学日与总周数。上游同一个接口、同一个菜单号、同一个请求体 | 交 `null`，parse 回落到推算并写进 `warnings` |

- 三条请求里**两条来自上游** QDHHC/qdhhc.js：课表接口 `xskbcx_cxXsgrkb.html?gnmkdm=N2151`（POST）与
  学期周次校历 `xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154`（POST），方法、菜单号、请求体都与上游逐字一致。
  **第三条是我们新增的**：`xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default`（GET 课表页 HTML）——
  上游对这条地址 **0 命中**，它不读页面，学年学期是 `showPrompt` + `showSingleSelection` 两个弹窗问用户要的
  （见 §4 第 2 条）；移植件不问用户，只能自己把学期读出来。
- 新增这条的依据与边界：① 它就是本校教务「信息查询 - 学生课表查询」那个页面（`manifest.json` 的
  `scheduleUrlHint` 也是它），`gnmkdm=N2151` 是同一个菜单号、`layout=default` 是同一个页面参数，
  没有引入新的主机、菜单或权限；② 本仓同平台已内置的其它件（`cfec` / `cqcivc` / `huel` / `taru` /
  `wenhua` / `zjut`）读当前学期用的就是这同一个页面，属于该平台的既有写法，不是本件自创；③ **只有需要用
  它的时候才发**：用户已经开在课表页（`#xnm` / `#xqm` 读得到）时这一步整个跳过，只发两条 POST；
  ④ 它只**读**那两个下拉框的值，不写页面、不触发提交（见 §2 第 7 条）。
- 请求头只带 `Content-Type` / `X-Requested-With` / `Accept`，**不带任何自定义令牌**；
  Cookie 由 WebView 自己按同源规则带上，脚本不读也不写它。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

**读到的数据里有什么**：

| 来源 | 读什么 | 交出去什么 |
|---|---|---|
| 当前页面 | `#xnm` / `#xqm` 两个下拉框的 `value` 与选项文本（没有 `options` 时读 `value`） | 只交 `xnm` / `xqm` / 两个选项文本 |
| 课表响应 JSON | `kbList` 数组、`total` / `totalResult` / `totalCount` / `count` | **只交 `kbList` 与记录总数**。响应里夹带的登录学生信息（正方放在 `xsxx` 之类字段里）与 `sjkList` **一律不带出**，也不进 fixture（桩测试逐项验过） |
| 周次校历响应 | 整份 JSON | 整份交出去 —— 它是**学校的公共校历**（周次号 + 周起止日期），不含任何个人信息 |

## 2. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。两个脚本都没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` / `document.cookie` 访问（静态扫描无命中，见 §1 末的 grep）。唯一的「凭据」是浏览器自带会话 Cookie，脚本既不读它也不把它发到别处 |
| 2 | 不外发 | **过**。全部 `fetch` 都在 `extract.js` 里（共一处，被三个调用点复用），地址全部由 `window.location.origin` + 上下文路径拼成；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有任何第三方域 |
| 3 | 请求域可控 | **过**。请求主机只有一个：`loginUrl` 的主机 `jwxt.qdhhc.edu.cn`（`loginUrl` 给的是 http，`extract.js` 不在页面里跳转、只按当前 origin 拼地址，所以走 http 还是 https 由用户实际打开的那个地址决定）。`allowHosts` 留空，不写通配 |
| 4 | 只读课表 | **过**。三条请求全部落在 `/jwglxt/kbcx/*`（课表查询模块：课表页、课表接口、周次校历），**不碰成绩（`/cjcx/*`）、学籍、个人信息、缴费**等任何其它接口。**注意**：课表接口的响应体里会夹带登录学生自己的信息（正方把它们放在 `xsxx` 之类的字段里）——`extract.js` 只把 `kbList` 与记录总数交出去，其它字段一律不带出，也不会进 fixture。周次校历是**学校的公共数据**，不含个人信息 |
| 5 | 不埋点 | **过**。没有任何统计 / 上报 / 遥测，也没有 `img` 打点 |
| 6 | 不 eval 远程代码 | **过**。两个脚本都没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse` |
| 7 | 不写页面 | **过**。`extract.js` 只**读**当前页面里 `#xnm` / `#xqm` 两个字段的值；取课表页 HTML 时用的是 `fetch` + `DOMParser`（离线文档，不插入当前页面），既不写 DOM、不改表单、也不触发提交或点击。上游的 `showToast` / `showAlert` / `showPrompt` / `showSingleSelection` / `notifyTaskCompletion` / `saveImportedCourses` / `saveCourseConfig` / `savePresetTimeSlots` 这类桥调用**全部没有移植** |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码密钥、令牌或他人的学号。脚本里的常量只有正方的两个菜单号 `N2151` / `N2154` 与上下文路径 `/jwglxt`，都是公开的页面参数 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表（含周次校历一个只读附加接口），
不碰凭据、不外发、不埋点、不写页面。

## 3. 与同平台已移植件 `cfec` 的对照片（本批要求「同平台 ≠ 同编码」）

两件都是正方新版 `jwglxt`，但**取数路径、周次编码、作息来源三处都不同**，不能照抄：

| 层 | qdhhc | cfec | 能不能复用 |
|---|---|---|---|
| 接口信封（POST 表单 + `{kbList:[...]}`） | 同 | 同 | **能** |
| 行字段名 | `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` | 同上 + `cdbh` / `xqh_id` | **能**（本校不用 `cdbh`，上游也没读） |
| 取数路径 | 课表页 `N2151`（**本件新增，上游没有**）+ 课表接口 `N2151` + 周次校历 `N2154`（后两条是上游本来就有的） | 课表页 + 课表接口 + **校区作息** `xskbcx_cxRjc` + 周次校历（后两条是移植时另加的） | **未必** |
| 学年学期怎么来 | 读 `#xnm` / `#xqm` | 同 | **能**（同一套页面） |
| 周次编码 | 上游用 `/(\d+)-(\d+)周/` + `/^(\d+)周/`，**「周」必须紧跟数字** | 上游同一族正则 | **未必**（见 §5 第 1 条：qdhhc 这边 `1-16(单周)` 会整门课丢掉，cfec 那边不会） |
| 节次编码 | 上游 `jcs.split('-')` 取首尾 | 同一族 | **未必** |
| 合并逻辑 | 上游有**两阶段**合并（先并连堂、再并周次），15K 的件里占一半 | 无（cfec 上游直接产出 course） | **不能**：这是 qdhhc 独有的，必须单独移植 |
| 作息表 | 上游脚本里写死 11 节（不请求教务） | 上游写死 13 节，移植件另取校区作息 | **不能** |
| 分页行为 | 无分页（见 §5 第 6 条） | 无分页 | **能** |

**所以「同平台」在这里只帮到「信封 + 字段名 + 读 `#xnm`/`#xqm`」，取数路径、周次节次编码与合并逻辑都单独验过。**

## 4. 移植时对上游做的删改（都不牵涉安全问题，但需要审阅者知道）

1. **ES6 → ES5**：去掉 `async/await`（上游此处全在流程控制里，没有搬）、模板串、箭头函数、
   对象 / 数组展开、`const` / `let`。`parse.js` 是纯同步函数。
2. **不问用户**：上游先 `showAlert` 公告、再 `showPrompt` 问起始学年（还要用户自己把
   「2025-2026」换算成「2025」）、再 `showSingleSelection` 问第一 / 第二学期。
   移植件改成自动取教务当前学期 —— 用户在课表页时读页面上的 `#xnm` / `#xqm`（他自己切过的学期优先），
   否则取一次课表页 HTML 读这两个下拉框的默认选中项。载荷里用 `warnings` 说明「只导入了当前学期」。
3. **切两段**：上游在同一个脚本里算周次、拼课程、存配置、推作息表；移植件把取数留在 `extract.js`
   （只交出 `kbList` 原始行、记录总数与周次校历原始响应），周次解析、节次解析、两阶段合并、
   开学日与总周数、作息补齐全部落在 `parse.js`，这样这段逻辑在 CI 里有真回归。
4. **地址不再写死**：上游两条 `fetch` 都写 `http://jwxt.qdhhc.edu.cn/...`；移植件按当前 origin +
   上下文路径拼（见 §1）。副作用是 http/https 与门户前缀都跟着用户走的地址走。
5. **上游「六个字段全非空」的判据放宽**：上游要求 `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd`
   **全部非空**，缺一个就 `continue` 丢掉整行 —— 空教室（线上课）与空教师都会因此丢课。
   移植件只要求课名 / 星期 / 节次 / 周次；教师与教室没有就留空（`null`），
   真正丢掉的行走分类计数写进 `warnings`。
6. **周次解析加固**：见 §5 第 1、2 条 —— 上游有两处会丢数据（一处丢整门课、一处丢前三周）。
7. **节次解析加固**：上游只认 `1-2`（`split('-')` 取首尾），`第9-10节` 会整行丢掉、
   `1-2,5-6` 会被静默拉成 1-6、`0304` 会算成第 304 节。移植件都按各自的写法解析，
   读不出来的行计数写进 `warnings`。
8. **开学日、总周数都改成「优先取教务」**：上游 `semesterStartDate` 取不到就交 `null`（我们的
   `firstDay` 必填），总周数则写死 20。移植件拿不到校历就按学期序号推算并如实说明；
   总周数回落时仍用上游写死的 20，但课表里更晚的周次会把它抬上去（否则那些 block 会越界、
   整包会被 `JwPayloadCodec` 拒掉），抬了单独说明。
9. **合并的排序键换成确定性比较**：上游用 `localeCompare` 排中文，Rhino 与 V8 的排序结果未必一致，
   而 fixture 是**逐数组比对**的。移植件按码位比较，并给每个排序键都补上完整次级键
   （不依赖排序算法的稳定性）。**合并语义本身一行没改**（先并连堂、再并周次，含完全重复行去重）。
10. **课程顺序**：按**首次出现的排课行**排（上游按合并后的排序结果排）。载荷语义与顺序无关，
    但这样人工核对 fixture 时不用在脑子里跑一遍排序。block 顺序同理，按
    （星期、起始节、结束节、起始周、结束周、单双周、教室）排。

## 5. 批次三 10 条检查表逐条

1. **周次编码四写法**：**过**，而且**上游在这里真的会丢数据**。把上游的 `parseWeeks` 原样抠出来跑
   （见下表），四种写法里有两种不对：

   | 写法 | 上游 `parseWeeks` | 移植件 `weeksOf` |
   |---|---|---|
   | `1-16周(单)` | `[1,3,…,15]` | `[1,3,…,15]` |
   | `(单)1-16周` | `[1,3,…,15]` | `[1,3,…,15]` |
   | `1-16(单周)` | **`[]`** | `[1,3,…,15]` |
   | `1-3,5-9周` | **`[5,6,7,8,9]`** | `[1,2,3,5,6,7,8,9]` |

   上游的正则 `/(\d+)-(\d+)周/` 与 `/^(\d+)周/` 都要求「周」紧跟数字：
   `1-16(单周)` 两个都不命中 → `weeksArray.length === 0` → `continue`，**整门课被静默丢掉**；
   `1-3,5-9周` 按逗号切开后 `1-3` 没有「周」字 → **前三周静默消失**（课还在，周次错了，
   比丢课更难发现）。移植件先把量词「周」整个删掉再分段，并允许单/双标记写在周次前、后、
   括号里或自己成一段（`1-16周,单` 上游也是丢标记的：整段 `includes('(单)')` 不命中）。
   fixture：`weeks-forms`（14 行，覆盖上表全部写法 + 双周 + 标记自成一段 + 下面两条加固）。
   变异测试：①（丢掉单/双标记）→ `weeks-forms`、`basic` 变红。

   **两条加固（本轮对抗式验收证伪后补的，见 §5.1 本轮变异）**：
   - **破折号连同两侧空白一起归一成半角 `-`**。本件原来按 `split(/[,，、;；\/|]+|\s+/)` 切段，
     破折号旁多一个空格就把区间拆开：`1 -16周(单)` 会解析成「只上第 1 周、而且单周标记一起丢」
     （`w1-1 ALL`），`1- 16周` / `1 - 16周` 会变成两块孤立的一周（`w1-1` + `w16-16`）。
     现在把「空白 + 区间号 + 空白」整体归一（字符类含 `- — – − － ~ ～ 至 到`），
     `weeks-forms` 末尾三行专门钉这三条写法。
   - **其余空白是分段符，不许全剥**。上游同族（`CFEC` / `wenhua_01` / `zjut_01` / `huel_01`）
     都是先 `replace(/\s+/g,'')` 再分段 —— 那会把 `1-3周 5-9周`（空格分隔两段周次）拼成
     `1-35-9`、静默吞掉一段（同批 `taru` / `zcmu` / `cqcivc` 按全剥实现时实测就是这个结果）。
     所以只有破折号旁的空格跟着区间号走，其余空白留给切段的 `\s+` 分支：
     `1-3周 5-9周` 必须切成两段（两条 block），`1-16周 双`（空格隔开的单双标记）要并回周次段。
     `weeks-forms` 的「空格分隔两段周次」「空格隔开单双标记」两行钉这条。
   - **括号里的班号序号带空格 / 用了别的区间号**（`(1 -2)1-16周` / `(1～2)1-16周`）：
     这两行钉住「先归一区间号、再判定序号、再摘掉」的顺序 —— 归一被去掉时，
     `(1 -2)` 认不出是序号，整段被读成 `w1-21`。
2. **括号内纯数字不是周次**：**过**。`(1)` 与 `(1-2)` 是教学班序号，解析前先摘掉。
   诚实说明：`1-16周(1)` 与 `(1-2)1-16周` 这两种写法上游**恰好也给对**
   （它的正则不加锚点，`(\d+)-(\d+)周` 能在 `(1-2)1-16周` 里找到 `1-16周`），所以这两条不是
   「修上游的 bug」，而是**用显式规则把这个行为固定住**：规则是「括号里是纯数字或纯数字区间，
   且括号外还有数字时，摘掉它」；括号外一个数字都没有时（`(1-16周)` 这种整段写在括号里的写法）
   不摘区间形态，免得把整段周次摘空。fixture：`weeks-forms`（`1-16周(1)` / `(1-2)1-16周` /
   `(1～2)1-16周` / `(1 -2)1-16周` 四行 —— 后两行钉「先归一区间号（连同两侧空白）、再摘序号」
   这个顺序：归一那一步被改坏时，这两行会变成 `w1-21` 或裂成两块）。
   变异测试：②（不摘纯数字）与 ③（不摘数字区间）→ `weeks-forms` 变红。
3. **无星期表头兜底 / 禁止按数组长度猜列**：**不适用，但这条要说清楚**。本件读的是**JSON 接口**
   （`kbList` 行对象），**不解析 HTML 表格** —— 上游 qdhhc.js 就是这么写的（它只 `JSON.parse`
   课表接口的响应体，脚本里没有任何 `document.querySelector` 去读课表格子）。

   `xqj` 读不出来或不在 1..7 的行按「缺星期」计数写进 `warnings`，**不猜**。
   fixture：`dirty-rows` 第 1 行（`xqj` 为空）。
4. **时间合法性**：**过**。写进 `periodTimes` 的每个时间都过 `timeOf()`
   （`^([01]?\d|2[0-3]):([0-5]\d)`，即 `HH:mm` 且 `00:00–23:59`），并要求结束时间晚于开始时间；

   五个用例仍全部变红 —— 因为每个载荷里都带 `periodTimes`，这道闸真的在拦。

   最长 74 / 92 / 99 / 74 / 74 字，都远在限内。

   带出来，`parse.js` 发现它大于实际取到的行数时写进 `warnings`。

7. **学期名**：**过**。用教务自己的学年学期：优先响应 / 页面里的显式学期名，

8. **`teacher` 拿不到就留空**：**过**。上游写 `'未知'` 的兜底没有搬过来，空教师是 `null`；

## 6. 用例与自验

| 用例 | 打什么 |
|---|---|
| `basic` | 连堂合并、完全重复行去重、同节次分段周次合并、单/双周、落单一周（`20周`）、1 行缺课名、空教师 + 空教室、教务周次校历（20 周，第 1 周 2026-09-07）、内置 11 节作息表 |
| `weeks-forms` | 周次的各种写法（见 §5 第 1、2 条），含破折号旁有空格的三行（`1 -16周(单)` / `1- 16周` / `1 - 16周`）、空白当分段符的两行（`1-3周 5-9周` 切成两段 / `1-16周 双` 标记并回）、两行「序号里带空格 / 序号里用全角波浪」（`(1 -2)1-16周` / `(1～2)1-16周`）；校历接口不返回（开学日推算 + 总周数回落到上游写死的 20） |
| `dirty-rows` | 缺星期 / 缺节次 / 缺周次、周次 31-40 全超限、节次多段、`0304`、`第9-10节`、第 12 节要补作息、第 22 周把总周数抬到 22、记录总数说 9 条只回 8 条 |
| `calendar-26` | 校历给 26 周（课表最晚只到第 16 周，所以 26 只可能来自校历）：钉住「总周数取自校历」，也钉住「抬总周数」那条分支没有被误用 |
| `calendar-nonmonday` | 校历第 1 周从 2026-09-09（周三）开始：`firstDay` 必须回退到第 1 周的那个周一 2026-09-07；校历共 18 周 |

自验方式（用 node，没有跑 `./gradlew`）：

- 五个用例在 `vm` 里实跑 `parse.js`，与 `expected` 逐字段比对：**全部 MATCH**
  （`JSON.stringify` 全等，数组顺序也一致）。
- `extract.js` 用桩页面 + 桩 `fetch` 跑过五遍（CI 里跑不到的那一段）：请求条数与顺序与 §1 一致
  （已在课表页 = 2 条，不在 = 3 条，挂 `/webvpn` 前缀时路径跟着前缀走），
  交出的键与 `parse.js` 的读法对得上，**载荷里不含**课表响应夹带的 `xsxx` / 学号 / 身份证 / `sjkList`。
- 五个 `expected.json` 按 `JwPayloadCodec.validate` + `JwManifest.validate` 的规则逐条核过
  （`totalWeeks` 1..30、`endWeek ≤ totalWeeks`、`weekType ∈ {ALL,ODD,EVEN}`、时间 `HH:mm` 且不逆序、
  `warnings` ≤ 20 条且每条 ≤ 200 字、`firstDay` 是 `yyyy-MM-dd`、`periodIndex ≥ 1`）：全部通过。
- 另跑了一轮对抗输入（空 `kbList` / `raw` 缺失 / `kbList` 不是数组 / 周次全认不出 / `kcmc` 是数字 /
  节次 25-26 超上限 / 周次 1-100 / `xnm` 不是四位 / 校历给别的学期 / 校历是 `{datas:{rows:[]}}` 信封 /
  `total` 说 99 条实际 1 条 / 一条 `zcd` 里塞满垃圾）：**没有一处抛异常或产出非法载荷**。
  其中「一条排课记录都没有能解析成课程」与「教务说这个学期没课」这两种失败给了**不同**的报错 ——
  前者会带上「缺课程名 x 行 / 缺星期 y 行 / 缺节次 z 行 / 缺周次 w 行」的分项计数并提示
  「多半是教务系统改了课表接口的字段」，不会被误读成「假期还没排课」。
- ES5 自检 `grep -nE "=>|\`|\blet |\bconst " jw-adapters/qdhhc/*.js` **无输出**；
  两个脚本 + 十个 fixture 的 NUL 字节计数均为 **0**，无 BOM。

## 7. 没能确定的事（交接给下一位）

- **fixture 是合成的**：按上游实际读取的字段形状（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd`）
  编出来的形状正确的数据，**不是真实抓取**，课名 / 教师 / 教室 / 日期均为虚构（测试方案 §3）。
  它只保证「同样的输入永远得到同样的输出」，**不保证真实页面上解析正确**。
  拿到真实 dump 后请替换 fixture 并重跑门。
- **上游的哪些写法在本校真实数据里出现**：没有账号，验不了。移植件按「宁可多认一种写法」处理
  （`1-16(单周)` / `1-3,5-9周` / `1-16周,单` / `1 -16周(单)` / `1- 16周` / `1～16周` / `1至16周` /
  `1-3周 5-9周`（空白分段）/ `1-16周 双`（空白隔开标记）/ `第9-10节` / `0304` / 两位一拼的节次），
  认不出的部分一律进 `warnings`，不静默。
- **空白是分段符，但「区间号当两段分隔符」的写法会丢段**：`1-3周 5-9周`（空白分段）能切成两段；
  但「区间号」字符类里的字符（`- — – − － ~ ～ 至 到`）被当成**区间**读 —— 例如 `1-3 至 5-9`
  会归一成 `1-3-5-9`，按「第 1-3 周」解析，后面的 5-9 被静默丢掉（`warnings` 里也没有
  「认不出的说明」—— 段里除数字和区间号外没有别的字符）。这是沿用「一段只读前两个数字」的
  上游语义，正方数据里没见过这种写法；真机上若发现某门课周次少了一段、且没有任何 warning，
  先查这里。`1-16周-单`（破折号隔开标记）倒是没问题的：归一后并成一段，按单周解析。
- **作息表**：上游没有向教务请求作息，那张 11 节表是脚本作者对学校的了解。移植件原样带进载荷，
  并在**每条** `warnings` 里说明它没跟教务核对过。真机上一旦发现时间对不上，先看这里 ——
  同平台其它部署一般有 `/kbcx/xskbcx_cxRjc.html`（校区作息）可以取，本校有没有装这个菜单未知。
- **`cxZcByXnxq` 的字段名**：移植件同时认 `zs` / `zsmc` 与 `rq` / `zcrq` / `ksrq` / `zrq`
  （前两个来自上游 qdhhc.js，后几个是同一族里见过的写法）。真实部署若用别的名字，
  会退化成推算 —— 有 warning，不静默。上游还有一条 `|| json[0]` 的兜底（找不到第 1 周就拿第一行），
  移植件**没有**沿用：万一那一行不是第 1 周，写进去的开学日会整学期错位，宁可按推算走 + 说出来。
- **`jcs` 空、`jc` 非空的行**：上游只读 `jcs`，这类行会被整行丢掉。移植件在 `jcs` 为空时回落读
  `jc`（正方这个接口在已见过的 52 个上游脚本里都写 `jcs`，回落属于防御性容忍，正常不会触发）。
- **校历判为「不属于这个学期」时，它的周数仍会被用来定总周数**：`parse.js` 只用「第 1 周日期是否
  离学期锚点 ≤ 45 天」判开学日可不可信；判为不可信时开学日走推算（有 warning），但 `calendarWeeks`
  仍取自同一份校历（与 `cfec` 同构，没有单独处理）。后果很轻 —— 一份跑偏的校历一般也是 18-20 周，
  与回落值 20 差不多，而且 `warnings` 里已经明说了开学日被忽略。真机上若发现总周数不对，
  先查这里。
- 需要真实环境才能验的：登录后的会话是否被这三条接口接受、课表页 HTML 里是否真有 `#xnm` / `#xqm`
  两个选择框、菜单号 `N2151` / `N2154` 是否仍然有效、`loginUrl` 给的是 http
  （应用会显示「不安全连接」标记，学校如果也开了 https，维护者可以直接换成 https）。
