# 安全审计 —— 甘肃医学院（正方新版 jwglxt 平台）

审计对象：`jw-adapters/gsmc/` 下的 `extract.js` / `parse.js`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `GSMC/gsmc_01.js`（快照 commit `e62554a4034386b893bcd6813c7b2b64f8c730a3`，
2026-09-12，MIT，上游 `GSMC/adapters.yaml` 的 maintainer 是 `星河欲转`）。

审计方式：逐行读上游脚本 + 逐行读移植件，并跑移植手册 §5 给的静态扫描
（`grep -oE "https?://[A-Za-z0-9.-]+"` 与 `grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*="`）。
扫描结果：两个移植脚本里出现的绝对 URL 只有 `https://github.com`（文件头里写明上游出处的那一行），
网络调用只有 `extract.js` 里的一个 `fetch` 包装函数（`X-Requested-With: XMLHttpRequest` 是请求头，
不是 XHR 对象）。

## 1. 请求域与请求清单（本节必须与代码一致，不许写得比代码窄）

上游 `GSMC/gsmc_01.js` 里**只有一个绝对 URL**：`https://jw.gsmc.edu.cn/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151`
（课表接口），`fetch` 也只有那一处。移植件把这个主机名也去掉了：四条请求的地址全部由
`window.location.origin + '/jwglxt'` 拼出来，所以**主机只有用户当前所在的那一个教务主机** ——
正常就是 `loginUrl` 的主机 `jw.gsmc.edu.cn`；学生若通过学校的 WebVPN 打开，请求会跟着当前源走，
不需要（也没有）额外放行任何域。**`allowHosts` 留空，不写通配。**

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期字段（`#xnm` / `#xqm`）。**用户已经开在课表页时这一步跳过**，直接读页面上的这两个字段 | 报错并提示重新登录（没有学年学期就没法查课表） |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表数据（JSON：`kbList` 排课行、`sjkList` 集中实践课、可能的记录总数）。请求体 `xnm` / `xqm` / `kzlx=ck` / `xsdm` / `kclbdm`，**与上游逐字一致** | 报错并提示重新登录 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151` | 取**校区作息时间**（`xnm` / `xqm` / `xqh_id`） | 交 `null`，parse 回落到上游那张 12 节表并写进 `warnings` |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154` | 取**学期周次校历**（`xnm` / `xqm`），用来定开学日与总周数 | 交 `null`，parse 回落到推算并写进 `warnings` |

- 后两条接口**不来自上游 GSMC 脚本**（它只请求课表一条，也不读 `xqh_id`）：路径与参数取自
  **同族正方脚本** ——
  - 作息 `xskbcx_cxRjc.html`：快照里 7 份脚本用这个接口，其中 4 份带 `?gnmkdm=N2151`
    （`WENHUA/wenhua_01.js`、`NBUT/nbut.js`、`SCUT/SCUT_01.js`、`YXHMC/yxhmc.js`），
    `HUALIXY/hualixy.js` 用变量、`QUT/qut.js` 与 `SCNU/scnu.js` 不带菜单号。
    移植件带 `N2151`（课表菜单本身，主接口能通就说明这个菜单一定存在），
    请求体 `xnm` / `xqm` / `xqh_id` 与 `SCNU/scnu.js` 逐字一致。
  - 周次校历 `xskbcxZccx_cxZcByXnxq.html`：快照里有 **20 份**脚本用同一个菜单号 `N2154`
    （`GDOU/gdouyj.js`、`QUT/qut.js`、`CQEPC/cqepc.js` 等），请求体 `xnm` / `xqm` 与 `GDOU/gdouyj.js` 一致。
  - 两处独立来源都指向同一个路径族，判断可用；但它们**不是每个部署都装了菜单**，
    所以一律 best-effort（见上表最后一列）。
- 这两条请求失败**不会**影响导入：`optionalJson` 把任何失败（含非 2xx、超时、JSON 解析失败）都吞成 `null`，
  由 `parse.js` 回落，并且**回落这件事会出现在导入预览的 `warnings` 里**（不是静默降级）。
- 请求头只带 `Content-Type` / `X-Requested-With` / `Accept`，**不带任何自定义令牌**；
  Cookie 由 WebView 自己按同源规则带上，脚本既不读它、也不把它发到别处。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 读了什么（数据面）

| 数据 | 从哪来 | 是否带出 |
|---|---|---|
| 学年学期（`xnm` / `xqm` + 下拉框文本 `2026-2027` / `第一学期`） | 课表页的 `#xnm` / `#xqm`，或课表首页 HTML（`DOMParser` 解析的离线文档） | 带出（学期名要用） |
| 排课行 `kbList`（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id`） | 课表接口 | 带出（这就是课表本身）；`xqh_id` 只用来拼作息请求 |
| 集中实践课 `sjkList` | 课表接口 | 带出（只有课名与起止周，排不进周课表，但**不能吞掉**：写进 `warnings` 让用户自己加） |
| 校区作息 | 作息接口 | 带出（写进载荷的 `periodTimes`） |
| 学期周次校历 | 校历接口 | 只用来算开学日与总周数，**不整表带出** |
| 记录总数（若响应里有） | 课表接口 | 只用于对账，不整表带出 |
| **学生个人信息**（正方课表响应里夹带的 `xsxx` 之类） | 课表接口 | **不带出、也不进 fixture**（`extract.js` 只挑 `kbList` / `sjkList` / 记录总数） |

不读的东西（静态扫描无命中）：`password` / `pwd` / 登录表单、`localStorage` / `sessionStorage`、
成绩（`/cjcx/*`）、学籍、个人信息、缴费、任何其它模块的接口。

## 3. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。两个脚本都没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` 访问（静态扫描无命中）。唯一的「凭据」是浏览器自带会话 Cookie，脚本既不读它也不把它发到别处。**上游那三个 `showPrompt` / `showSingleSelection` / `showAlert` 弹窗全部没有移植**：学年学期改成读页面上的 `#xnm` / `#xqm`，一个字段都不问用户要 |
| 2 | 不外发 | **过**。全部 `fetch` 都在 `extract.js` 里，地址全部由 `window.location.origin + '/jwglxt'` 拼成；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有任何第三方域（脚本里唯一的绝对 URL 是文件头里写上游仓库的 `https://github.com`，不是请求） |
| 3 | 请求域可控 | **过**。请求主机只有一个：`loginUrl` 的主机 `jw.gsmc.edu.cn`（走 http 还是 https 由用户实际打开的那个地址决定）。`allowHosts` 留空，**不写通配**；代码里也没有写死主机名 |
| 4 | 只读课表 | **过**。四条请求全部落在 `/jwglxt/kbcx/*`（课表查询模块：课表页、课表接口、作息、周次校历），**不碰成绩、学籍、个人信息、缴费**等任何其它接口。课表接口响应里夹带的学生信息一律不带出（见 §2）。作息与周次校历是**学校的公共数据**，不含个人信息 |
| 5 | 不埋点 | **过**。没有任何统计 / 上报 / 遥测，也没有 `img` 打点 |
| 6 | 不 eval 远程代码 | **过**。两个脚本都没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse` |
| 7 | 不写页面 | **过**。`extract.js` 只**读**当前页面里 `#xnm` / `#xqm` 两个字段的值（下拉框或隐藏 input，与上游一样读 `value`）；取课表首页 HTML 时用的是 `fetch` + `DOMParser`（离线文档，**不插入当前页面**），既不写 DOM、不改表单、也不触发提交或点击。上游的 `showToast` / `notifyTaskCompletion` 这类桥调用**全部没有移植** |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码密钥、令牌或他人的学号。脚本里的常量只有正方的上下文路径 `/jwglxt` 与两个公开菜单号 `N2151` / `N2154`，都是页面上可见的参数 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表（含作息与周次校历两个只读附加接口），
不碰凭据、不外发、不埋点、不写页面。

## 4. 本批（批次三）10 条检查表逐条

| # | 检查项 | 本件结论 |
|---|---|---|
| 1 | 周次四写法 | **过，且有用例**。`1-16周(单)`（A）、`(单)1-16周`（B）、`1-16(单周)`（C）、`1-3,5-9周`（D）各一条，见 `fixtures/weeks-forms.*`。实现上先把量词「周」整个删掉再切段，所以「标记在周后」不会被切走；标记在括号里/最前/独立成段都能跟到自己那一段。**上游在这里是错的**：它的 `/(\d+)-(\d+)周/` 与 `/^(\d+)周/` 对 `1-16(单周)` 一个都匹配不上，整段周次塌成空数组 → 这门课被静默丢掉。变异测试 M1 证明这四条用例真的在看这段逻辑 |
| 1b | **空白的分段语义**（2026-09-13 空白口径统一轮） | **过，且有用例（K）**。原实现只按逗号切段、空白留在段内靠「段内全局 match 区间」兜住 —— 对 `1-3周 5-9周`（无逗号）碰巧给对，但**标记绑定与统一口径不一致**：`1-3周 5-9周(单)` 会把「单」作用于两段、并成一个 `1-9 ODD`（同批 `xawl` 定稿口径是两段各自认标记：`1-3 ALL` + `5-9 ODD`）。本轮按统一口径改成两步：① 破折号异体（含「至」「到」）**连同两侧空白**归一成 `-`（`1 -16周(单)` / `1- 16周` 不再被劈开）；② 剩下的空白**当分段符**折成逗号 —— `1-16周 双` 的标记自成一段、`1-3周 5-9周` 切成两段（各认各的标记）。`weeks-forms` 补 K「空格分段两段」`1-3周 5-9周` 钉住（期望 1-3 与 5-9 两个 ALL block，按规范手推）；变异 M4 证明这行真的在看这条路径（§6）。另注：统一口径前用「基线对照探针」测第二份 fixture 报「不是两段」，**不是两条代码路径不一致** —— 探针替换的第一处周次串在 `1-16周(单)` 语境里，旧实现把 (单) 作用到全文、把两段并成一个 `1-9 ODD`，正是上面说的标记绑定差异 |
| 2 | 括号内纯数字不是周次 | **过，且有用例**。解析前先整段摘掉「括号里只有数字或数字区间」的组（`(1)`、`(1-2)`），并计数（`serialGroups`）写进 `warnings`。用例：`1-16周(1)`（E）→ 1-16 每周；`(1-2)1-16周(双)`（F）→ 双周 2-16；**整格只有 `(3)`（G）→ 判为没有周次、该行进 `warnings`，绝不塌成「第 3 周」**。变异测试 M2 证明摘除这一步是活的 |
| 3 | 无星期表头兜底 | **不适用，且没有猜列**。本件走的是**接口**（`xskbcx_cxXsgrkb.html` 的 JSON），星期由 `xqj` 字段直接给出（1-7），不解析课表 HTML 表格，因此不存在「按行宽猜列」的问题；`parse.js` 里没有任何 `length - 7` 之类的推断。`xqj` 不是 1-7 的行走 `warnings`（计数 + 原因），不猜 |
| 4 | 时间合法性 | **过**。写进 `periodTimes` 的时间有两个来源：① 教务作息接口 —— 逐条要求 `HH:mm`（`^([01]?\d\|2[0-3]):([0-5]\d)`，`24:00` 这类直接不匹配）、`start < end`、从第 1 节起连续不重叠，任何一条不满足就**整表作废**并回落到内置表 + `warnings`；② 上游那张 12 节常量表（逐条核对过，全部在 `00:00–23:59` 内）。脚本**不做任何时间加减**，算不出 `24:00` / `85:45` 这种值 |
| 5 | `warnings` 上限 | **过**。所有 `warnings` 都过一个 `warn()` 收口：单条超 200 字先截断（补「…」），总数超过 20 条不再追加并记数（正常路径下永远不会触发：本件最多 9 条）。本地自验脚本按 `JwPayloadCodec.validate` 的口径复核了 4 份期望载荷（条数与每条长度） |
| 6 | 分页 | **不适用，但对账了**。正方这个接口一次性返回整学期排课，**没有分页参数**（上游脚本也没有翻页）。响应里若带了记录总数就与行数对账，取到的少就出声：`fixtures/calendar-extra`（教务说 30 条、实际 10 行）覆盖了这条 |
| 7 | 学期名 | **过**。取自教务下拉框的文本（`xnmText` / `xqmText` → `2026-2027学年第一学期`），整个「…学年…学期」在 `xqmText` 里时直接用原文；只有这些都读不到才用学年代号拼。**没有拿适配器名当学期名**，也没有写死学校名 |
| 8 | `teacher` 拿不到就留空 | **过**。`teacher` / `location` 读不到就是 `null`，不写「未知」「暂无」。用例：`basic` 的「大学体育(一)」（`xm` 为空）与 `calendar-extra` 的「大学语文」（无教师、无教室）都以 `null` 进载荷。**上游在这里会整行丢课**（它要求六个字段全非空），移植件只要求课名/星期/节次/周次 |
| 9 | `allowHosts` | **过**。`allowHosts: []` —— 四条请求全是**当前页同源相对路径**，只放行 `loginUrl` 那一个主机，没有任何通配。本件**不使用 OCR / 提问桥**（源码里没有 `__ncOcr` / `__ncOcrGrid` / `__ncSelect` 等全局名），所以不存在「通配拿不到桥」的问题 |
| 10 | 每件都要做变异测试 | **已做，见 §6** |

## 5. 与同平台已移植件的对照片（"同平台 ≠ 同编码"）

上游 `GSMC/gsmc_01.js` 与本批模板 `CFEC/CFEC.js`（→ `jw-adapters/cfec/`）同属正方新版 `jwglxt`，
但**不是克隆**：`diff` 出来的关键差异说明「同平台的可复用性分层」（测试方案 §3.2）在这两件上完全成立。

| 层 | 能不能复用 | 本次结论 |
|---|---|---|
| 接口信封（POST 表单 + `{kbList:[...]}`） | **能** | 与 cfec 同一套。移植件沿用「响应必须是对象且 `kbList` 是数组」的判据，也沿用「响应带记录总数就对账」 |
| 行字段名（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id`） | **能** | 上游两份脚本读的是同一组字段；本件 fixture 也按这组形状编 |
| 取数路径（接口、参数、要不要先取学号） | **未必** | **GSMC 的入口与 cfec 不同**：上游 GSMC 是「问用户起始学年 + 选第一/第二学期」再换算成 `xnm` / `xqm`（`3` = 第一学期、`12` = 第二学期），cfec 是读页面下拉框。移植件统一成「读页面下拉框 / 取一次课表首页」，**学年学期不再问用户**；请求体的 `kzlx=ck&xsdm=&kclbdm=` 照 GSMC 自己的写法（cfec 多带一个 `kclxdm=`，本件**不带**） |
| 周次 / 节次编码 | **未必** | 两件的周次解析代码不同（GSMC 上游的 `parseWeeks` 与 CFEC 上游那份逐字克隆的版本不是同一段），本件因此**没有照抄 cfec 的 fixture 期望**，而是按 GSMC 自己的编码单独造了 4 份用例 |
| 作息表 | **未必** | cfec 13 节、上午排到第 5 节（08:10 起）；GSMC 12 节、上午排到第 4 节（08:00 起）、下午第一节 14:30。本件内置表就是上游 GSMC 那张，逐条搬过来 |

上游 GSMC 自己的默认值：`semesterTotalWeeks = 20`、`firstDayOfWeek = 1`，**没有开学日**。
移植件据此把 20 周当作「教务不给校历时的总周数」，并按手册 §4.3 把每周起始日 1（周一）
落成 `firstDay` 取周四舍五入到周一（推算路径见 §7）。

## 6. 变异测试记录（本批检查表 10）

变异改的是**真文件** `jw-adapters/gsmc/parse.js`，跑完从备份还原。
还原校验：`diff` 无输出，且 sha1 前后一致（M1–M3 轮：`46533bd7213eebc0cda52bf1d38243314da66eac`；
空白口径统一轮的 M4 在本轮修复版上做的，还原后 sha256 =
`f5587f31497468abef69fec55544e1f83d19678dece9301151c8672be069e6bc`，再跑一次五条用例仍全 `MATCH`）。

| 变异 | 改坏了什么 | 结果 | 说明 |
|---|---|---|---|
| **M1** | 单双周标记不再过滤（周次循环里的 `if (onlyOdd && week % 2 === 0) continue;` 与 `if (onlyEven && week % 2 === 1) continue;` 改成恒假）→ 单/双周塌成「每周都上」 | **4/4 用例变红**：basic（大学英语 endWeek 16 vs 15）、weeks-forms（A 单周 16 vs 15）、calendar-extra（组织学与胚胎学 startWeek 1 vs 2）、second-term（药剂学 endWeek 16 vs 15） | 单双周是贯穿全套用例的主路径，任何一件丢了标记都会红 |

## 7. 移植时对上游做的删改（都不牵涉安全问题，但审阅者需要知道）

1. **两段式**：上游把取数、解析、存配置写在一段里；移植件按手册 §3 第 1 步切开 ——
   `extract.js` 只取数（`kbList` / `sjkList` / 作息 / 校历 / 学年学期原样交出），
   `parse.js` 是纯转换（CI 用 Rhino 实跑的那一段）。
2. **交互全部去掉**：上游的 `showAlert`（开场公告）、`showPrompt`（手填起始学年）、
   `showSingleSelection`（选第一/第二学期）三个弹窗都没有移植，改成读页面上的 `#xnm` / `#xqm`。
   要导入别的学期，用户在教务页面里切一下再点「提取课表」—— 他看得见自己切的是哪个学期，
   比弹窗更清楚（规范 §5.2 的建议）。
3. **不再整行丢课**：上游要求 `kcmc`/`xm`/`cdmc`/`xqj`/`jcs`/`zcd` 六个字段全非空，缺教师或
   缺教室的课**整行丢掉且不吭声**。移植件只要求课名/星期/节次/周次，跳过的行按原因计数写进 `warnings`。
4. **节次解析放宽**：上游只 `split('-')` 取首尾（`0102` 这种会算出第 102 节）。移植件认
   `1-2` / `第9-10节` / `1,2` / 两位一拼的 `0102`，多段（`1-2,5-6`）按最大跨度放入并写进 `warnings`；
   超出 1-20 节判为脏数据（计数 + `warnings`），不塞进载荷。
5. **周次解析重写**（本批检查表 1、2 的两个坑），见 §4。
6. **开学日与总周数**：上游根本没有开学日（`config` 里只有 `semesterTotalWeeks` / `firstDayOfWeek`），
   总周数写死 20。移植件优先取教务的学期周次校历，取不到才按学期序号推算，且**两种情况都写进 `warnings`**；
   学期名同理（上游完全没有学期名这个概念）。
7. **作息优先用教务的**：上游那张 12 节表成为回落值（教务作息接口取不到时用它，并写进 `warnings`）。
