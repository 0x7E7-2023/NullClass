## 1. 脚本实际请求了哪些域

上游全脚本**只有一个绝对 URL、一处网络调用**：

```bash
$ grep -oE "https?://[A-Za-z0-9.-]+" upc.js | sort -u
https://jwxt-443.webvpn.upc.edu.cn
$ grep -nE "fetch\(|XMLHttpRequest|sendBeacon|WebSocket|\.src\s*=" upc.js
181:        const response = await fetch("https://jwxt-443.webvpn.upc.edu.cn/jsxsd/xskb/xskb_list.do", {
```

| 主机 | 上游怎么用 | 我们怎么用 |
|---|---|---|
| `webvpn.upc.edu.cn` | 不请求（只是 `import_url`：用户要打开的那一页） | **不请求**，它只是 `loginUrl`（宿主会把它的域自动加进白名单） |
| `jwxt-443.webvpn.upc.edu.cn` | POST `/jsxsd/xskb/xskb_list.do`（写死在脚本里） | 不写死。请求**当前页面同源**的同一条路径 |
| `jwxt.upc.edu.cn` | 不出现 | 同样不写死；校内直连时页面就在这个域上 |

**这两个主机名从哪来的（公开信息，不是猜的）：**

- WebVPN 入口是 `https://webvpn.upc.edu.cn`，信息化建设处《WebVPN 使用说明》
  （<https://nic.upc.edu.cn/_s6/2023/0804/c7809a409626/page.psp>）写明「登录成功后，通过 VPN 页面内的
  链接或手工输入**以 upc.edu.cn 结尾的域名**进行访问」「任何资源都必须是在此页面中访问」。
- 教务系统自己的名字是 `jwxt.upc.edu.cn`，教务处《关于新版教务系统上线运行的通知》
  （<https://jwc.upc.edu.cn/_t34/2019/0401/c475a202426/page.psp>）给学生的入口就是 `http://jwxt.upc.edu.cn`。
- `jwxt-443.webvpn.upc.edu.cn` 是**网瑞达式重写**：`<内部主机>-<端口>.webvpn.<学校域>`。
  上游把这一形态写死在脚本里，说明作者是在真实页面上看到的 —— 也就是说：**用户在 WebVPN 里打开教务后，
  页面本身就在这个子域上**。

**移植后的取数方式（与上游的三处差别）**：

1. **当前页面已经是课表页 → 一个请求都不发**（上游无论如何都发那一个 POST）；
2. 否则 POST **同源**相对路径 `/jsxsd/xskb/xskb_list.do`，body 与上游一字不差
   （`cj0701id=&zc=&demo=&xnxq01id=<学年学期>`，学年学期从课表页的「学年学期」下拉框里取，读不到就留空取当前学期）；
3. 第一次拿不到课表、且返回页给出了别的学年学期时，用那个学期再 POST 一次（最多 2 个请求）。

脚本里**没有任何主机名字面量参与请求**（`grep -nE "https?://" extract.js` 只命中注释与错误提示文案），
`sameOriginUrl()` 只做一件事：若当前页路径形如 `/http[s]/<token>/…`（深信服那套把内网站点挂在路径前缀下），
把这个前缀拼回去，**结果永远是同源相对路径**（与 `neau` 的 `vpnBase()` 同一做法，不是绕过白名单的写法）。

## 2. manifest 取值

- **`loginUrl` = `https://webvpn.upc.edu.cn/users/sign_in`** —— 上游 `adapters.yaml` 的 `import_url`，
  也是用户实际要打开的那一页（先登录网关，再从网关进教务）。校内直连的 `http://jwxt.upc.edu.cn`
  **不填**：它不是入口，且 2019 年的通知给的是 http，写进来只会让首次进入落到一个 http 页。
- **不写 `scheduleUrlHint`**：教务在网关重写域上的确切地址我们没有账号验证过（`-443` 后缀是上游看到的形态，
  校方通知里没出现过）。「一键刷新」会打开上次**成功提取**的那一页，比猜一个地址准。
- **`allowHosts` = `["*.webvpn.upc.edu.cn", "jwxt.upc.edu.cn"]`**，理由：

  1. 脚本请求的是**当前页面同源**。用户从网关进教务后，页面可能是
     `jwxt-443.webvpn.upc.edu.cn`（网瑞达按端口重写的子域），**同一台教务也可能以别的端口后缀出现**
     （同批次的 `neau` 就在校方通知里同时出现过 `<站点>` 与 `<站点>-443` 两种写法）。写死一个
     `jwxt-443.webvpn.upc.edu.cn` 会让「重写形态稍有不同」的用户**被自己的白名单静默挡死**，
     所以这一族写成后缀通配：`*.webvpn.upc.edu.cn` 是**四段**（规范要求至少三段，`*.edu.cn` 会被拒），
     且仍然只落在**学校自己的网关域**下。
  2. `jwxt.upc.edu.cn` 是**精确主机、零通配**：教务自己的名字（教务处通知里的地址）。校内直连时
     用户可能就停在这个域上，相对路径要能发出去。它不是第三方域。
  3. **不用更宽的 `*.upc.edu.cn`**：那会把「学校所有主机」都放进来，而本适配器只需要网关域族 + 教务自身这**两类**。
  4. **不含任何第三方**：统计、CDN 上的业务接口、加速器 —— 一个都没有。

  > **要点名的代价**：WebVPN 网关是个**代理**，放行 `*.webvpn.upc.edu.cn` 等于放行「网关能转发到的任何校内服务」
  > —— 这条口子天然比非 WebVPN 学校粗（与 `neau` 的结论一致）。本适配器只发**一条固定路径**、
  > 不发往任何外部域，脚本全文对用户可见；但以后移植网关系学校时，审计要盯的是
  > **「脚本要了哪条路径」**，而不是「域名是不是本校的」。

  > **桥的代价**：`JwOriginRules.forAdapter` 跳过 `*.` 通配项，所以 `__ncOcr` / `__ncAsk` **不会**注入到
  > `jwxt-443.webvpn.upc.edu.cn` 这类重写子域上（`loginUrl` 的 `webvpn.upc.edu.cn` 会注入）。
  > 本适配器是纯 DOM + fetch，不用 OCR 与提问桥，**没有影响**；换学校时如果要用 OCR，
  > 得写精确主机名（或改宿主的 origin 规则，那是 Kotlin，不在本次改动范围内）。

## 3. 有没有绕过白名单的写法 —— 逐类点名

| 写法 | 有没有 |
|---|---|
| 把目标地址塞进 URL 参数（`?url=` / 网关的 `/proxy?target=` 之类） | **没有**。请求只有一条固定路径 `/jsxsd/xskb/xskb_list.do`，**不带任何 URL 参数**；body 只有强智自己的四个表单字段。 |
| 非同源 iframe / `<img>` / `<script>` 拉取 | **没有**。脚本不创建元素、不 append（`grep -nE "createElement|appendChild|innerHTML\s*=\|new Image"` 两段脚本都无命中）；取回的 HTML 只交给 `DOMParser`（惰性文档，不执行脚本、不加载子资源）。 |
| 重定向把数据带走 | **没有**。不赋值 `location`、不导航、不开窗。唯一的重定向风险是强智把未登录的请求 302 到校内统一身份认证 —— 那仍然是学校自己的域，且我们拿到的是「没有课表的页面」→ 直接明确报错。 |
| `fetch(u,{mode:'no-cors'})` / 跨域带凭据 | **没有**。唯一一处 fetch 是同源相对路径 + `credentials: 'same-origin'`（本校 cookie 交给本校接口），没有 `mode` 覆盖、没有跨域目标。 |
| 把主机名拼出来（域名分片、base64 拼串） | **没有**。脚本里连参与请求的主机名字面量都没有，只有路径。 |
| WebSocket / EventSource / Service Worker 侧信道 | **没有**（三者在两段脚本里都无命中）。规范 §3.3 明说这三类不经过宿主的请求拦截，所以只能靠读脚本审 —— 本适配器一类都不涉及。 |
| `sendBeacon` / 隐藏表单提交 | **没有**。 |
| 借 `sameOriginUrl()` 把请求引向别的主机 | **没有**。它只从 `location.pathname` 取 `/http[s]/<token>` 前缀，拼出来的仍是**同源**相对路径。 |

## 4. 手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **通过**。两段脚本都不读 `password` / 登录表单 / `localStorage` / `document.cookie`（`grep` 无命中，见 §5 的扫描口径）。网关登录由用户在 WebView 里手工完成；fetch 只带同源 cookie。 |
| 2 | 不外发 | **通过**。无 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏 iframe / 表单提交；除课表接口外没有任何目的地；跨域请求一个都没有。 |
| 3 | 请求域可控 | **通过**。请求域 = 当前页面同源（校外即 `*.webvpn.upc.edu.cn`，校内直连即 `jwxt.upc.edu.cn`），两者都写进了 `allowHosts`（理由与代价见 §2）。 |
| 4 | 只读课表 | **通过**。只请求课表页 `/jsxsd/xskb/xskb_list.do`。不请求成绩、学籍、考勤、缴费、个人信息；上游脚本里也没有这些接口。读的是什么见 §5「读取面」。 |
| 5 | 不埋点 | **通过**。无统计、无上报、无遥测；没有「回传失败原因」的请求；连 `console` 都没有（上游也没有）。 |
| 6 | 不 eval 远程代码 | **通过**。无 `eval` / `new Function`（宿主用 `new Function` 编译适配器脚本是宿主的机制，不是适配器行为）；取回的 HTML 只经 `DOMParser`，`parse.js` 只经 `JSON.parse`。 |
| 7 | 不写页面 | **通过**。两段脚本对页面只读。上游在页面里写过 `window.validateYearInput`（它自己输入校验用的全局函数）—— 移植时**连同弹窗一起删掉了**。 |
| 8 | 不依赖用户输入之外的秘密 | **通过**。无硬编码密钥 / 固定令牌 / 他人学号；`xnxq01id` 来自课表页下拉框（读不到就留空交给教务默认），`now` 来自浏览器本地时间。 |

## 5. 读取面（`extract.js` 到底读了什么）

第 4 条说的是「读什么」，这里说「怎么读、读到哪一层」。本节与代码逐条对齐（给函数名，不给行号 —— 行号会漂）。

| # | 读什么 | 代码位置 | 取出的值 | 去处 |
|---|---|---|---|---|
| 1 | 当前页面：`#timetable` / `#kbtable`，都没有时含 `.kbcontent` 的那张表 | `findTable()` → `rowsOfTable()` | 每格的 `textContent` + **一份** `div.kbcontent*` 的 `innerHTML` | 载荷 `rows[]`（由 `parse.js` 解释） |
| 2 | 同上那页的「学年学期」下拉框：id 或 name 含 `xnxq` 的 `<select>` | `readTerm()` 主路径 | 选中项的 value（`2026-2027-1`）与选项文字（学期名） | 请求 body 的 `xnxq01id` + 载荷 `term` |
| 3 | 兜底①：`document.title` | `termTextHints()` | 只做一次正则匹配 | 见下 |
| 4 | 兜底②：页面上**每个** `<select>` 的 option 文字 | `termTextHints()` | 同上 | 见下 |
| 5 | 兜底③：id 或 class 含 `xnxq` 的元素的**短**文本（≤120 字） | `termTextHints()` | 同上 | 见下 |

兜底（3-5）只在下拉框认不出学期时才走，与同平台的 `hynu` 是**同一套收窄口径**（**不读 `document.body`**）：

- 取到的整串文字只在本页内存里做一次正则匹配
  `(20\d{2})\s*-\s*(20\d{2})\s*学年\s*第?\s*([一二三123])\s*学期`；
- 命中后**只把匹配到的那一小段**（如 `2026-2027学年第一学期`）当学期名，`term.code` 由捕获组拼出来；
- 没命中的文字不留引用、不记日志、**不外发、不进载荷**；
- 这条路径上唯一可能进载荷的是 `term.name` / `term.code`，即学期名，不是页面上的其它内容。

`parse.js` 不读页面、不联网：输入是 `extract.js` 交出来的 JSON 字符串（`__ncInput`），是纯函数。

**两段脚本的行为清单**（供逐条核对，`grep -nE "createElement|appendChild|innerHTML\s*=|document\.write|location\s*=|localStorage|sessionStorage|document\.cookie|sendBeacon|WebSocket|EventSource|new Image|eval\(|new Function|password|pwd|XMLHttpRequest"` —— **无命中**）：

- 网络：`extract.js` 一处 `fetch`（`requestHtml()`，同源 POST，最多调用 2 次）；`parse.js` 零网络调用。
- 页面：只读（`DOMParser` 解析取回的 HTML；不碰 `document` 的写 API）。
- 存储：不读不写任何存储；不碰 cookie。
- 载荷：`warnings` 只写「哪些字段是推算/假定的、哪些块没解析出来」两类内容，不写广告、不模仿空课自己的文案。

## 6. 与 hynu 的同平台对照片（哪些能抄、哪些一抄就坏）

上游脚本与已落地的 `hynu` 相似度 0.863（同平台近克隆），但**不是逐字克隆**。按「接口信封 / 字段名 / 取数路径 /
编解码 / 分页」分层（测试方案 §3.2）：

| 层 | hynu（衡阳师范学院） | upc（中国石油大学华东） | 能不能照抄 |
|---|---|---|---|
| 平台与接口路径 | 强智 `/jsxsd/xskb/xskb_list.do` | 同 | **能**（两边都是强智学生端） |
| 请求体 | `cj0701id=&zc=&demo=&xnxq01id=` | **一字不差** | **能** |
| 格子结构与字段名 | `div.kbcontent` + `font[title=教师\|周次(节次)\|教室]` | 同 | **能**（上游 UPC 用的正是这套 title） |
| **课名从哪来** | 第一个 `<font>` **之前**的纯文字 | **没有 title 的 `<font>` 里的文字**（上游选择器 `font:not([title])`） | **不能**：照抄 hynu 会让 UPC **所有课都读不出课名**（变异 M3 实测：基本课表用例变红，另两份整个解析不出课程）。本移植两条都认，以无 title 的 `<font>` 为主 |
| 明细 div 选哪份 | 隐藏的 `kbcontent` 优先，只取一份 | 上游把 `.kbcontent, .kbcontent1` **两份都算**（同一门课会重复）；我们按内容打分只取一份 | **不能照抄上游**；取法按「谁带 教师/周次(节次) 字样」定，同分再取隐藏的那份 |
| 周次文本 | `1-16(周)`、`1-15(单)`、拆写的 `周次`+`节次` | `1-16(周)[01-02节]`（节次与周次同一条 font）、也有 `1-16周(双)` | **能复用解析**，但**必须**认「单/双 在「周」字后面」 |
| 节次文本 | `[0708节]` / `[07-08节]` | 同（`[01-02节]`、`[0102节]`） | **能** |
| **每周起始日** | `firstDayOfWeek = 1`（周一） | **`firstDayOfWeek = 7`（周日）** | **不能**：`firstDay` 要回退到**周日**（本移植按手册 §4.3 做，并在 warnings 里说明） |
| 作息表 | 12 节，08:30 起 | 12 节，**08:00** 起（上游 `saveAppTimeSlots` 的 12 条） | **不能**（逐条按 UPC 的值） |
| 学期总周数 | 上游写 20 | 上游**没给**（`saveCourseConfig` 只有 `firstDayOfWeek`） | 取默认 20 + 被更晚周次抬高（进 warnings） |
| 取数路径 | 页面优先 + GET + POST 三级 | 页面优先 + **带学期 POST**（最多两次） | **不能照抄**：UPC 上游是「按学年学期 POST」，GET 只用来发现学期 |
| 分页 | 无 | 无 | 都不是问题，见 §8 第 5 条 |

## 7. 移植时删掉/改了的上游行为（不涉及安全也记一下）

- **弹窗全删**：`showAlert` 确认已登录、`showPrompt` 输起始学年、`showSingleSelection` 选第一/第二学期、
  一串 `showToast`、`notifyTaskCompletion()`。空课的导入流程自己会确认；学期改成从课表页下拉框里取
  **选中的那一项** —— 用户在页面上切学期，适配器就跟着他走（手册 §3 第 1 步认可的两种做法之一）。
- **`window.validateYearInput`** 是上游为了那个弹窗往页面写的全局函数，随弹窗一起删掉。
- **教师 / 教室**：上游写 `"未知教师"` / `"未知地点"`，这里留 `null`（空课里「未知」会当成真名字显示）。
- **丢掉 `start > 0` 才收块的规则**：上游节次读不出就静默丢块；这里节次读不出先回落本行的「第N节」标签，
  仍读不出才跳过并计数进 `warnings`。
- **周次解析重写**：上游 `weekStr.split('(')[0]` 会把 `1-16周(双)` 的标记连同括号丢掉（双周课退化成每周都上，
  而且不报警 —— 第一批 `hbmu` 的真实故障）。这里按逗号分段各判、整串开头的「单周/双周」当全局修饰，
  「只有部分分段带标记」的歧义写法计数进 `warnings`（按字面解析，不猜）。
- **作息表超出 12 节**：上游只会存 12 节；这里按每节 45 分钟、课间 10 分钟顺延补出并进 `warnings`
  （宿主的默认作息表只在 `periodTimes` **整个为空**时才顶上来，缺一半会一路带进课表）。
  **顺延有个硬上界 23:59**：第 13 节 = 21:35-22:20、第 14 节 = 22:30-23:15，第 15 节会算出 23:25-24:10
  —— `JwPayloadCodec` 的时刻只收 `00:00-23:59`，一个非法时刻会让**整次导入失败**（不是丢这一条）。
  所以补到第 14 节为止：第 15 节起的课块**保留**（节次本身合法，丢掉就再也找不回来），
  但没有上下课时间 —— 课表的网格行是按 `periodTimes` 铺的，没有时刻的课块画不出来，所以计数进 `warnings` 明说。
- **字段标题只认上游那三个**：`font[title="教师"|"周次(节次)"|"教室"]`（外加同平台拆写的 `周次`/`节次`）。
  **不认 `font[title="上课时间"]` / `[title="时间"]`** —— 那种 font 装的是钟点区间（`08:00-09:35`），
  按周次去解会从 `00-09` 里凭空造出 1-9 周，整格课多出一条排课且不报警。「时间」是移植时自己加的，上游没有。

## 9. 已知不确定 / 只有真机能验

1. **fixture 是合成的**：只保证「同样的输入永远得到同样的输出」，**不保证真实页面上的解析是对的**。
   拿到真实 dump 请替换 `fixtures/*.extracted.json` 并重跑门 —— 顺便核对四件事：
   ① 课名到底在不在无 title 的 `<font>` 里；② 同一格的两份 `kbcontent`/`kbcontent1` 各是什么；
   ③ 周次 font 的文本到底是 `1-16(周)[01-02节]` 还是别的写法；
   ④ 明细里除了 `教师`/`周次(节次)`/`教室` 还有没有别的 font title（尤其是有没有拿 `时间` 装钟点区间的写法，
   有的话它的 title 到底叫什么 —— `SPEC_TITLE` 只认列出的那三种，多出来的标题会被当没有周次字段）。
2. **`extract.js` 的选块规则（打分取一份明细）在夹具里测不到** —— 夹具是 `extract.js` **之后**的形状，
   这条规则只有真机能验（它的收益是消掉上游那种「同一门课算两次」）。
3. **`firstDayOfWeek = 7`（周日）是照上游声明的口径搬的**：它只影响「第 1 周从星期几开始」，
   而开学日本身是推算的。推算值和真值在库里长得一模一样，所以 `warnings` 第一条把日期与「周日」都写出来了。
4. **WebVPN 重写形态是按上游硬编码 + 公开说明推断的**：`jwxt-443.webvpn.upc.edu.cn` 这一个是上游脚本里
   的原值；`allowHosts` 的后缀通配对「同族但端口后缀不同」的形态也成立，所以不影响能不能用。
5. **`warnings` 的显示要新版应用**：`minAppVersionCode` 取 11（与 `dlutci` / `ustc` / 其余移植件一致），
   老版本能装、能导入，只是不显示核对提示。若希望「推算的开学日」必定被看到，集成时可提到带 warnings 通道的版本。
6. **没有账号做过真机抽验**（测试方案 §4 的第 ③ 层）：本适配器与上游一样，正确性靠用户反馈迭代。
