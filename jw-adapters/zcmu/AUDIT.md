# 安全审计 —— 浙江中医药大学（正方新版 jwglxt 平台）

审计对象：`jw-adapters/zcmu/` 下的 `extract.js` / `parse.js`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `ZCMU/zcmu.js`（快照 commit `e62554a4034386b893bcd6813c7b2b64f8c730a3`，
2026-09-12，MIT，上游 maintainer `Daoguan-king`）。

**平台按接口路径判，不按上游抬头的自述判。** 上游脚本第 2 行写的是「基于正方教务系统 v9.0 接口适配」，
但它实际请求的是 `/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151`（正方新版 jwglxt 的课表接口，
`xnm` / `xqm` 表单参数），所以本件归**正方新版 `jwglxt`** 族，与 `zjut` / `wenhua` 同族。

审计方式：逐行读上游脚本全文 + 逐行读移植件，并跑移植手册 §5 给的静态扫描：

```
grep -oE "https?://[A-Za-z0-9.-]+"                      上游 0 条命中；移植件只有注释里的 homepage
grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*="
        -> 上游 1 条：第 162 行的 fetch(url)
        -> 移植件 1 条：extract.js 第 63 行的 fetch(url)（唯一的网络出口，GET/POST 共用）
```

## 1. 请求域与请求清单

上游脚本里**没有任何绝对 URL**，唯一的 `fetch` 地址是写死的相对路径
`"/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151"`。移植件沿用「同源」这一条，地址由
`window.location.origin` 拼出来，所以两个脚本请求的主机都只有**用户当前所在的那一个教务主机**。

| 谁 | 方法 | 地址 | 干什么 |
|---|---|---|---|
| extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期下拉框（`#xnm` / `#xqm`）。**用户已经停在课表页时这一步整个跳过**（直接读当前页面的这两个框），所以正常情况下只发一个请求 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表数据。body 与上游逐字一致：`xnm=<4 位起始学年>&xqm=<学期代号>&kzlx=ck&xsdm=&kclbdm=&kclxdm=`（上游 `getSemesterCode` 用 3 = 第一学期、12 = 第二学期） |

- `<origin>` 只可能是 `https://jwmk.zcmu.edu.cn`（`loginUrl` 的主机）。extract 用
  `window.location.origin` 拼地址，**不在页面里跳转、不硬编码主机名**。
- **`allowHosts` 是空的**：两条请求都是同源，与 `loginUrl` 同一个主机，不需要额外白名单
  （应用会把 `loginUrl` 的主机自动放进白名单）。这里也**不能用 `*.` 通配** ——
  `JwOriginRules` 会跳过通配项，写了通配就拿不到提问桥（见 §3 第 9 条）。
- 请求头只带 `Content-Type` / `X-Requested-With` / `Accept`，**不带任何自定义令牌**；
  `credentials: 'include'` 让 WebView 按同源规则自己带会话 Cookie，脚本不读也不写它。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 读了什么

| 读的东西 | 在哪 | 用途 |
|---|---|---|
| `window.location` 的 `origin` / `protocol` / `host` / `pathname` | extract.js | 拼同源地址（`pathname` 只用来兼容挂在门户前缀下的部署） |
| 当前页面 `#xnm` / `#xqm` 两个下拉框的 `value` 与选项文本 | extract.js | 取用户当前选中的学年学期 |
| 课表页 HTML（`fetch` 回来后交给 `DOMParser` 解析成**离线文档**） | extract.js | 同上，页面里读不到时才走 |
| POST 响应 JSON 的 `kbList` 数组 | extract.js | 排课行，原样交给 parse.js |
| `__ncCapabilities.ask` / `__ncSelect` | extract.js | 问一次校区（见 §3 第 7 条） |
| `new Date()` | extract.js | 只取当天日期（`today`），供 parse.js 在学年读不出来时推算开学周 |

**没有读**：Cookie / `localStorage` / `sessionStorage` / 登录表单的账号密码 / 任何隐藏令牌；
**没有带出**：课表接口响应里夹带的学生信息（正方放在 `xsxx` 之类的字段里）——`extract.js`
只把 `kbList` 排课行交出去，其余字段一律不取、不进 fixture。

## 3. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。没有 `password` / `pwd` / 登录表单读取，没有 `localStorage` / `sessionStorage` 访问（静态扫描无命中）。唯一的「凭据」是浏览器按同源规则自己带的会话 Cookie，脚本既不读它、也不把它发到别处。**提问桥也没有用来索要任何账号信息**：唯一一次提问是选校区（两个选项都是校区名） |
| 2 | 不外发 | **过**。两个脚本合计只有 `extract.js` 里的一处 `fetch` 调用，地址全部由 `window.location.origin + '/jwglxt'` 拼成；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有任何第三方域（`allowHosts` 为空）。`extract.js` 里出现的两处 `https://` 都是**注释里的上游仓库地址**，不是请求目标 |

| 4 | 只读课表 | **过**。只请求课表页与课表接口（`/jwglxt/kbcx/*`），不碰成绩（`/jwglxt/cjcx/*`）、学籍、个人信息、缴费等任何其它接口。上游脚本除了 `fetchAndParseCourses` 里的那一个请求外没有任何网络调用（静态扫描只有 1 条 `fetch(`），移植件同样只保留这一个 |

| 7 | 不写页面 | **过**。`extract.js` 只**读**当前页面里 `#xnm` / `#xqm` 两个字段的值；取课表页 HTML 时用的是 `fetch` + `DOMParser`（离线文档，不插入当前页面），既不写 DOM、不改表单、也不触发提交或点击。**唯一的用户可见副作用是提问桥**：`__ncSelect` 弹一次「选择校区」（标题 / 说明 / 选项全部是校区名，由应用渲染弹窗抬头），取消是正常结果、按「没选」回落滨文校区并写进载荷 warnings |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码密钥、令牌或他人的学号。脚本里的常量只有正方的菜单号 `N2151`、上下文路径 `/jwglxt`、两张作息时间表与两个校区名，都是公开信息 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表，不碰凭据、不外发、不埋点。

## 5. 移植时对上游做的删改（都不牵涉安全问题，但审阅者需要知道）

1. **ES6 转 ES5**：`async/await` 改成 `then` 链，去掉模板串、箭头函数、`let`/`const`。
   `parse.js` 是纯函数、`extract.js` 只有一条 Promise 链。
2. **三个弹窗砍成一个**：上游连问三次（起始学年手输 4 位数字 / 学期 / 校区）。移植件把学年学期
   改成**自动取教务当前选中的那一份**（用户在课表页时读 `#xnm` / `#xqm`，那是他自己切过的学期），
   只保留「校区」一问 —— 两个校区的作息时间不同，而这件事页面上没有、从排课行里也认不出来
   （教室名不足以下判断），只能问用户。载荷里用 warnings 说明「只导入了当前学期」。
3. **切两段**：上游在同一个脚本里算周次、拼课程、存配置；移植件把取数留在 `extract.js`
   （只交出 `kbList` 排课行），周次解析、节次解析、课程合并、开学日推算全部落在 `parse.js`，
   这段逻辑因此在 CI 里有真回归。
4. **不再丢行**：上游要求 `xm`（教师）与 `cdmc`（教室）都非空，缺一个就 `continue` ——
   没排教室、还没定教师的课会**凭空消失且不留痕迹**。移植件留空（`null`），行照收。
5. **周次解析整段重写**：上游的 `parseWeeks` 有两个真会丢课的洞 ——
   ① 正则 `/(\d+)-(\d+)周/` 要求数字后面紧跟「周」字，所以 `1-3,5-9周` 的第一段 `1-3`
   **被整段吞掉**（只剩 5-9 周），`1-16(单周)` 整段认不出来、**这门课直接没了**；
   ② 括号里的教学班序号不剥，`(1-2)1-16周` 会被读成只有第 1-2 周。
   移植件按移植手册 §4.1 重写：括号分「纯数字组」与「其余」两类分别处理、
   数字不再要求跟「周」字、周次集合再切极大段。**这三处都有专门的用例与变异记录**（§6 的 M2 / M3）。
6. **节次取首末改成取最小 / 最大**：上游 `parseSection` 取 `parts[0]` 与 `parts[last]`，
   遇到 `3-4节(1)` 会得到 3 到 1、末节比首节还小，整行被默默丢掉。
7. **开学日与总周数**：上游给 `semesterStartDate: null`、`semesterTotalWeeks: 20`；
   移植件按学年学期推算开学周的周一（第一学期 = 9 月 1 日所在周的周一），总周数从上游那个
   20 起、被课表里更晚的周次抬高时以课表为准，**两种情况都写进 warnings**。
8. **脏数据不再静默丢**：上游解析不了的行直接 `return`；移植件按「缺课名 / 缺星期 / 缺节次 /
   缺周次」分别计数，合并成一条 warnings，节次写法认不出来的单独再出一条。

## 7. 没能确定的事（交接给下一位）

- **fixture 是合成的**（五对，全部在文件头的 `_note` 里注明）：按上游脚本实际读取的字段名
  （`kcmc` / `xm` / `cdmc` / `cdbh` / `xqj` / `jcs` / `zcd`）编出来的形状正确的数据，
  **不是真实抓取**。它只保证「同样的输入永远得到同样的输出」，不保证真实页面上解析正确。
  拿到真实 dump 后请替换 fixture 并重跑门（测试方案 §3）。
- **`jcs` / `zcd` 的真实写法只覆盖了用例里那几种**：`1-2` / `0102` 形态的节次，
  以及 `1-16周` / `1-16周(单)` / `(单)1-16周` / `1-16(单周)` / `1-3,5-9周` / `2-16周(双)` /
  `1-16周(1)` / `(1-2)1-16周`（以上 `weeks-forms`）、`1-16周,双` / `1-16周，双` / `1-16周,双周` /
  `双周,1-16周` / `1-16周,单` / `(1),双,1-16周` / `双周` 与六种破折号异体
  （以上 `week-marks`）这些周次写法。上游脚本自己只认「数字紧跟周字」的形态，
  说明**真实数据里大概率就是那几种**，但 `1-16(单周)`（无「周」字结尾）、括号序号、
  自成一段的单双标记、以及那六种破折号异体，都是从别的正方学校见过的写法、
  **没有 ZCMU 的真实样本** —— 破折号异体这一条尤其拿不准 ZCMU 到底会不会吐，
  修它是因为同族几所学校实测会吐、且只认半角「-」的代价是静默丢 15 周。
- **作息时间两张表是上游写的**，其中富春校区第 5 节 `11:35–13:15` 疑为笔误（见 §4 第 4 条）；
  滨文校区的作息也**没有和学校实际校历核对过**。真机上请核对一次。
- **`xskbcx_cxXskbcxIndex.html` 这个页面路径没有验证过**：上游只请求数据接口、从不请求课表页 HTML，
  移植件为了「不在课表页时也能自动取学年学期」加了这个 GET（正方该菜单号下页面路径的通用形态）。
  用户停在课表页时这一步会跳过，所以**最坏情况是「不在课表页时提示读不到学年学期」**，
  不会解析出错。真机上请核对一次。
- **校区**：上游作者说明是「通过滨文校区的教务数据开发的，不确定富春校区是否支持」，
  作息表分校区这一条**同样没有经过富春校区的实测**。
- **接口没有回记录总数**，所以「取少了课」在脚本这侧看不出来（见 §4 第 6 条）。
