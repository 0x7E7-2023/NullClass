## 1. 请求了哪些域、哪些地址

上游脚本只引用**一个绝对 URL**：`https://xk.huel.edu.cn/jwglxt`（写在 `BASE` 常量里）。移植件
**不写死主机**：所有地址都由 `window.location.origin` + `/jwglxt` 拼出来（`extract.js` 的 `jwBase()`，
路径里已经带 `/jwglxt` 前缀时跟着它走），所以脚本请求的主机永远是**用户当前所在的那一个教务主机**。

| # | 谁 | 方法 | 地址 | 什么时候发 | 干什么 |
|---|---|---|---|---|---|
| ① | extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | **仅在当前页面上读不到 `#xnm` / `#xqm` 时** | 离线解析返回的 HTML（`DOMParser`，不插入当前页面），读学年 / 学期下拉框 |
| ② | extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151`　body：`xnm=<学年>&xqm=<学期>&kzlx=ck&xsdm=&kclbdm=&kclxdm=` | 每次提取 | 取课表（JSON，只取 `kbList` 排课行） |
| ③ | extract.js | POST | 同 ② 的地址，body 追加 `&queryModel.showCount=<总数>&queryModel.currentPage=1` | **仅在信封报的记录总数大于实到行数时**，最多一次 | 补取没给全的行（见 §5 第 5 条） |

- 三个请求都带 `Content-Type: application/x-www-form-urlencoded;charset=UTF-8`、`X-Requested-With: XMLHttpRequest`、
  `Accept: */*` 与 `credentials: 'include'`（让 WebView 自己按同源规则带 Cookie，脚本不读也不写它）。
- **`allowHosts` 是空的**：三条请求全部同源，与 `loginUrl` 同一个主机，不需要额外白名单。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

实测（`extract.js` 冒烟脚本，假 fetch 记录调用）：已在课表页时**只有 ②**；不在课表页时 **①+②**；
报总数 5、实到 1 行时 **②+③**（`followUp: "ok"`，拿到 5 行）；报总数 42、补取失败时 `followUp: "failed"`；
返回登录页 HTML 时明确报错（「教务系统没有返回课表数据」），不会静默通过。

## 2. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | **不碰凭据** | 通过。没有 `password` / `pwd` / 登录表单读取，没有 `localStorage` / `sessionStorage` / Cookie 访问（静态扫描无命中）。唯一的「凭据」是浏览器自带的会话 Cookie，脚本既不读它也不外发。**也没有用提问桥**（不用 `__ncSelect` / `__ncPrompt` / `__ncConfirm`），不存在借弹窗索要账号信息的可能 |
| 2 | **不外发** | 通过。两个脚本只有 `extract.js` 里的 `fetch`（三处调用，地址都是同一个 `jwBase()` 拼出来的同源地址）；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，没有任何第三方域。上游的 `shiguangBridge*` 桥调用全部没有移植 |
| 3 | **请求域可控** | 通过。请求主机只有一个：用户当前所在的那个教务主机（`loginUrl` 的主机 `xk.huel.edu.cn`）。**不写通配**，`allowHosts` 留空 |
| 4 | **只读课表** | 通过。只调课表页与课表查询接口（`/kbcx/*`），不碰成绩（`/cjcx/*`）、学籍、个人信息、缴费等任何其它接口。**上游写死主机、还要求页面正好在课表页；移植件把主机改成同源、也不再要求停在课表页**，但没有增加任何新接口 |
| 5 | **不埋点** | 通过。没有统计 / 上报 / 遥测，没有打点。两个脚本都不写 `console` |
| 6 | **不 eval 远程代码** | 通过。没有 `eval` / `new Function`；教务返回的字符串只做 `JSON.parse` 与字段读取 |
| 7 | **不写页面** | 通过。`extract.js` 只**读**当前页面上的 `#xnm` / `#xqm` 两个字段（下拉框 `options` 或隐藏 input 的 `value`）；课表页 HTML 用 `fetch` + `DOMParser` 解析成**离线文档**，不插入当前页面；不写 DOM、不改表单、不触发提交、不点击、不跳转。`parse.js` 完全不碰页面 |
| 8 | **不依赖用户输入之外的秘密** | 通过。没有硬编码密钥 / 令牌 / 他人学号。脚本里的常量只有上下文路径 `/jwglxt`、正方菜单号 `N2151`、作息表与警告文案 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表；不碰凭据、不外发、不埋点、不写页面、不提问。

## 3. 读了什么、丢掉了什么

- 排课行里**用到**的字段：`kcmc`（课名）、`xm`（教师）、`cdmc` / `cdbh`（教室）、`xqj`（星期）、
  `jcs`（节次；为空时退回 `jc`，再为空退回 `jcor`）、`zcd`（周次）。其它字段（`kch` / `xf` / `zhxs` /
  `jxbmc` / `xqh_id` 等）原样随行交出去但**不使用**。
- **主动丢弃**：课表响应的信封里除了 `kbList` 还有登录学生自己的信息（正方放在 `xsxx` 之类的字段里），
  `extract.js` **只交出 `kbList`**，其它字段一律不带出 —— 冒烟测试里伪造了 `xsxx`（学号 / 姓名 / 身份证号），
  输出里没有它。fixture 也因此天然脱敏（课程、教师、教室全是虚构的）。
- 上游把教师 / 教室为空的课写成 `'未知'` / `'未排地点'`；移植件**留空**（`null`）——那两个占位符在课表里
  会被当成真名显示，而信息并没有丢（教务本来就没给）。

## 4. 与 `zjut` 的同平台对照片（相似度 0.833，哪些能复用、哪些不能）

| 层 | 复用程度 | 本适配器的实际情况 |
|---|---|---|
| 接口信封 | **能复用** | 同一套 `/jwglxt` 上下文路径、同一个 POST 表单接口 `kbcx/xskbcx_cxXsgrkb.html`、同样是 `{kbList:[...]}` 的 JSON。**但菜单号不同**：`zjut` 是 `N253508`，本校上游用的是 `N2151`（同平台 80 个上游脚本里 N2151 也最常见） |
| 行字段名 | **能复用** | `kcmc` / `xm` / `cdmc` / `cdbh` / `xqj` / `jcs` / `zcd` / `xqh_id` 与 `zjut` 一致；上游 HUEL 只认 `jcs`，移植件补了 `jc` / `jcor` 兜底（与 `zjut` 的上游同口径） |
| 取数路径 | **部分复用** | 学年学期都从课表页的 `#xnm` / `#xqm` 读（同一套做法）。但上游 HUEL 把主机写死成 `https://xk.huel.edu.cn` **并要求当前页正好是课表页**（`isOnTimetablePage`），`zjut` 上游用 `window.location.origin`；移植件按后者做，所以用户在任意一页都能提取 |
| 周次编码 | **常能复用，但有本校差别** | `1-16周` / `1-16周(单)` / `1-16周(双)` / `1-4,6-8周` 这些写法两校一样；上游两校的 `parseWeeks` 是逐字克隆（只差空白与变量名，见 §6）。**但总周数口径不同**：`zjut` 移植件取「实际周次的最大值」（`1-16周(单)` → 15 周），本适配器取**周次文本声明的上界**（→ 16 周），否则单周课会把学期截短一周 |
| 节次编码 | **常能复用** | 正方的 `jcs` 都是 `1-2` / `3-4` 这种；本适配器另外认 `01-02节`、`0102`（两位一节连写）、`第9,10节`（测试方案 §3.1 点名的这几种写法），并把**区间**当成连堂（`1-4` = 第 1 到第 4 节），不再把它当成「1 和 4 两个孤立的节」 |
| 分页行为 | **未必** | 正方的学生课表接口一次给全（上游两校都不翻页）。本适配器仍然看信封里的总数字段，报的总数大于实到行数时补一次请求、补不全就报警（见 §5 第 5 条） |
| 作息表 | **不能复用** | `zjut` 是 10 节（第 10 节 18:30-21:30），本校是 **13 节**（08:00 起，第 11-13 节在 19:00-21:25）；照抄 `zjut` 的节次表会把晚上的三节课排错时间 |
| 开学日锚点 | **不能复用** | `zjut` 移植件用「第二学期 = 2 月 20 日所在周的周一」；本校上游自己在给用户的默认值里写了 `<学年>-09-01`（第一学期）与 `<学年+1>-03-01`（第二学期），本适配器就按这两个锚点找所在周的周一 |

**结论**：把 `zjut` 当模板是对的（两段式切法、周次切段、合并去重、warnings 结构照搬），
但**不能照抄完事**的正好是上面标了「不能复用 / 有本校差别」的五处：菜单号、作息表、总周数口径、
开学日锚点、以及主机是否写死。

## 5. 上游取数方式与移植改动

上游：一个脚本，`resolveTerm()` 拿学年学期（在课表页读 `#xnm`/`#xqm`，否则取一次课表页 HTML 再让用户
在两个弹窗里选），POST 课表接口，自己在脚本里算周次、拼课程、**再用第三个弹窗问开学日期**，最后把
`courses` / `timeSlots` / `config` 通过 `window.shiguangBridge*` 交给拾光的宿主。

移植改动（都不牵涉安全，但审阅者要知道）：

1. **切两段**：取数留在 `extract.js`（只交出 `kbList` 行 + 学年学期 + 取数元信息），
   周次解析、节次解析、课程合并、总周数、开学日推算全部落在 `parse.js` —— CI 因此能真跑这段逻辑。
2. **ES6 改成 ES5**：`async/await` 改成 then 链，去掉模板串、箭头函数与块级作用域声明（CI 硬检查）。
3. **不弹窗问**：上游的「选学年 / 选学期 / 填开学日期」三个弹窗全部去掉 —— 改成自动取教务当前选中的
   学年学期（用户在页面里自己切学期优先），开学日期按学期锚点推算**并写进 `warnings`**，用户能在
   导入预览里看到「这是推算值」。上游那段默认日期代码反而成了本适配器的锚点依据。
4. **只取数**：上游在脚本里拼课程；移植件把原始行交出去（行字段名与上游读的一致）。
5. **开学日 / 总周数**：上游给 `semesterStartDate: <推算或用户输入>`、总周数取实际周次最大值；
   移植件按学年学期锚点推算并在 `warnings` 里说明依据，总周数取「课表里出现的最晚周次（含单双周区间
   声明的上界）」，同样写进 `warnings`。
6. **脏数据不再静默丢**：上游 `parseCourses` 里 `return` 掉的行不留痕迹；移植件按「缺课名 / 星期」
   「节次读不出来」「节次超出上限」「没有周次」四类分别计数并写进 `warnings`。
7. **教师 / 教室不再写占位符**（见 §3）。
8. **分页不再只看第一页**（见下）。

### 第一批审查的 8 条坑，逐条对照

| # | 坑 | 本适配器的处理 | 谁在看着它 |
|---|---|---|---|
| 1 | 「单 / 双」写在「周」字后面（`1-16周(双)`）被吞、退化成每周都上 | 先在整段里认 `单` / `双` 标记，再做其余清理（顺序刻意如此）；同一段里单双同时出现（`1-16周(单双)`）按每周都上处理**并报警** | `weeks-parity` 用例；变异 M1（把标记置空）→ 用例变红 |
| 2 | 括号里的纯数字序号 `(1)` 不是周次 | 括号外有周次数字时完全不看括号里（`3-4周(1)` → 第 3、4 周，不是第 1、3、4 周）。正方这里风险本就小：课名 / 教师 / 教室是分开的 JSON 字段（`kcmc` / `xm` / `cdmc`），适配器**从不解析拼在一起的单元格文本**，`(1)` 只会出现在 `zcd` 里 | `weeks-parity` 用例；变异 M2（把括号里也算周次）→ 用例变红 |
| 3 | 读不出「第N节」标签的行不许静默丢课 | 认 `第9,10节` / `01-02节` / `0102` / `1-2节` / `1-4`；一行里数字有但超出第 1-16 节、或一个数字都没有，都**分别计数并写进 `warnings`** | `sections-forms` 用例；变异 M9（去掉 `jc` 兜底）、M13（不报警）→ 变红 |
| 4 | 连堂标签下 `periodTimes` 要覆盖每一节 | 作息表 13 节覆盖 1-13；连堂 `1-4` 的 block 是 `startPeriod 1 / endPeriod 4`，节次表里 1-4 都有；课表用到第 13 节之后的节次时，按上一节的时长顺延（+10 分钟休息、45 分钟一节）补出条目**并报警** | `basic`（连堂 1-4 与晚上 11-13）、`sections-forms`（第 14 节）；变异 M5 / M6 / M7 → 变红；另有脚本按「每个 block 的每一节都要在 periodTimes 里」逐用例检查 |
| 5 | 分页：接口没回记录总数时不能只取第一页；取不全要出声 | 正方学生课表接口**不翻页**（上游两校都不翻页），所以先看信封有没有总数字段（`totalResult` / `total` / `totalCount` / `totalRow` / `records`）：报了总数且大于实到行数时**补一次**带 `queryModel.showCount` / `queryModel.currentPage` 的请求，补不全就把总数交给 `parse.js` 写进 `warnings`；没有总数就不编造「可能有下一页」 | `short-page` 用例（报 42 条只交 4 行）；变异 M3（不报警）→ 变红。`extract.js` 本身 CI 跑不到，这段只能靠冒烟脚本与真机 |
| 6 | 总周数被课表里更晚的周次抬高时要进 warnings | 载荷声明的总周数（`term.totalWeeks` / `term.semesterTotalWeeks`）小于课表里最晚周次时，按最晚周次抬高**并报警**；正方通常根本不报总周数，这时走「取课表里最晚周次」的分支，同样报警 | `short-page` 用例（声明 16 周、课表排到第 18 周）；变异 M4 → 变红 |
| 7 | `AUDIT.md` 声明必须与代码一致 | 本文的请求清单、请求头、读取字段、丢弃字段逐条来自 `extract.js` / `parse.js` 正文，不比代码窄；§1 末尾那段冒烟实测就是记录的请求流水 | 冒烟脚本的调用记录（§1） |
| 8 | fixture 期望值独立推出 + 变异测试证明用例真能拦住 | 5 个用例的期望载荷按规范（周次切段 §4.1、`weekType` 语义、开学日锚点、总周数口径）**先手推、后跑**，输出与手推不一致时先查代码（M7 与「`over` 行被重复计数」两处 bug 就是这么抓到的：`1-4` 曾被切成第 1-1 节、越界行同时进了两类计数）；变异表见 §7 | 14 个变异，每个至少翻红一个用例 |

## 6. fixture 说明

**都是合成的**（每个 `*.extracted.json` 顶部的 `_note` 写明）：手上没有该校账号，只按上游脚本实际读取的
字段形状（正方 `kbList` 行）编造。它只保证「同样输入永远同样输出」，**不保证在真实教务上解析正确** ——
与内置 `universal` 的合成 fixture 同一个档位（测试方案 §3）。拿到真实 dump 后请替换 fixture 并重跑门。

| 用例 | 覆盖 |
|---|---|
| `basic` | 多行合并成多个 block、完全重复的行去重、连堂 1-4、晚上 11-13、分段周次（半角与全角逗号）、单双周、`jcs` 为空退回 `jc`、空教师空教室、3 行脏数据（无课名 / 无节次 / 星期为 0） |
| `weeks-parity` | `1-16周(双)`、`1-16周(单)`、`双周2-16`、`单周1-15`、`1-18周全周`、`1-17周单周`、`3-4周(1)`（括号序号）、`1-8周(单),9-16周(双)`（多段）、`1-16周(单双)`（同时出现，按每周都上并报警） |
| `sections-forms` | `01-02节`、`0102`、`第9,10节`、`1-2节`、`1-2,5-6`（两段只取前一段并报警）、`14`（超出内置作息表）、`17-18`（超出节次上限整行跳过并报警） |
| `short-page` | 信封报 42 条只交回 4 行（`followUp: "failed"`）必须报警；学期声明 16 周而课表排到第 18 周（第二学期，顺带覆盖 3 月 1 日锚点） |
| `weeks-overflow` | `1-36周` 超出 1-30 的部分丢弃并报警（总周数按上限 30）、`zcd` 为空的行跳过并报警、正常行不受影响 |

## 7. 变异测试结果（把 `parse.js` 改坏 → 哪条用例变红）

原始：`basic=MATCH  weeks-parity=MATCH  sections-forms=MATCH  short-page=MATCH  weeks-overflow=MATCH`

| 变异 | 变红的用例 |
|---|---|
| M1 单 / 双标记被吞（退化成每周都上） | basic, weeks-parity, short-page |
| M2 括号里的纯数字序号被当成周次段 | **weeks-parity** |
| M3 接口报的总数大于实到行数时不出声 | **short-page** |
| M4 总周数被更晚的周次抬高时不报警 | **short-page** |
| M5 作息表不为超出的节次补时间 | **sections-forms** |
| M6 作息表只到第 10 节（11-13 节没有上下课时间） | 五个用例全红 |
| M7 连堂区间只取第一节（`1-4` 变成 `1`） | 五个用例全红 |
| M8 完全重复的行不去重 | basic |
| M9 `jcs` 为空时不退回 `jc`（整行丢课） | basic |
| M10 空教师写成「未知」 | basic |
| M11 跳过的脏行不出声 | basic |
| M12 空周次的行不出声 | **weeks-overflow** |
| M13 读不出节次的行不出声 | basic |
| M14 开学日直接用 9 月 1 日（不回退到周一） | basic, weeks-parity, sections-forms, weeks-overflow |

加粗的是**为该变异专门造的用例**：它在别的变异下不动，只有对应逻辑被改坏时才红 —— 说明这条用例
盖的确实是那条路径，不是把当前行为钉死。

## 8. `loginUrl` / `scheduleUrlHint` 怎么填、为什么

- **`loginUrl = "https://xk.huel.edu.cn/"`**（只有域名，与上游 `adapters.yaml` 的 `import_url` 一致）。
  上游脚本里唯一能佐证的路径常量是 `/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html` 与
  `/jwglxt/kbcx/xskbcx_cxXsgrkb.html`（都是**模块页 / 接口**，不是登录页）；正方标准登录页
  `/jwglxt/xtgl/login_slogin.html` 是「同平台惯例」而不是本校实测地址。**不猜一个没验证过的路径**：
  写错会 404 / 落到模块页 403（`dlutci` 踩过这个坑），而根地址会由学校自己的跳转链把用户带到
  它实际的登录入口（含可能的 CAS / 门户）。取数只走同源接口，**停在教务主机（`xk.huel.edu.cn`）
上的任意一页都能提取**，根地址够用。

> **能力边界（2026-09-12 订正）**：本适配器的 `allowHosts` 为空，白名单只有 `loginUrl` 主机
> `xk.huel.edu.cn`。若用户停在**别的主机**（CAS 认证域、门户、WebVPN 网关子域）上点提取，
> 同源请求会被 JS 沙箱与原生闸门一起拦掉，界面报「禁止访问白名单之外的地址」。
> 原先这里写的是「停在任意一页都能提取」，比实际能力宽 —— 已按实情改写。
> 要支持网关入口就得把网关域写进 `allowHosts`；目前没有证据表明本校教务在网关后面，故不预先放行。
- **不写 `scheduleUrlHint`**。应用里 `startUrl = preferredUrl ?? scheduleUrlHint ?? loginUrl` ——
  写了提示就等于**新会话一进来就深链到课表模块页**，正是 `dlutci` 那个「深链落到模块页会 403」的教训；
  而本适配器**不需要**先打开课表页（学年学期读不到时自己 GET 一次课表页 HTML 离线解析），
  课表页路径 `kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` 能否在未登录时直接打开
  没有实测过。同批次的 `hbmu` / `neau` / `jstc` 也是同样取舍（`zjut` 写了，那是它上游给的信息更全）。

## 9. 明确没能确定的事（交接给下一位）

- **fixture 是合成的**（见 §6），合成 fixture 只保证输入输出稳定，不保证真实页面上解析正确。
- **开学日是推算的**：锚点来自上游脚本里给用户的默认日期（第一学期 9 月 1 日、第二学期次年 3 月 1 日），
  不是校历。真机上请核对一次，并把「本校实际开学日」反馈回来 —— 这个值决定「现在第几周」。
- **没验证过的**：`gnmkdm=N2151` 在本校是否仍然有效；课表信封里到底有没有总数字段（各部署不一样，
  没有就走「不补取」）；`queryModel.showCount` / `currentPage` 这两个正方分页参数在课表接口上是否被接受
  （不被接受时脚本会保留原行并报警，不会丢数据）；`jcs` 的真实写法（`01-02节` / `0102` / `第9,10节`
  这几种是按测试方案 §3.1 的清单做的防御，上游只演示过 `1-2`）。
- **`term.totalWeeks` / `term.semesterTotalWeeks` 目前没有任何来源**（正方不给）：解析器认它、
  并在它小于课表最晚周次时报「已抬高」，但今天的 `extract.js` 不会填这个字段，所以生产里走的是
  「总周数 = 课表里出现的最晚周次」那条分支（同样有 `warnings`）。留着它是为了将来接校历时不用改 `parse.js`。
- 上游那个「问用户开学日期」的弹窗没有移植成 `__ncPrompt`：手册 §4.2 的做法是推算 + `warnings`，
  少一次交互、也不依赖提问桥（`__ncCapabilities.ask` 为 false 时行为一致）。如果用户反馈「推算的开学日
  离真实值差得多」，改成在 `extract.js` 里问一次是下一步选项。
