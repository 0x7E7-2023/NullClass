## 1. 请求了哪些域（手册 §5 第 3 条）

上游脚本**没有任何绝对 URL**：全部地址由 `window.location.origin + '/jwglxt'` 拼出来。
移植件沿用这一做法（`originOf()` / `jwBase()`），所以：

| 谁 | 方法 | 地址 | 干什么 |
|---|---|---|---|
| extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期字段（`#xnm` / `#xqm`）。**用户已经在课表页时这一步跳过**，直接读页面上的这两个字段 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表数据（JSON，`kbList` 排课行）；body 为 `xnm=&xqm=&kzlx=ck&xsdm=&kclbdm=&kclxdm=` |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151` | 取节次时间（JSON 数组）；body 为 `xnm=&xqm=`。**取不到不算失败**，交给 parse.js 回落内置节次表并写进 warnings |

- **请求主机只有一个**：用户当前所在的那一台教务主机 = `loginUrl` 的主机
  `jw1.hustwenhua.net`（`<origin>` 就是 `window.location.origin`，脚本里没有写死的主机名，
  `grep -nE "https?://" *.js` 只命中注释里的上游仓库地址）。请求头只有
  `Content-Type` / `X-Requested-With` / `Accept` 三个固定值，**不带任何自定义令牌**；
  Cookie 由 WebView 按同源规则自己带上，脚本不读也不写它。
- **`allowHosts` = `[]`（空）**：三条请求都是同源，宿主已经把 `loginUrl` 的主机自动放进白名单
  （`JwAdapterPackage.allowedHosts(loginHost) = loginHost + manifest.allowHosts`）。
  再写一条 `jw1.hustwenhua.net` 只是重复；写别的主机会**多**放行一台。**不写通配**。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 读了什么

- **页面**：只读两个**下拉框的值** —— 当前课表页的 `#xnm` / `#xqm`（不在课表页时先取一次
  课表页 HTML，用 `DOMParser` 读**离线文档**里同样两个字段，不插进当前页面）。
  另外读 `window.location`（拼请求地址用）。
  **不读** `localStorage` / `sessionStorage` / `document.cookie` / 登录表单 / 任何密码字段
  （静态扫描无命中）；**不写 DOM、不改表单、不点提交**。
- **接口**：只有课表接口的返回体（课名、教师、教室、星期、节次、周次）与节次时间接口的返回体
  （第几节、起止时间）。
- **输出**：`extract.js` 只把 `kbList` 排课行、`timeSlots`、学年学期代号和一个日期字符串
  （`today`，用于「学年读不出来」时推算第 1 周）交出去。课表响应里夹带的**学生信息
  （`xsxx` 之类的学号姓名）一律不带走**，也不进 fixture；上游算过但没用上的 `xqh_id`（校区号）
  没有移植（它会污染教室名）。
- 载荷里只有排课信息：课名 / 教师 / 教室 / 星期 / 节次 / 周次 / 学期名 / 开学日。

## 3. 手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | ✅ 没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` / `document.cookie` 访问。唯一的「凭据」是浏览器自己带的会话 Cookie，脚本既不读内容也不把它发到别处。上游的 `showToast` / `showSingleSelection` / `notifyTaskCompletion` 这类桥调用全部没有移植 |
| 2 | 不外发 | ✅ 全脚本只有一处 `fetch`（`extract.js:53` 的 `request()` 包装），三个地址都由 `window.location.origin` 拼成；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有任何第三方域。唯一的绝对 URL 是注释里的上游仓库地址 |
| 3 | 请求域可控 | ✅ 请求主机只有一个（`loginUrl` 的主机，用户当前所在的那一台），`allowHosts` 留空、无通配。见 §1 |
| 4 | 只读课表 | ✅ 只请求 `/kbcx/xskbcx_cxXskbcxIndex.html`（课表页）、`/kbcx/xskbcx_cxXsgrkb.html`（学生课表）、`/kbcx/xskbcx_cxRjc.html`（节次时间）。不碰成绩（`/cjcx/*`）、学籍、个人信息、缴费。**注意**：课表响应体里会夹带登录学生自己的信息（正方放在 `xsxx` 之类字段），`extract.js` 只把 `kbList` 交出去 |
| 5 | 不埋点 | ✅ 没有任何统计 / 上报 / 遥测，也没有 `img` 打点 |
| 6 | 不 eval 远程代码 | ✅ 两个脚本都没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse`（包在 `try` 里） |
| 7 | 不写页面 | ✅ 不插入或修改 DOM、不改表单、不触发提交或点击。读页面只读两个下拉框的 `value`；取课表页 HTML 用的是 `fetch` + `DOMParser`（离线文档） |
| 8 | 不依赖用户输入之外的秘密 | ✅ 没有硬编码密钥、令牌或他人的学号。脚本里的常量只有正方的菜单号 `N2151` 与上下文路径 `/jwglxt`，都是公开的页面参数 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表，不碰凭据、不外发、不埋点。

## 4. 与 `zjut` 的对照片（同平台假设成立到什么程度）

先看事实：上游 `WENHUA/wenhua_01.js` 与 `ZJUT/zjut_01.js` 的 `diff` **只有四处**，
其余（`req` / `resolveTerm` / `parseWeeks` / `parseCourses` / `fetchCourses` / `run` 的主体）
逐字相同：

1. 菜单号：`GNMKDM = 'N253508'`（zjut）→ 内联写死 `N2151`（wenhua）；
2. **多一个节次时间接口** `TIME_API_PATH = '/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151'`；
3. `xqh_id` 的默认值 `'01'` → `'1'`；
4. 节次表来源：zjut 在脚本里写死一张 10 节表，wenhua 改成向教务要（`cxRjc`），
   并在 `savePresetTimeSlots` 前加了个「取到了才存」的判断。

按测试方案 §3.2 的四层分开说「能复用多少」：

| 层 | 对文华成立吗 | 依据 |
|---|---|---|
| **接口信封**（`origin + /jwglxt/kbcx/*`、`?gnmkdm=` 查询参数、`credentials: 'include'`、表单 body） | **成立**，但**菜单号不是平台常量**：zjut 用 `N253508`、文华用 `N2151`；上游另外几个 `jwglxt` 学校（QUT / SCUT）也是 `N2151`，QUT 甚至在两个菜单号之间轮流重试。所以菜单号按**上游给文华的那一个**（`N2151`）写死，不跟着 zjut 抄 | `diff`、`grep -l cxRjc`（8 个脚本用它）、`QUT/qut.js` 的 `gnmkdms` 数组 |
| **行字段名**（`kcmc` / `xm` / `cdmc` / `cdbh` / `xqj` / `jcs` / `jc` / `zcd` / `xqh_id`） | **成立**（上游两脚本读的是同一组字段，我们没有真机 dump 能证伪） | `diff` |
| **取数路径**（要哪几个接口、什么参数、要不要先取学号） | **不成立**：文华多一个节次时间接口，且它的 body 只有 `xnm`/`xqm`，而同一平台别的学校（QUT / SCUT）给 `cxRjc` 传的是完整的课表 body。这一层按文华自己的脚本走 | `diff`、`QUT/qut.js` / `SCUT/SCUT_01.js` |
| **周次 / 节次编码**（`zcd` = `"1-16周"`、`jcs` = `"1-2"`） | **假设成立但无佐证**：上游两份脚本用的是同一段 `parseWeeks`（逐字相同），所以「编码一样」是上游作者的一层假设，不是我们验过的。移植件在这层**做得比上游宽**（见 §5 的 ④⑤），并把认不出来的写法写进 warnings | `diff`（两份 `parseWeeks` 完全相同） |
| **节次时间** | 只在文华这边有：上游用 `jcdm \|\| jcmc` 当节次号、`qssj`/`jssj` 当起止；同一平台另外几个脚本也用 `jcmc`（SCUT）。移植件两个字段都认 | `SCUT/SCUT_01.js`、`NBUT/nbut.js` |

**一句话**：信封和字段名可以照 zjut 那份复用；**取数路径和节次时间不能**，
周次/节次编码只能算「同源假设」——所以这一件按文华自己的编码单独造了 fixture（§6）。

## 5. 相对上游的改动（都会影响行为，逐条列出）

1. **ES6 → ES5**：`async/await` 改成 `then` 链，去掉模板串、箭头函数、`let` / `const`。
2. **不问用户**：上游在「不在课表页」时弹两次窗（先选学年、再选学期）。
   移植件改成自动取教务当前学期 —— 用户在课表页时读页面上的 `#xnm` / `#xqm`（他自己切过的
   学期优先），否则取一次课表页 HTML 读这两个下拉框的默认选中项。载荷里用 `warnings` 说明
   「只导入了当前学期」。
3. **切两段**：上游在一个脚本里算周次、拼课程、存配置；移植件把取数留在 `extract.js`
   （只交出 `kbList` 与 `timeSlots`），周次解析、课程合并、开学日/总周数推算全部落在 `parse.js`，
   这样这段逻辑在 CI 里有真回归。
4. **周次解析收紧了**：① 单/双标记先在**原文**里找（上游也是，这份没退化），
   兜底了 `单双周1-16`（两个标记同时出现 = 每周都上，不兜底两边互相排除会把整段周次清空）；
   ② `隔周1-16` 这种**认不出相位**的写法按每周都上导入，但**计数进 warnings**（上游静默当每周）；
   ③ 超出 1-30 的周次计数进 warnings（上游静默丢）；④ 被空白隔开、自己成一个词的标记
   （`1-16周 双`）也算数（整段先抹掉空白再找标记），不许丢。
5. **节次解析收紧了**：上游取「数字里的第一个和最后一个」当首末节，遇到 `3-4节(1)` 会得到
   末节 1、末节比首节小，整行被默默丢掉；移植件取**最小值和最大值**，并支持同一平台
   `jcdm` 那种两位一节写法（`0304` = 第 3、4 节）。读不出节次的行**计数 + 带原文样本**进 warnings。
6. **括号组分两类**（2026-09-12 修正，缺陷 B12）：括号里装的是**纯数字 / 数字区间**（`(1)`、`(1-2)`）时
   整组连内容一起丢 —— 那是教学班序号，留着会让 `(1)1-16周` 被读成「第 1 周」（正则从左往右先撞上
   括号里的 1），还会让 `3-4节(1)` 的末节被压到 1；**其余括号只丢括号字符、内容留着**
   （上游 `wenhua_01.js` 就是逐个删 `周` / `单` / `双` / 左右括号的写法）。
   移植时把这一条写成了「一律连内容一起删」，于是周次或节次**整串被括号包住**时（`(1-16周)`、
   `(1-2节)`）真实数据被整段删掉：单行时整份抛「没有解析到任何课程」，夹在多行里时那门课
   **凭空消失**，跳过的理由还写成「缺课程名 / 星期 / 节次 / 周次」——四个字段其实都在。
   `1-16(周)`（「周」写在括号里）与被空白隔开的 `1-16周 双` 也归这一条管。
   用例：`serial-number`（序号侧）、`weeks-wrapped` / `sections-wrapped`（整串被包住的两侧）、
   `bracket-forms`（形态合集）。
7. **节次时间只按「课表用到的节」要求覆盖**：教务的节次时间必须覆盖课表**用到的**每一节
   （连堂 3-4 节要能查到 3 和 4）；缺任何一节就交空数组，让应用补它自己的默认表，并写进 warnings。
   真实作息和内置表**拼**出来的表比哪一份单独用都糟，且用户看不出来。反过来，教务给的表在
   课表**没用到的**位置上缺几行（例如晚上单独一张表）不算缺 —— 不值得因此把真实作息换成内置表。
   上游是「有就用、没有就算了」（取不到时 `catch` 掉、什么都不说）。
8. **空教师 / 空教室不再写占位符**：上游写 `'未知'` / `'未排地点'`，在课表里会被当成真名显示；
   移植件留空（`null`）。信息没有丢失——教务本来就没给。
9. **开学日与总周数**：上游给 `semesterStartDate: null`、总周数取「课表里最大的周次」。
   移植件按学年学期推算开学周的周一（手册 §4.3，`firstDayOfWeek=1` 的口径），总周数按 20 周估、
   被更晚的周次抬高时以课表为准 —— **推算值和抬高都写进 warnings**，用户在导入预览里就能看到。
10. **脏数据不再静默丢**：上游 `parseCourses` 里 `return` 掉的行不留痕迹；移植件分类计数
    （缺课名 / 缺星期 / 缺节次 / 缺周次）并写进 warnings。
11. **多了一个记录总数对账**：响应里若出现 `total` / `totalCount` / `count` 之类的数字字段，
    `extract.js` 带出来，`parse.js` 对不上就出声（见 §7 第 2 条）。

## 6. fixture 是合成的（必须说清楚）

十一份 fixture **都不是真机抓取**，是按上游脚本实际读取的字段形状编造的
（测试方案 §3 为移植件开的例外，与内置 `universal` 同一档位）。只保证
「同样的输入永远得到同样的输出」，**不保证真机解析正确**。每份 `*.extracted.json` 顶部的
`_note` 都注明了合成来源与它锁的是什么。

| 用例 | 锁的是 |
|---|---|
| `basic` | 基本表格：完全重复的行、单周 / 双周、分段周次、全角逗号、两位一节 `0304`、节次写法认不出来（`第一大节`）、4 类脏行、超出 1-30 的周次、教务节次时间表（含 `HH:mm:ss` 写法） |
| `weeks-parity` | 单双周写法专场：`1-16周(双)`、`1-15周(单)`、`双周1-16`、`单周1-15`、`1-8周(单),9-16周(双)`（单双区间混排）、全角括号 `1-16周（双）`、认不出单双的 `隔周1-16` / `单双周1-16` |
| `period-times-partial` | 节次时间**不完整**（教务只到第 8 节、课表用到第 9-10 节 + 两条坏时间）→ 整份回落内置表并说明 |
| `period-times-gap` | 作息表在课表**没用到的**位置上缺行（用到 1-2 与 9-10、教务只给了这四节）→ 保留真实作息，不误判成「不完整」 |
| `serial-number` | 括号里的教学班序号：`3-4节(1)`（上游会整行丢掉）、`(1)1-16周`（上游会读成第 1 周）。**防御性用例** |
| `weeks-wrapped` | 周次**整串被括号包住**（`(1-16周)`）：旧版连内容一起删 → 这一行没周次 → 单行时整份抛「没有解析到任何课程」。**B12 回归** |
| `sections-wrapped` | 节次**整串被括号包住**（`(1-2节)`）：同一处缺陷的节次一侧。**B12 回归** |
| `bracket-forms` | 括号形态合集：`1-16(周)`（周写在括号里）、`1-16周 双`（空白隔开的单双标记）、全角括号整串包住、`(2)1-8周` / `7-8节(2)`（序号在首 / 在尾仍整组丢掉）、`0304` 两位一节 |
| `total-weeks-raised` | 总周数被课表里更晚的周次抬高（排到第 22 周）→ 抬到 22 并写进 warnings |
| `reported-total` | 响应带了记录总数但条数对不上（报 42 条、只取到 3 条） |
| `no-year` | 学年读不出来：学期名退化成「第二学期」、第 1 周退回今天所在周的周一 + warnings |

**期望值是独立推出来的**（按规范手推每门课的 block、周次段、开学日与 warnings，不是把
`parse.js` 的输出贴回去），并且每份用例都做过**变异测试**（2026-09-12，Node 实跑；
把 `parse.js` 里对应逻辑改坏，看用例是否变红）：

| 变异 | 变红的用例 |
|---|---|
| M1 单双标记改成「把单 / 双字符抹掉之后再找」（= 第一批 `hbmu` 那个 bug 的等价形态） | `basic`、`weeks-parity` |
| M2 `stripGroups` 原样返回（不剥括号组） | `serial-number`、`bracket-forms` |
| M6 上游原样：不剥括号 + 节次取首尾 | `serial-number`、`bracket-forms` |
| M18 `stripGroups` 恢复成「整组连内容一起删」（= B12 缺陷本身） | `weeks-wrapped`、`sections-wrapped`、`bracket-forms` |
| M19 只回退周次侧（周次整串被包住时仍连内容一起删） | `weeks-wrapped`、`bracket-forms` |
| M20 只回退节次侧（节次整串被包住时仍连内容一起删） | `sections-wrapped`、`bracket-forms` |
| M21 只删括号字符、不剥纯数字括号组 | `serial-number`、`bracket-forms` |
| M22 抹空白那一步改成「只取第一段」（空白隔开的单 / 双标记丢掉） | 只有 `bracket-forms` |
| M3 节次时间不查覆盖（拿到就给） | 只有 `period-times-partial` |
| M9 节次时间不做时间合法性校验（坏时间直接交出去） | 只有 `period-times-partial` |
| M17 覆盖判据改成「从第 1 节连续排到最后一节」 | 只有 `period-times-gap` |
| M4 总周数不按课表抬高（固定 20 周） | 只有 `total-weeks-raised`（这一版还会让载荷校验失败：`endWeek=22 > totalWeeks=20`） |

## 7. 只能真机确认的事（没验证的都写在这里）

1. **菜单号 `N2151` 与三个接口路径**：全部来自上游脚本，没有真机 dump 佐证。
   同一平台各校的菜单号并不统一（zjut `N253508`、文华/QUT/SCUT `N2151`），
   教务升级后换掉的可能性真实存在，届时表现为「读不到学年学期」或「没返回课表 JSON」。
2. **分页**：正方这个课表接口**本身不分页**（上游也是一个 POST 取完；参数里
   `xsdm`/`kclbdm`/`kclxdm` 是筛选条件，不是页码），所以适配器**没有翻页可做**。
   它能做的是：响应里出现 `total` / `totalCount` / `count` 这类数字字段时带出来对账，
   对不上就写进 warnings（`reported-total` 用例）。**如果真机发现这个接口其实是分页的，
   这里会漏课**（只会漏在「响应里没有总数」的那种部署上）——真机要核对课程条数。
3. **`cxRjc` 的 body**：文华这份只传 `xnm` / `xqm`（上游如此），而同平台别的学校传的是完整课表
   body。真机若返回 400 / 空数组，适配器会**回落内置节次表并说明**，不会静默错。
4. **节次时间字段名**：`jcdm` / `jcmc` 谁放节次号、`qssj` / `jssj` 的写法（上游按
   `jcdm || jcmc` 取号），没有真机佐证；移植件两个字段都试、时间接受 `HH:mm` 与 `HH:mm:ss`，
   解析不了就整份回落内置表。
5. **`xsxx` 之外还有哪些字段**：课表响应里的其它字段（例如可能存在的 `sjkList` 作息表）
   一律没有使用 —— 节次时间只认 `cxRjc`。
6. **开学日与总周数都是推算的**：正方接口不给校历。真机上请核对一次文华的实际开学日
   与学期周数（推算依据与结果都写在载荷的 warnings 里）。
7. **学期代号**：正方用 `3 / 12 / 16` 表示第一 / 二 / 三学期，移植件的学期名与开学日推算先看
   教务自己的下拉框文本（`一/二/三`），文本认不出来才用这套代号。
8. **登录后的会话是否被三个接口接受**、课表页 HTML 里是否真有 `#xnm` / `#xqm` 两个选择框。
