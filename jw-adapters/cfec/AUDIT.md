# 安全审计 —— 重庆财经学院（正方新版 jwglxt 平台）

审计对象：`jw-adapters/cfec/` 下的 `extract.js` / `parse.js`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `CFEC/CFEC.js`（快照 commit `e62554a4034386b893bcd6813c7b2b64f8c730a3`，
2026-09-12，MIT，上游 maintainer `glxgo` —— 与本校 `adapters.yaml` 一致）。

审计方式：逐行读上游脚本 + 逐行读移植件，并跑移植手册 §5 给的静态扫描
（`grep -oE "https?://[A-Za-z0-9.-]+"` 与 `grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*="`）。

## 1. 请求域与请求清单（本节必须与代码一致，不许写得比代码窄）

上游脚本里**没有任何绝对 URL**：两条 `fetch` 的地址都由 `window.location.origin + '/jwglxt'` 拼出来。
移植件沿用同一做法，所以两个脚本请求的主机都只有**用户当前所在的那一个教务主机**
（`http(s)://jwmis.cfec.edu.cn`，即 `loginUrl` 的主机）。**`allowHosts` 留空**，不写通配。

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期字段（`#xnm` / `#xqm`）。**用户已经开在课表页时这一步跳过**，直接读页面上的这两个字段 | 报错并提示重新登录（没有学期名就没法查课表） |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表数据（JSON：`kbList` 排课行、`sjkList` 集中实践课、可能的记录总数） | 报错并提示重新登录 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxRjc.html` | 取**校区作息时间**（`xnm` / `xqm` / `xqh_id`） | 交 `null`，parse 回落到内置 13 节表并写进 `warnings` |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcxZccx_cxZcByXnxq.html` | 取**学期周次校历**（`xnm` / `xqm`），用来定开学日与总周数 | 交 `null`，parse 回落到推算并写进 `warnings` |

- 后两条接口**不来自上游 CFEC.js**（它只请求前两条，也不读 `xqh_id`）：这是移植时从同一批上游脚本里
  另外两所正方学校学来的 —— `SCNU/scnu.js`（作息 `/kbcx/xskbcx_cxRjc.html`、校历 `/kbcx/xskbcxZccx_cxZcByXnxq.html`）
  与 `GDOU/gdouyj.js`（同一个校历接口，用来算开学日）。两处独立来源都指向同一个路径族，所以判断是可用的；
  但它们**不是每个部署都装了菜单**，因此一律按 best-effort 处理（见上表第三列）。
- 校历接口按 `SCNU` 的写法**不带 `gnmkdm`**（`GDOU` 那份带 `N2154`）。若 CFEC 的部署要求菜单号，
  这个请求会失败 → 退化成推算，并且**这件事会出现在导入预览的 warnings 里**（不是静默降级）。
- 请求头只带 `Content-Type` / `X-Requested-With` / `Accept`，**不带任何自定义令牌**；
  Cookie 由 WebView 自己按同源规则带上，脚本不读也不写它。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。两个脚本都没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` 访问（静态扫描无命中）。唯一的「凭据」是浏览器自带会话 Cookie，脚本既不读它也不把它发到别处 |
| 2 | 不外发 | **过**。全部 `fetch` 都在 `extract.js` 里，地址全部由 `window.location.origin + '/jwglxt'` 拼成；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有任何第三方域 |
| 3 | 请求域可控 | **过**。请求主机只有一个：`loginUrl` 的主机 `jwmis.cfec.edu.cn`（`loginUrl` 给的是 http，`extract.js` 不在页面里跳转、只按当前 origin 拼地址，所以走 http 还是 https 由用户实际打开的那个地址决定）。`allowHosts` 留空，不写通配 |
| 4 | 只读课表 | **过**。四条请求全部落在 `/kbcx/*`（课表查询模块：课表页、课表接口、作息、周次校历），**不碰成绩（`/cjcx/*`）、学籍、个人信息、缴费**等任何其它接口。**注意**：课表接口的响应体里会夹带登录学生自己的信息（正方把它们放在 `xsxx` 之类的字段里）——`extract.js` 只把 `kbList`（排课行）、`sjkList`（实践课）与记录总数交出去，其它字段一律不带出，也不会进 fixture。作息与校历是**学校的公共数据**，不含个人信息 |
| 5 | 不埋点 | **过**。没有任何统计 / 上报 / 遥测，也没有 `img` 打点 |
| 6 | 不 eval 远程代码 | **过**。两个脚本都没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse` |
| 7 | 不写页面 | **过**。`extract.js` 只**读**当前页面里 `#xnm` / `#xqm` 两个字段的值（下拉框或隐藏 input，与上游一样读 `value`）；取课表页 HTML 时用的是 `fetch` + `DOMParser`（离线文档，不插入当前页面），既不写 DOM、不改表单、也不触发提交或点击。上游的 `showToast` / `showSingleSelection` / `notifyTaskCompletion` 这类桥调用**全部没有移植**（我们的移植件连提问桥都不用） |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码密钥、令牌或他人的学号。脚本里的常量只有正方的菜单号 `N2151` 与上下文路径 `/jwglxt`，都是公开的页面参数 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表（含作息与校历两个只读附加接口），
不碰凭据、不外发、不埋点、不写页面。

## 3. 与同平台已移植件 `zjut` 的对照片（批次二要求）

`CFEC/CFEC.js` 与 `ZJUT/zjut_01.js` 是**逐字近克隆**：整段 `diff` 只有三处 —— 菜单号
（`N2151` vs `N253508`）、作息表（13 节，时间不同）、`xqhId` 默认值（`'1'` vs `'01'`）。
**解析代码一行不差**，所以「同平台」在下面每一层的成立程度必须分开说：

| 层 | 能不能复用 | 本次结论 |
|---|---|---|
| 接口信封（POST 表单 + `{kbList:[...]}`） | **能** | 与 zjut 同一套。移植件沿用「响应必须是对象且 `kbList` 是数组」的判据；课表接口的**响应里可能带记录总数**这件事上游两个脚本都没利用，我们拿来对账 |
| 行字段名（`kcmc` / `xm` / `cdmc` / `cdbh` / `xqj` / `jcs` / `jc` / `zcd` / `xqh_id`） | **能** | 上游两份脚本读的是同一组字段；移植件的 fixture 也是按这组字段形状编的 |
| 取数路径（具体接口、参数、要不要先取学号） | **未必** | 菜单号就不通用（`N2151` ≠ `N253508`）。更要紧的是：CFEC 的部署**不一定会**装作息与校历这两个菜单，所以这两条只能 best-effort；反过来 zjut 的移植件根本没有这两条请求 |
| 周次 / 节次编码 | **未必** | 两份上游脚本共用同一段 `parseWeeks` / 节次解析（因为逐字克隆），但**同平台不同校的写法确实会变**（同批上游里 `GDOU` 的研究生版就是同接口不同参数）。移植件因此没有照抄 zjut 的 `parse.js`：周次、节次各自按 CFEC 自己的编码重新造了用例（见 §5） |
| 分页行为 | **未必（此接口没有分页）** | 扫过同平台 52 个用 `xskbcx_cxXsgrkb` 的上游脚本：**没有一个是翻页取数的**（唯一匹配到 `page` 字样的 `GDOU/gdouyj.js` 是「从当前页面读学年学期选项」，不是翻页）。正方这个接口一次性返回整学期，没有 `pageNo` 之类参数 —— 但我们仍然把响应里的记录总数带出来对账，见 §5 第 5 条 |

**所以「同平台」在这里只帮到「信封 + 字段名 + 大体走法」，取数路径与编码都单独验过。**

## 4. 移植时对上游做的删改（都不牵涉安全问题，但需要审阅者知道）

1. **ES6 → ES5**：`async/await` 改成 `then` 链，去掉模板串、箭头函数与块级声明关键字。
2. **不问用户**：上游在「不在课表页」时弹窗让用户选学年 / 学期（`showSingleSelection`）。
   移植件改成自动取教务当前学期 —— 用户在课表页时读页面上的 `#xnm` / `#xqm`（他自己切过的学期优先），
   否则取一次课表页 HTML 读这两个下拉框的默认选中项。载荷里用 `warnings` 说明「只导入了当前学期」。
   顺带一提：上游判断「是否在课表页」用的是 `pathname` **完全相等**，挂了门户/网关前缀就会误判；
   移植件不看路径，直接尝试读字段。
3. **切两段**：上游在同一个脚本里算周次、拼课程、存配置；移植件把取数留在 `extract.js`
   （只交出 `kbList` / `sjkList` 原始行与两个附加接口的原始响应），周次解析、课程合并、开学日与
   总周数、作息补齐全部落在 `parse.js`，这样这段逻辑在 CI 里有真回归。
4. **空教师 / 空教室不再写占位符**：上游写 `'未知'` / `'未排地点'`，在课表里会被当成真名显示；
   移植件留空（`null`）。信息没有丢失 —— 教务本来就没给。
5. **开学日、总周数、作息都改成「优先取教务」**：上游 `semesterStartDate: null`、作息写死一张表。
   移植件先要校历与作息（两条 best-effort 接口），**每一项都把自己的来源写进 `warnings`**，
   让用户在导入预览里就能看到哪个值是查来的、哪个是推算的。
6. **脏数据不再静默丢**：上游 `parseCourses` 里 `return` 掉的行不留痕迹；移植件分四类
   （缺课程名 / 缺星期 / 缺节次 / 缺周次）计数并写进 `warnings`，另外单列「周次超出 1-30」
   与「节次写成多段」两条。
7. **集中实践课（`sjkList`）不再静默丢**：上游完全没读这个字段。它们只有课名与起止周，
   没有星期节次、排不进周课表，但也不该消失 —— 移植件把门数与前几门课名写进 `warnings`。

## 5. 批次二 8 条坑逐条对照

1. **周次里的「单/双」写在「周」之后**（`1-16周(双)`）：**过**。`周` 先被整个删掉（留成空格的话
   紧跟其后的 `(双)` 会被切成另一段），单/双标记可以写在周次前、后、括号里，也可以自己成一段
   （`1-16周 双`）—— 最后一种会**并回最近的周次段**，并回不了就计数写进 `warnings`。
   `1-16周(单双周)` 两个标记都在 = 每周都上（不是丢标记，也不是空集）。
   fixture：`weeks-parity`（6 行覆盖 6 种写法）。
2. **括号里的纯数字序号不是周次**：**过**（这条对本平台是防御性的）。正方这两个值都是**独立字段**
   （`zcd` / `jcs`），课程名里的 `(3)` 不会被当数据读。解析器仍然先摘掉括号里的纯数字
   （`3-16周,(1)` 里的 `(1)` 不会被吃成「第 1 周」）。fixture：`dirty-rows` 最后一行。
3. **读不出「第N节」的行不许静默丢课**：**过**。节次认得出 `1-2` / `第9-10节` / `1,2` / `3-4节` /
   两位一拼的 `0102`；`jcs` 空时回落读 `jc`。**都读不出来**的行按「缺节次」计数写进 `warnings`
   （不在 1..20 节范围内也按读不出来处理，不猜）。fixture：`dirty-rows`（只给 `jc` 的一行 /
   两个字段都空的一行）。
4. **连堂标签下 `periodTimes` 要覆盖每一节**：**过**。作息表先按教务给的校验（第 1 节起连续、
   起止时间递增不重叠），课表用到的节次超出作息表时按空课内建节次表补齐，补了什么写进 `warnings`；
   内建表也没有的节次（第 13 节之后）单独说明「没有可用的作息时间」。
   fixture：`dirty-rows`（教务只回 4 节，课表里有第 5-6 节的课）。
5. **分页**：**此接口没有分页**（见 §3 表格最后一行）。仍然对账：`extract.js` 把响应里的
   记录总数（`total` / `totalResult` / `totalCount` / `count`）带出来，`parse.js` 发现它大于实际取到的
   行数时写进 `warnings`（「课表可能不完整，请重试或反馈」）。fixture：`dirty-rows`（说 9 条、回 7 条）。
6. **总周数被课表里更晚的周次抬高时要进 `warnings`**：**过**。校历写 18 周而课表里有第 20 周的课时，
   总周数抬到 20 并**单独**说明「否则第 19 周起的课放不下」；没有抬高时也说明总周数取自哪里
   （校历 / 课表最大周次 / 兜底 20）。fixture：`basic`（抬高）、`weeks-parity`（取自校历）、
   `no-extras`（取自课表最大周次）。
7. **`AUDIT.md` 的声明必须与代码一致**：本篇 §1 的表就是 `extract.js` 里全部四条请求，
   读取的字段（`#xnm` / `#xqm` / `kbList` / `sjkList` / 记录总数 / 作息行 / 校历行）逐项列全，
   没有写得比代码窄；`parse.js` 不发请求这一点也写明了。
8. **fixture 期望值独立推出 + 变异测试**：**过**。4 个用例的 `expected` 都是**先按手册的
   字段映射手算出来**（周次集合 → 极大段 → block、开学日回退到周一、总周数取谁），再拿去跟
   `parse.js` 的输出比；不一致就去查是哪边错，**没有把脚本输出贴进期望值**。
   变异测试（把 `parse.js` 里的逻辑故意改坏，看用例是否变红）跑了 21 处，全部命中。
   逐项：周次单/双标记忽略、单/双标记不成段、节次不按多段最大跨度、不认 `0102` 拼接、不回落读 `jc`、
   总周数不被更晚周次抬高、开学日不取校历、校历日期不回退周一、不认校历里的起止区间、不摘括号序号、
   集中实践课不写进 warnings、超限周次不计数、记录总数不对账、作息不回落到内置表、作息缺节次不补、
   单双周不当成每周都上、脏数据行不计数、教师不留空、教室不留空、重复排课行不去重、周次不切极大段
   —— **每一处都至少让一个用例变红**。
   唯一一处「改坏了也不红」的是「删 `周` 字时改成留成空格」：本实现把括号单独摘掉，所以这处改动在
   语义上是无害的（上游那个 bug 在我们这里构造不出来），这不是覆盖缺口。
   另有两处变异第一轮跑不出红，是**用例本身没盖住**、补了 fixture 才盖住：①「开学日不取校历」——
   原来各用例的校历第 1 周恰好都等于推算值，已把 `basic` 的校历整体挪后一周（2026-09-07）；
   ②「教师/教室写占位符」——原来没有一行教师为空，已让 `no-extras` 的毕业设计教师与教室都为空。
   Rhino 1.8.0（与 CI 同一个引擎、同样 `optimizationLevel = -1` / `VERSION_ES6`）实跑 4 个用例全 MATCH；
   `extract.js` 用桩页面 + 桩 `fetch` 跑过一遍（CI 里跑不到的那一段），四条请求顺序与 §1 一致，
   交出的键与 `parse.js` 的读法对得上，且载荷里**不含**课表响应夹带的学生信息（`xsxx`）。

## 6. 没能确定的事（交接给下一位）

- **fixture 是合成的**：按上游实际读取的字段形状编出来的形状正确的数据，**不是真实抓取**，
  课程 / 教师 / 教室 / 日期均为虚构。它只保证「同样的输入永远得到同样的输出」，
  **不保证真实页面上解析正确**（测试方案 §3）。拿到真实 dump 后请替换 fixture 并重跑门。
- **作息与校历两条接口在 CFEC 的部署上到底有没有**：没有账号，验不了。两条都是 best-effort：
  取不到就退化成推算 / 内置作息表，并且**会在导入预览里说明**。校历接口的 `gnmkdm` 也可能需要
  （`GDOU` 那份带 `N2154`），真机上如果发现开学日总是推算值，先试这个参数。
- **校历接口的字段名**：移植件同时认 `zs` / `zsmc` 与 `zrq` / `zcrq` / `rq` / `ksrq`
  （前两个来自 `SCNU` 与 `GDOU` 两份上游脚本），真实部署若用别的名字，会退化成推算（有 warning）。
- **作息表与校区**：`xqh_id` 取的是第一条排课行里的校区号（上游也是这么取的），多个校区时只用第一个
  —— 真机上一旦发现作息时间对不上，先查这里。
- **「0102」这种两位一拼的节次**：正方这个接口在已见过的 52 个上游脚本里都写 `1-2` 这种区间形态，
  拼接形态是**强智**那边的写法；移植件认它是为了不静默丢课，属于防御性容忍。
- 需要真实环境才能验的：登录后的会话是否被这四条接口接受、课表页 HTML 里是否真有 `#xnm` / `#xqm`
  两个选择框、菜单号 `N2151` 是否仍然有效、`loginUrl` 给的是 http（应用会显示「不安全连接」标记，
  学校如果也开了 https，维护者可以直接换成 https）。
