## 1. 脚本实际请求了哪些域

上游全脚本**只有一个绝对 URL、一处网络调用**：

```bash
$ grep -oE "https?://[A-Za-z0-9.-]+" HNVCC_01.js | sort -u
http://jwxt.hnvcc.edu.cn
$ grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|EventSource|\.src\s*=|eval\(|new Function|localStorage|document\.cookie|password" HNVCC_01.js
100:        const response = await fetch(url, {
```

第 97 行拼出来的就是那一个地址：

```
http://jwxt.hnvcc.edu.cn/jsxsd/framework/mainV_index_loadkb.htmlx?rq=all&xnxqid=<学年学期>&xswk=false
```

| 主机 | 上游怎么用 | 我们怎么用 |
|---|---|---|
| `jwxt.hnvcc.edu.cn` | GET 上面那条路径（写死在脚本里），`credentials: 'include'` | **不写死主机名**：请求**当前页面同源**的根相对路径 `/jsxsd/framework/mainV_index_loadkb.htmlx?rq=all&xnxqid=<学年学期>&xswk=false`，`credentials: 'same-origin'` |

**没有第二个域**：没有统计、没有 CDN 上的业务接口、没有 CAS 登录域、没有 WebVPN 网关（上游给的就是直连地址，
`adapters.yaml` 的 `import_url` 与脚本 fetch 的是同一台主机）。这一条比同批次的 `ccit`（WebVPN）干净得多。

**移植后的取数方式（最多 2 个请求，都是同源同路径）**：

1. **当前页面已经是课表页 → 一个请求都不发**（上游无论如何都发那个 GET）。上游的课表面板
   `mainV_index_loadkb.htmlx` 本来就是学生端首页用 AJAX 装进页面的，所以用户停在首页时
   课表已经在 DOM 里了 —— 这时候再请求一遍纯属多余。
2. 否则 GET 同源相对路径，query 与上游一字不差（`rq=all`、`xswk=false`），`xnxqid` 取页面上
   「学年学期」下拉框**选中的那一项**（读不到就留空，交给教务的当前学期）。
3. 第一次没拿到课表、而返回的页面自己给出了**另一个**学年学期时才再请求一次；否则明确报错。

脚本里**没有任何主机名字面量参与请求**：`grep -nE "https?://" extract.js` 只命中文件头注释与
`LOGIN_HINT` 这句给用户看的提示文案（`para parse.js` 里只命中上游仓库地址注释）。

## 2. manifest 取值

- **`loginUrl` = `http://jwxt.hnvcc.edu.cn/`** —— 上游 `adapters.yaml` 的 `import_url`，也是教务自己的主机。
  它是 **http 不是 https**（上游给的就是 http，校方没有给出 https 入口的公开证据），规范允许 http，
  应用会给它显示「不安全连接」标记。若该校日后启用 https，同一份脚本的**同源相对路径请求照样能用**，
  只需把 `loginUrl` 改成 https 入口。
- **不写 `scheduleUrlHint`**：能一键打开的那一页就是学生端首页；课表片段的完整地址带 `xnxqid` 参数，
  猜一个不带参数的地址打开的是半张页面。「一键刷新」会打开上次**成功提取**的那一页，比猜准。
- **`allowHosts` = `["jwxt.hnvcc.edu.cn"]`**，理由：
  1. 请求本来就是**当前页面同源相对路径**，`loginUrl` 那台主机已经在白名单里（`JwAdapterPackage.allowedHosts`
     会把 loginUrl 的主机拼进来）。这里显式再写一遍，是为了让安装前的白名单展示**看得见**这个域，
     并且让 `JwOriginRules` 也加上 `https://jwxt.hnvcc.edu.cn` 这条 origin 规则
     （`loginUrl` 是 http，只加 http 那条）—— OCR/提问桥按 origin 注入，学校哪天换 https 不至于拿不到桥。
  2. **零通配**：不写 `*.hnvcc.edu.cn`（那是学校所有主机，本适配器只需要教务这一台）。
     而且 `JwOriginRules.forAdapter` 会**跳过** `*.` 开头的项，写通配等于桥拿不到，两头不讨好。
  3. **不含任何第三方**，也不含校内的其它服务。
- **`minAppVersionCode` = 11**（移植手册 §5.1）：本件只多了 `warnings` 这类可加字段，
  老版本能装、能导入，只是不显示核对提示 —— 不是「行为诡异」，不该因此拒绝安装。

## 3. 有没有绕过白名单的写法 —— 逐类点名

| 写法 | 有没有 |
|---|---|
| 把目标地址塞进 URL 参数（`?url=` / 网关的 `/proxy?target=` 之类） | **没有**。请求只有一条固定路径 + 三个固定 query（`rq`/`xnxqid`/`xswk`），`xnxqid` 是页面上选中的学年学期编号（`^\d{4}-\d{4}-\d$` 才收，且经过 `encodeURIComponent`）。 |
| 非同源 iframe / `<img>` / `<script>` 拉取 | **没有**。脚本不创建任何元素（`createElement`/`appendChild`/`innerHTML =` 两段脚本都无命中）；取回的 HTML 只交给 `DOMParser`。 |
| 重定向把数据带走 | **没有**。不赋值 `location`、不导航、不开窗。唯一的重定向风险是强智把未登录请求 302 到登录页 —— 那仍是学校自己的域，我们拿到「没有课表的页面」→ 明确报错。 |
| `fetch(u,{mode:'no-cors'})` / 跨域带凭据 | **没有**。唯一一处 fetch 是同源相对路径 + `credentials: 'same-origin'`，没有 `mode` 覆盖、没有跨域目标。 |
| 把主机名拼出来（域名分片、base64 拼串） | **没有**。参与请求的主机名字面量一个都没有，只有路径与 query。 |
| WebSocket / EventSource / Service Worker 侧信道 | **没有**（两段脚本都无命中）。 |
| `sendBeacon` / 隐藏表单提交 | **没有**。 |
| 借 `xnxqid` 把请求引向别处 | **没有**。它只进 query，值有 `\d{4}-\d{4}-\d` 的格式约束。 |

  不写广告、不模仿空课自己的文案。

## 7. 移植时删掉/改了的上游行为

安全无关的行为也记一下（前 3 条是安全相关的）：

- **弹窗全删**：`showPrompt`（起始学年）、两个 `showSingleSelection`（第几学期 / 夏季还是冬季作息）、
  一串 `showToast`、`notifyTaskCompletion()`。空课的导入流程自己会确认；学年学期改成从课表页下拉框取
  **选中的那一项**（用户在页面上切学期，适配器就跟着他走 —— 手册 §3 第 1 步认可的两种做法之一）。
- **`window.validateYearInput` 删除**：那是上游为弹窗往页面写的全局函数（上游唯一的页面写操作）。
- **不写死主机名**：改成同源相对路径（上游写死了 `http://jwxt.hnvcc.edu.cn/...`）。
- **作息季节不再问用户**，改由 `parse.js` 按提取日期判：**5-9 月夏季作息，其余冬季作息**，
  并进 warnings 让用户核对。两张表是同一份硬编码表（只有第 5-8 节差 30 分钟）。
  说明：上游让用户**整个学期**选一个季节，而一个学期本来就横跨换季，所以「问用户」并不比按日期判更准；
  这条改动把选择权交还给用户（导入前能看到提醒、导入后能在「学期管理」里改）。
- **周次解析重写**（安全无关、正确性相关，也是本批次的重点）：上游 `/第(.*?)(周|\()/` 只认「第…周」或「第…(」，
  **「周」后面的括号整段丢掉** —— `第1-16周(双)` 的双周课会退化成「每周都上」而且不报警
  （测试方案 §3.1 记的第一批真实故障 `hbmu` 就是这个形态）。本件按分段各判、整串开头的「单周/双周」当全局修饰。
- **节次解析先摘钟点**：上游 `parseSections()` 只做 `/(\d+)\s*-\s*(\d+)/`，在带上下课时间的节次格上会先匹配到
  `08:20-09:05` 里的 `20-09`，算出 `start=20 > end=9`；而载荷里 `endPeriod < startPeriod` 会让**整次导入失败**。
- **教师/教室留空而不是占位词**：上游 `position` 空着就交空串，这里教室空串转 `null`，教师取不到也 `null`。
- **丢掉上游「找不到 `.tch-name` 或地点/周次 div 就静默丢掉这门课」的规则**：`extract.js` 照样把这块交出来，
  由 `parse.js` 计数并进 warnings（不许静默丢课）。
- **`extract.js` 交的是原始结构而不是解析结果**：上游在页面里就把周次/节次/课程拼好了；
  本件只交「网格列号 + 每门课的原始文字」，解释全在 `parse.js`，因为 CI（Rhino）只跑 `parse.js`。

## 9. 已知不确定 / 只有真机能验

1. **fixture 是合成的**：只保证「同样的输入永远得到同样的输出」，**不保证真实页面上的解析是对的**。
   拿到真实 dump 请替换 `fixtures/*.extracted.json` 并重跑门 —— 顺便核对四件事：
   ① `.item-box` 的直接子 `<p>` 是不是课名、`.tch-name` 里第一个 span 是不是「教师：X」；
   ② 带 `item1.png` 的 div 里是不是**两个** span、顺序是不是「地点、周次」；
   ③ 节次格的文字到底是 `第一大节 第1-2节` 还是别的写法（有没有阿拉伯数字是关键 ——
      上游的 `parseSections` 也只认阿拉伯数字，全是中文数字的格子它一样读不出）；
   ④ 强智的星期表头在 `<thead>` 还是 tbody 第一行（本适配器两种都认，但只有真机能确认）。
2. **`#timetable` 与 `.item-box` 的假设来自上游选择器**：本件把容器放宽到 `#timetable`/`#kbtable`/含 `.item-box` 的表，
   但没有真实页面确认「课表面板在首页里就已经加载好」这条 —— 若不成立，就走请求那条路（最多 2 次）。
3. **分页**：见 §6 第 6 条，那个片段按上游用法是一次性返回整学期；如果实际是按周分页，
   `extract.js` 会只拿到第一页而**不会报警**（这是本件唯一一处「取不全不会说」的地方，
   因为分页参数上游一个都没用 —— 真机上要确认一次）。
4. **作息时间是内置的**：教务页面不给上下课时间，两张表照上游抄；季节按提取日期判（5-9 月夏季）。
   顺延补出来的第 13 节起的时刻（每节 45 分钟、课间 10 分钟）是**编的**，已在 warnings 里说明。
5. **开学日是推算的**：教务不给开学日（上游整个适配器也没有这个字段），按「提取当天所在周的周一」推算
   （口径取自上游声明的 `firstDayOfWeek = 1`），warnings 第一条把日期原样写出来。推算值与真值在库里长得
   一模一样，所以这一条提示很重要。
6. **根相对路径的前提**：请求用 `/jsxsd/...`（站点根）。上游给的地址是直连教务主机、没有网关前缀，
   所以这是对的；哪天学校把它套到深信服式 `/http/<token>/` 的路径前缀后面，这条路径会落空
   （同批次的 `upc` 为此写了前缀拼接，本件没有 —— 没有证据表明该校有这层）。
7. **http 而非 https**：`loginUrl` 是上游给的 http 地址，应用会显示「不安全连接」标记。登录凭据的传输安全
   由学校自己的部署决定，不是适配器能改变的；适配器本身不接触凭据。
8. **没有账号做过真机抽验**（测试方案 §4 的第 ③ 层）：本适配器与上游一样，正确性靠用户反馈迭代。
