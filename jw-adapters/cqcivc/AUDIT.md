## 1. 两个域：本适配器实际请求的是哪一个（本件的重点）

上游 `adapters.yaml` 的 `import_url` 是 CAS 登录址
`http://dc.cqcivc.cn/cas/login?service=http://jwxt.cqcivc.edu.cn/sso/zllogin` —— **两个域**：
`dc.cqcivc.cn`（CAS 单点登录）与 `jwxt.cqcivc.edu.cn`（教务，正方 `jwglxt`）。判断依据：

| 依据 | 结论 |
|---|---|
| 上游脚本里 `fetch` 只有一个，URL 是写死的 `http://jwxt.cqcivc.edu.cn/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | **只有教务主机被真正请求** |
| `dc.cqcivc.cn` 在上游脚本里只出现在 `isLoginPage()` 的一个字符串常量里，跟 `window.location.href` 做 `===` 比较，从不发请求 | 登录域**零请求** |
| 登录全程由用户在 WebView 里手工完成（CAS 页 → 回跳 `jwxt.../sso/zllogin`），适配器不参与登录流程 | 适配器不需要碰登录域 |
| 取数走的是**教务主机的 JSON 接口**（`xskbcx_cxXsgrkb.html`），不是页面抓取 | 请求目标就是教务主机 |

**因此 `allowHosts` 只写 `["jwxt.cqcivc.edu.cn"]`**（精确主机名，不用 `*.` 通配）：
- 登录域 `dc.cqcivc.cn` **不进 `allowHosts`** —— 适配器不对它发任何请求，写进去等于白扩一次白名单；
  它出现在 `manifest.loginUrl` 里（用户从这里开始登录），由 `JwOriginRules` 单独取 origin 注入桥；
- 精确主机名还顺带保证桥注入得到（`JwOriginRules` 会跳过 `*.` 通配项，通配写法的适配器拿不到桥）。
  `manifest.scheduleUrlHint` 也给了教务主机的课表页，CAS 场景下这两个 origin 都会被放行。

## 2. 请求清单（本节必须与代码一致，不许写得比代码窄）

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `<教务 origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期字段（`#xnm` / `#xqm`）。**用户已经开在课表页时这一步跳过**，直接读页面上的这两个字段 | 报错并提示「先打开信息查询 - 学生课表查询」 |
| extract.js | POST | `<教务 origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表数据（JSON：`kbList` 排课行、`sjkList` 集中实践课、可能的记录总数）。请求体 `xnm=…&xqm=…&kzlx=ck&xsdm=&kclbdm=`，**与上游逐字一致** | 报错并提示重新登录 |

- `<教务 origin>` 的取法（`jwOrigin()`）：**页面本身就在 `jwxt.cqcivc.edu.cn` 时用页面自己的 origin**
  （http / https / 端口都跟着页面走）；否则用 `location.protocol + '//jwxt.cqcivc.edu.cn'`。
  两条分支都**不写死 http** —— 上游两个域给的地址都是 http，但学校若开了 https，写死 http 会在
  https 页面上被 WebView 当混合内容拦掉。**全文没有第三个主机**。
- 请求头只有 `Content-Type` / `X-Requested-With` / `Accept` 与 `credentials: include`，
  **不带任何自定义令牌**；Cookie 由 WebView 按同源规则带上，脚本不读也不写它。
- `parse.js` **不发任何请求**（CI 里用 Rhino 实跑，是纯函数）。
- 上游在这里有第三条路径（`isLoginPage()` 命中就 `showToast` 后 return），移植件**没有移植任何桥调用**，
  所以既没有 toast 也没有弹窗；「不在课表页」这件事改成由一次 GET 兜底，兜不住就明确报错（见 §7 第 2 条）。

## 3. 读了什么（逐项列全）

**页面**：只在**当前页面**上读 `#xnm` / `#xqm` 两个字段（学年 / 学期下拉框或隐藏 input）。
读的是 `value` 与选中项的文本（`textContent`）。不写 DOM、不改表单、不点按钮、不触发提交。

**课表响应**（`kbList` / `sjkList`）：

| 字段 | 用在哪 |
|---|---|
| `kcmc` | 课程名（空 → 该行计入「缺课程名」，进 warnings） |
| `xqj` | 星期（1–7） |
| `jcs` | 节次（`1-2` / `3-4节` / `第9,10节` / `0102` …），读不出来按「缺节次」计数 |
| `zcd` | 周次文本（`1-16周` / `1-16周(单)` / `(单)1-16周` / `1-16(单周)` / `1-3,5-9周` …；破折号旁可能带空格、连接号可能是全角/异体，见 §5 第 1 条） |
| `xm` | 教师（**空就留空**，不写「未知」） |
| `cdmc` | 教室（空就留空） |
| `sjkList[].kcmc` | 集中实践课的课名（只用来写一条 warnings，不排进周课表） |
| `total` / `totalResult` / `totalCount` / `count` | 记录总数，仅用于对账（见检查表第 6 条） |

**没有读**：`xsxx`（响应里夹带的登录学生信息）、`cdbh`、`jc`、`xqh_id`、成绩 / 学籍 / 缴费 / 个人信息类接口一个都没有。
`extract.js` 只把 `kbList`、`sjkList`、记录总数三者交出去，其它键一律不带出（桩测试里在响应中塞了一份
`xsxx: {xh:'20230101', xm:'张同学'}`，验证它既不出现在 extract 的产物里，也不出现在载荷里）。

## 4. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | **不碰凭据** | **过**。两个脚本里没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` 访问（静态扫描无命中）。唯一的「凭据」是浏览器自带会话 Cookie，脚本既不读它也不把它发到别处；登录全程由用户在 WebView 手工完成，上游那几个弹窗（含让用户手输学年的 `showPrompt`）**全部没有移植** |
| 2 | **不外发** | **过**。全部 `fetch` 都在 `extract.js` 里，地址由 §2 的两条规则拼成，落点只有教务主机一个；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有任何第三方域（上游脚本里只有本校那两个域，移植件里连这两个域都只在注释里出现） |
| 3 | **请求域可控** | **过**。`allowHosts` 只有 `jwxt.cqcivc.edu.cn` 一个精确主机名，无通配；登录域 `dc.cqcivc.cn` 不发请求所以不写（判断依据见 §1） |
| 4 | **只读课表** | **过**。两条请求都在 `/jwglxt/kbcx/*`（课表查询模块）。不碰 `/cjcx/*`（成绩）、学籍、个人信息、缴费。**注意**：课表接口的响应体里会夹带登录学生自己的信息（正方放在 `xsxx` 之类的字段里）——`extract.js` 只交出 `kbList` / `sjkList` / 记录总数，其它字段一律不带出，也不会进 fixture |
| 5 | **不埋点** | **过**。没有任何统计 / 上报 / 遥测，也没有 `img` 打点、没有 toast 上报；上游的 `showToast` / `notifyTaskCompletion` 这类桥调用一个都没移植 |
| 6 | **不 eval 远程代码** | **过**。两个脚本都没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse` |
| 7 | **不写页面** | **过**。`extract.js` 只**读**当前页面里 `#xnm` / `#xqm` 两个字段的值；取课表页 HTML 时用的是 `fetch` + `DOMParser`（离线文档，不插入当前页面），既不写 DOM、不改表单、也不触发点击或提交。上游那段「检测到登录页就终止」的逻辑没有移植（我们进不去、也没必要进去） |
| 8 | **不依赖用户输入之外的秘密** | **过**。没有硬编码密钥、令牌或他人的学号。脚本里的常量只有正方的菜单号 `N2151`、上下文路径 `/jwglxt` 与教务主机名 `jwxt.cqcivc.edu.cn`，都是公开信息 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表，不碰凭据、不外发、不埋点、不写页面。

## 5. 第三批专项检查表 10 条逐条

1. **周次编码四写法**：**过**。上游只认 `1-16周(单)` 一种（`includes('(单)')`），另外三种在它手里是**静默丢数据**：
   `1-16(单周)`（正则要求「周」紧跟第二个数字，两条正则都不匹配 → 一个周次都解析不出 → 整行被 `continue` 丢掉）、
   `1-3,5-9周`（逗号切开后 `1-3` 那段没有「周」字 → 前 3 周消失）、`(单)1-16周`（认得出，但标记写在「周」后时会被切走）。
   本件先把**破折号连同它两侧的空白**归一成 `-`、把全角/异体连接号也归一成 `-`，再摘括号里的序号、
   删量词「周」、最后按逗号**或空白**切段（空白在本域里同时是分段符），四种写法都得到正确周次。
   fixture：`weeks-forms`（17 行覆盖上述全部写法）。变异：**单/双标记整个不认 → 三个用例全红**；
   **括号里的内容一律当噪声摘掉（`1-16(单周)` 的标记丢）→ basic / weeks-forms 红**。

   **（补）破折号旁的空白不能当分段符**：教务偶尔把区间写成 `1 -16周` / `1- 16周`（破折号旁多一个空格）。
   原来那行切段正则把空白也当分隔符，于是先按空白切、区间被劈成孤立周次：
   `1 -16周(单)` 只留下 `1` 和 `(单)`，单周标记被并到孤立段上，退化成 **`w1-1 ALL`（应为 `w1-15 ODD`）**；
   `1- 16周` 劈成 `1` + `16` 两块，成了 **`w1-1 ALL` + `w16-16 ALL`（应为 `w1-16 ALL`）**。
   两处都是**静默错**：不丢课、不报警，周次就是错的。
   本件把「破折号 + 两侧空白」**整段归一成一个 `-`**（做法与上游同平台的 CFEC / wenhua_01 / zjut_01 /
   huel_01 一致），`1-16周` 标准形态不变。**注意：不能反过来全局删空白** —— 空白同时还是分段符，
   详见下一条。
   变异：**不归一连接号（删掉那行）→ weeks-forms 红（三条：`1 -16周(单)` / `1- 16周` / `3-16周,(1～2)`），
   basic / dirty 绿** —— 旧用例盖不住这条路径，正是补它的原因。

   **（补）空白本身仍是分段符**：有的学校把两段周次用空格隔开写（`1-3周 5-9周`，**没有逗号**），
   单/双标记自成一段也是靠它（`1-16周 双`）。所以**只归一「破折号旁的空白」，其余空白一律保留**，
   切段正则照旧把空白与逗号一起当分隔符。
   曾考虑过「先全文剥掉空白再按逗号切段」这个更省事的口径 —— **它是错的，已否决**：全文剥空白会把
   `1-3周 5-9周` 拼成 `1-35`，再按 1–30 截断成 `w1-30 ALL`，**静默吞掉一段**（同批 taru / zcmu / cqcivc
   实测过就是这个结果），单/双标记自成一段也会被并进周次段。
   fixture：`weeks-forms` 的 `1-3周 5-9周`（期望**两个块** `w1-3 ALL` + `w5-9 ALL`）。
   变异：**改成全文剥空白（`text(source).replace(/ /g,'')`）→ weeks-forms 红
   （该行 blocks 长度 1 vs 2、endWeek 30 vs 3、totalWeeks 被抬高到 30 vs 20），basic / dirty 绿**。

   **（补）全角/异体连接号归一**：`1～16周` / `1－16周` / `1−16周` / `1–16周` / `1—16周` / `1至16周` / `1到16周`
   统一成 ASCII `-`。周次本身不吃分隔符（取的是段里的数字），但**括号序号吃**：`3-16周,(1～2)` 里的
   `～` 不在「括号序号」那条正则的字符集里，不归一时 `(1～2)` 摘不掉，被当成「第 1-2 周」加进周次，
   周次错成 **1–16（应为 3–16）**。变异见上一条的「不归一连接号」。
2. **括号里的纯数字不是周次**：**过**。`(1)` / `(1-2)` 这类教学班序号先被整段摘掉，绝不当周次。
   fixture：`weeks-forms` 的 `3-16周,(1)` 与 `3-16周,(1～2)`（都期望 3–16 周，不是 1–16）。变异：
   **不摘括号序号 → weeks-forms 红**（周次变成 1–16，第 1、2 周凭空多出来）；
   **连接号不归一 → `(1～2)` 摘不掉，同样是 weeks-forms 红**（见第 1 条「（补）全角/异体连接号归一」）。
3. **无星期表头兜底 / 禁止 `row.length - 7` 猜列**：**不适用（本件不解析 HTML 表格）**。
   cqcivc 走的是正方 JSON 接口，星期直接来自 `xqj` 字段，`extract.js` 交出去的就是行对象，没有「列号」这个概念；
   全文没有按数组长度、也没有按 `colspan`/`rowspan` 推列的代码（`grep -nE "length\s*-\s*7|cellIndex|colSpan" jw-adapters/cqcivc/*.js` 无命中）。
   读不出星期（`xqj` 为空 / 不在 1–7）的行按「缺星期」计数进 `warnings`，**不猜**。
4. **时间合法性**：**过**。写进 `periodTimes` 的时间只有两个来源 —— 上游那张 11 节本校作息表，与空课内建节次表
   （`DefaultPeriodTimes`，12 节）。两张表全部匹配 `HH:mm` 且在 `00:00–23:59` 内、`start < end`
   （已用复刻 `JwPayloadCodec.validate` 的脚本逐条验过三个载荷）。**没有 clamp 分支**：
   作息表越界的情况在本件里不可能出现（常量表），真要出现也是脚本写错，应该被校验器当场拒掉而不是悄悄改时间。
5. **`warnings` 上限**：**过**。条数最多的一支是 9 条（`dirty` 用例实际 9 条），最长一条 84 字
   （`basic` 用例的脏行汇总），都在「≤20 条、每条 ≤200 字」之内（复刻校验器逐条量过三个用例）。
   没有一处把整段教务错误信息原样塞进 warnings。
6. **分页**：**该接口没有分页**。`xskbcx_cxXsgrkb.html` 一次性返回整学期排课，上游与同平台其它脚本都没有
   翻页参数；仍然对账：`extract.js` 把响应里的记录总数带出来，`parse.js` 发现「总数 > 实际取到的行数」就写进
   `warnings`（「课表可能不完整，请重试或反馈」）。fixture：`dirty`（说 9 条、回 7 条）。
   变异：**记录总数不对账 → dirty 红**。
7. **学期名**：**过**。用教务自己的学年学期（课表页下拉框的 `xnm` / `xnmText` / `xqm` / `xqmText`）拼成
   「2026-2027学年第一学期」；文本认不出来就看正方代号（`3` = 第一学期、`12` = 第二学期，与上游
   `getSemesterCode` 的映射一致）。**没有拿适配器名或学校名当学期名**。
8. **`teacher` 拿不到就留空**：**过**。`xm` 为空 → `null`（fixture `basic` 的「无机化学实验」教师与教室都是空的）。
   上游把 `xm` 当必填、缺一个就整行丢课，移植件没有沿用；上游式的「未知」占位符也没有移植。
   变异：**教师为空时写占位符「未知」→ basic 红**。
9. **`allowHosts`**：**过**。只有一个精确主机名 `jwxt.cqcivc.edu.cn`（非通配，桥才注得进去）；
   请求地址由 `window.location` 派生、不写死主机名之外的任何东西；`dc.cqcivc.cn` 不发请求所以不写。
   非标准端口的情况本件不涉及（登录址与教务址都是默认端口）。
10. **每件都要做变异测试**：**过**。23 处变异，**全部变红**，记录见 §8。

## 6. 与同平台已移植件（cfec / zjut / xawl / gsmc / qdhhc）的对照片

本批专项检查表说「同族 ≠ 同编码」，所以按层分开说：

| 层 | 能不能复用 | 本次结论 |
|---|---|---|
| 接口信封（POST 表单 + `{kbList:[...]}`） | **能** | 与 cfec 同一套，连菜单号都是 `N2151`。移植件沿用「响应必须是对象且 `kbList` 是数组」的判据 |
| 行字段名（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd`） | **能** | 上游两份脚本读的是同一组字段 |
| 取数路径（具体接口、要哪些参数） | **部分** | cqcivc 的请求体是 `xnm&xqm&kzlx=ck&xsdm=&kclbdm=`（**没有** `kclxdm`），与 cfec 那份不同 —— 本件按 cqcivc 自己的脚本写，没有跟 cfec |
| 周次 / 节次编码 | **未必** | 上游 cqcivc 的 `parseWeeks` 与 cfec 的**不是**同一段代码（cqcivc 只认 `1-16周(单)`，cfec 那份还能处理标记自成一段）。移植件按 cqcivc 自己的数据单独造了 fixture，没有照抄 cfec 的期望值 |
| 作息表 | **未必** | cqcivc 是 11 节（08:30 起，第 9 节 18:30），cfec 是 13 节（08:10 起）。本件带上 cqcivc 自己那张表 |
| 附加接口（作息 / 校历） | **不适用** | cfec 另外取了两条只读接口；**cqcivc 没有** —— 上游不取，我们也不取（少两条请求就少两块审计面）。代价是开学日只能推算，已写进 warnings |
| 分页行为 | **没有分页** | 同上，仅保留记录总数对账 |

## 7. 移植时对上游做的删改（都不牵涉安全问题，但需要审阅者知道）

1. **ES6 → ES5**：`async/await` 改成 `then` 链，去掉模板串、箭头函数与块级声明关键字；
   `parse.js` 在 Rhino 1.8.0（与 CI 同引擎、同 `optimizationLevel = -1` / `VERSION_ES6`）实跑三用例全 MATCH。
2. **不问用户学年 / 学期**：上游先弹公告、再让用户**手输起始学年**（提示词是「例如 2025-2026 应输入 2025」）、
   再弹窗选学期，然后把下标映射成学期码。移植件改成**自动取教务当前学期**：用户在课表页时读页面上的
   `#xnm` / `#xqm`（他自己切过的学期优先），否则取一次课表页 HTML 读同样两个下拉框；两条路都读不到就**明确报错**
   ——（手册 §3 第 1 步：能用页面解决的就别问用户）。**刻意不按日期猜学期**：猜错会整学期导错，
   报错让用户去教务页面里切一下更清楚。
3. **切两段**：上游在同一个脚本里算周次、拼课程、存配置、导作息；移植件把取数留在 `extract.js`
   （只交出 `kbList` / `sjkList` / 记录总数），周次解析、课程合并、开学日与总周数、节次补齐全部落在 `parse.js`，
   这样这段逻辑在 CI 里有真回归（`extract.js` 在 CI 里永远跑不到）。
4. **周次解析按本校自己的写法重写**：见 §5 第 1、2 条。除了上游认不出的三种写法（**静默丢课 / 丢周次**，
   不是「少导几周」那么轻 —— `1-16(单周)` 那种是整门课消失），还补了两处**静默错**（不丢课、不报警，周次就是错的）：
   把「破折号 + 两侧空白」整段归一成 `-`（`1 -16周(单)` / `1- 16周` 不再被劈成孤立周次），并把全角/异体
   连接号 `～－−–—~至到` 归一成 `-`（`3-16周,(1～2)` 的括号序号才摘得掉）。**其余空白保留**：它同时是
   分段符（`1-3周 5-9周` / `1-16周 双`），全文剥空白会把前一种拼成 `1-35`、静默吞掉一段。
5. **上游把六个字段全当必填**（`if (!kcmc || !xm || !cdmc || !xqj || !jcs || !zcd) continue;`）：
   教师或教室为空的课（网课、待排教室）会整门消失。移植件只要求课程名非空，教师 / 教室留空。
6. **脏数据不再静默丢**：四类（缺课程名 / 缺星期 / 缺节次 / 缺周次）分别计数进 `warnings`，
   另外单列「周次超出 1-30 周」与「节次写成多段」两条。
7. **开学日：上游完全没给**（`config` 里连 `semesterStartDate` 字段都没有，只有 `firstDayOfWeek: 1`）。
   移植件按学期序号推算（第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一），
   **并把「这是推算的」写进 warnings**（手册 §4.2 的硬要求：这个日期决定「现在第几周」）。
8. **总周数**：上游写死 `semesterTotalWeeks: 20`（顺带一提，手册 §4.5 记的那个坑 —— 上游 `saveCourseConfig`
   实际发出去的字段名是 `totalWeeks`，本件读的是**自己 extract 的产物**，不受影响）。
   移植件以 20 为默认，但课表里更晚的周次必须放得下：`endWeek` 超出 `totalWeeks` 会让**整个载荷**被校验拒掉
   （不是丢那几节课）。抬高时单独说明。变异：**总周数不被抬高 → dirty 红**。
9. **节次解析放宽**：上游 `jcs.split('-')` 取首尾，`"3-4节"` 第二个数是 `NaN` → `isNaN` 判断 → 整行静默丢掉。
   移植件认区间 / 多段（按最大跨度放入并出声）/ 两位一拼的 `0102`，读不出来才算缺节次。
   变异：**不认 `0102` → dirty 红**；**节次多段不取最大跨度 → 三个用例红**。
10. **集中实践课（`sjkList`）不再静默丢**：上游完全没读这个字段。它们只有课名与起止周，没有星期节次、
    排不进周课表，但也不该消失 —— 移植件把门数与前几门课名写进 `warnings`。变异：**不写进 warnings → basic 红**。
11. **作息表**：沿用上游那张 11 节本校作息表（原样搬过来，一个时间都没改），课表用到更晚的节次时
    按空课内建节次表补齐，补了什么写进 `warnings`；内建表也没有的节次单独说明「没有可用的作息时间」。

## 10. 没能确定的事（交接给下一位）

- **fixture 是合成的**：按上游实际读取的字段形状编出来的形状正确的数据，**不是真实抓取**，课程 / 教师 / 教室 /
  日期均为虚构。它只保证「同样的输入永远得到同样的输出」，**不保证真实页面上解析正确**（测试方案 §3）。
  拿到真实 dump 后请替换 fixture 并重跑门。
- **课表页路径 `xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` 是按同平台推的**：上游只请求数据接口
  `xskbcx_cxXsgrkb.html`，从没打开过课表页。这个路径与 cfec / zjut 同一模块、同一菜单号，可信度较高，
  但**没有账号验过**。影响面有限：用户开在课表页时走 DOM 分支（读 `#xnm` / `#xqm`），只有不在课表页时才依赖这条；
  真失败时见到的是一句明确的报错（不是静默导错）。
- **学年学期刻意不按日期猜**：读不到就报错。真机上如果发现「总是提示先打开课表查询页」，先查这里
  （也可能是学校改了课表页的字段名，`#xnm` / `#xqm` 是正方通用 id）。
- **作息表是否与学校现行一致**：上游写死的 11 节表，没有核对过；不一致时用户会在导入预览里看到这条说明。
- **开学日锚点（9 月 1 日 / 2 月 20 日）是通用经验值**，不是本校校历；推算值一律写进 warnings。
- **记录总数**：不确定该部署的课表响应里到底有没有 `total` 之类的字段（上游没读）。有就对账，没有就静默跳过
  —— 这条对账是**加一层**保险，不是取数依据。
- **登录域与教务域之间的跳转没有实测**：CAS 回跳、Cookie 是否被两类请求接受、`loginUrl` 给的是 http
  （应用会显示「不安全连接」标记；学校若也开了 https，维护者可以直接换成 https），都需要真机。
- **真机验证没做**（无账号）：`docs/jw-adapter-testing.md` 第 ③ 层整层未跑。
