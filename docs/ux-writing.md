# 界面文案规范

空课面向学生日常使用，文案要求**准确、克制、可预期**：用户读完应当清楚「这是什么、会发生什么、我该做什么」，
而不是先读到一段俏皮话。本文是全部界面文案的唯一依据，新增或修改文案前先对照本文。

## 一、语气

| 要求 | 应当 | 不应当 |
|---|---|---|
| 陈述事实，不做戏剧化表达 | 今天没有课程安排 | 今天没有课，好好休息 |
| 直述动作与结果，不夸大 | 添加到桌面 | 一键把课表钉到桌面，不用去列表里翻找 |
| 保持中性，不替用户表达情绪 | 本学期已结束 | 到期末再回来看看 |
| 使用完整书面语 | 该操作无法撤销 | 删了就没了哦 |
| 说明限制时给出原因与出路 | 未检测到摄像头权限，请在系统设置中授予后重试 | 需要相机权限才能扫码 |

- **不使用**感叹号。需要强调风险时靠措辞本身与警示样式，不靠标点。
- **不使用**语气词（哦、啦、呢、吧）、网络用语、表情符号。
- **不使用**「一键」「秒」「轻松」「超」等营销式修饰。功能就是功能，直接写它做什么。
- 第一人称一律避免；确需指代应用时写「空课」，不写「我们」。
- 第二人称「你」仅在说明用户自身操作时使用，且不宜密集出现；能用无主语句式就用无主语句式。

## 二、句式

- **标题与按钮**：名词或动宾短语，不加句号。长度尽量控制在 6 个汉字以内（按钮 4 个以内）。
- **说明文字**：完整句子，句末加句号。超过两句话的说明要考虑是否应当拆分或收进帮助入口。
- **空状态**：第一行说明当前状态，第二行给出下一步操作。两行都不带感情色彩。
- **错误提示**：`发生了什么 + 可采取的操作`。不要只写「失败」，也不要直接抛出原始异常文本。
  原始错误详情作为次要信息附在后面，供反馈问题时使用。
- **进行中**：统一使用「正在……」加中文省略号（`…`，U+2026），不使用三个句点。

## 三、标点与排版

- 中文全角标点；中英文之间、中文与数字之间加一个半角空格（`共 18 周`、`Material 取色`）。
- 引用界面上的其他位置用直角引号「」，如「导入 / 导出」。不使用双引号。
- 列举用顿号；分隔并列项用 ` · `（前后各一个空格）。
- 范围用波浪线 `~` 或「至」，不用连字符。
- 省略号用 `…`，不用 `...`。

## 四、术语表

同一概念在全应用只允许一种叫法。

| 统一用词 | 不再使用 |
|---|---|
| 课程表 / 课表 | 课程表格、课程安排 |
| 学期 | 学期设置、term |
| 节次 | 小节、第几节课 |
| 课程 | 科目 |
| 上课安排 | 课程块、block |
| 调课 | 串课、换课 |
| 跳过日期 | 跳过日、不上课的日子 |
| 教务系统导入 | 教务导入、抓课表 |
| 适配器 | 脚本、插件 |
| 桌面小组件 | 小部件、小工具、widget |
| 提醒 | 通知提醒、闹钟 |
| 同步 | 云同步、备份同步 |
| 导入 / 导出 | 备份与恢复 |

## 五、写给开发者

- 所有面向用户的文案都必须放在 `res/values/strings.xml` 中，不得硬编码在 Kotlin 里；
  非界面层（ViewModel、仓库）用 `UiText` 承载，理由与写法见 [`docs/i18n.md`](i18n.md)。
- 资源名格式为 `<范围>_<含义>`，范围取界面或功能名（`settings_`、`jw_`、`transfer_`、`common_`）。
- 带变量的文案用带位置的占位符（`%1$s`、`%2$d`），不要用字符串拼接 —— 拼接出的语序无法翻译。
- 数量相关的文案用 `<plurals>`，不要自行拼「个」「条」。
- 涉及品牌名与协议名保持原样：WebDAV、Material、WakeUp、拾光课程表、NextCloud、坚果云。
