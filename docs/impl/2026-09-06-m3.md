# M3 实现文档：小组件接数据 + 课前提醒 + 自动同步

日期：2026-09-06 · 模式：完整（Large）· 状态：待用户确认
基线：`b1bfebd` · 前置阅读：[PROJECT-CONTEXT.md](PROJECT-CONTEXT.md)

## 目标

用户装完 App 排好课后，**不解开应用也能知道今天上什么课、下节课是什么、课前收到提醒、课表在多设备间自动保持一致**。具体拆成三件事：

1. **T1 Glance 小组件接真实数据**：桌面小组件显示今日课程列表与「下一节课」，数据变化/翻天后自动刷新，点击进入应用
2. **T2 课前提醒**：每节课开课前 N 分钟发系统通知（N 可配，含关闭），数据变化后自动重排
3. **T3 WorkManager 自动同步**：按用户设定的周期（关闭/每 6 小时/每天）后台跑既有 `SyncManager.sync()`，网络受限时自动补跑

完成后发版 **v0.2.0**（versionCode 2，versionName "0.2.0"）。

## 现状盘点（实现前必读）

- `:widget` 模块已有 `TodayGlanceWidget`（写死的「空课 · 暂无课程」占位）+ `TodayWidgetReceiver` + `res/xml/today_widget_info.xml`（3 档 Responsive 尺寸）
- `:widget` 目前只依赖 `:core:model`；**没有** Hilt、没有 `:core:data`——这是 T1 要破的局
- `:sync` 的 `SyncManager.sync()` 已实现且互斥、可重入安全，但只能手动触发
- 通知相关：**什么都没有**——无 channel、无权限申请、无 Worker
- App 无任何用户偏好存储（WebDAV 凭证在 `:sync` 的 `SyncSettingsRepository`，独立 DataStore）

**关键机制决策与理由**：

- **小组件数据获取用 EntryPoint 而非把 receiver 标 @AndroidEntryPoint**：Glance 的 `provideGlance(context, id)` 里拿到的是普通 Context，EntryPointAccessors.fromApplication 是官方推荐路径，避免广播接收器生命周期的注入坑
- **小组件刷新采用「数据变化推 + WorkManager 拉」双轨**：Glance 没有可靠的常驻观察手段；App 活着时由 `WidgetAutoUpdater` 推（Room Flow 自动触发），App 进程死后靠每日定点的维护 Worker 兜底（跨天必须发生，否则「今日」永远陈旧）
- **提醒用 OneTimeWorkRequest + initialDelay 而非 AlarmManager 精确闹钟**：WorkManager 持久化、免权限、Doze 下误差 0~15 分钟，对课表场景足够；`SCHEDULE_EXACT_ALARM` 需要 API 31+ 特殊授权，M3 不碰
- **每条提醒一个 Worker 而非一个轮询 Worker**：省电、免轮询、单条失败不连坐；用 uniqueWork 名（含 blockId+startMillis）保证幂等，重排先 `cancelAllWorkByTag` 再全量入队

import com.nullclass.core.model.PlacedBlock

    val termName: String,
    /** 今天是本学期第几周；不在学期内为 null */

    val nextUp: TodayEntry? get() = ...

组装函数 `suspend fun buildTodaySnapshot(termRepo, courseRepo): TodaySnapshot`：
1. `termRepo.getCurrent()`；null → 返回空快照（widget 渲染引导文案「请先在应用中创建学期」）
2. `today = LocalDate.now()`；`week = term.weekOf(today.toEpochDay())`（null → 空快照带学期名）
3. `schedule = courseRepo.observeSchedule(term.id).first()`——一次性读，**不要 collect**
4. 遍历 schedule 中 `occursInWeek(week) && dayOfWeek == today.dayOfWeek.value` 的 block
5. `times = termRepo.getPeriodTimes(term.id)`；按 `startPeriod` 查 `startMinuteOfDay`，**查不到（节次配置残缺）的 block 跳过**（防御：用户改过节次表）
6. 排序（先 startMinute 再 startPeriod）、格式化时间（复用 `WeekGrid.kt` 的 `formatMinute`？**不行**，跨模块——把该函数移到 `core:model/ScheduleFormat.kt` 作为 `minuteLabel(minuteOfDay: Int): String`，周视图处同步替换引用）

class WidgetAutoUpdater @Inject constructor(
    private val termRepository: TermRepository,
    private val courseRepository: CourseRepository,
) {
    fun start(scope: CoroutineScope) {
        scope.launch {
            termRepository.observeCurrent()
                .flatMapLatest { term ->
                    if (term == null) flowOf(null)
                    else courseRepository.observeSchedule(term.id).map { term }

                    NextClassGlanceWidget().updateAll(context)

}

### 1.6 课表编辑后手动刷新（保险丝）

Widget AutoUpdater 依赖 App 进程活着。编辑保存路径都过 Repository，Flow 会推——**理论不需要手动刷**。但 Provider 安装、系统重启后首个 `APPWIDGET_UPDATE` 广播会调 `provideGlance`，此时 Hilt 组件已就绪（SingletonComponent 在 Application.onCreate 完成后可用；`provideGlance` 在广播 onReceive 后异步执行，时序安全）。

**风险点记录**：若 `provideGlance` 在极少数时序下拿到未初始化的 EntryPoint 会抛 `IllegalStateException`——Glance 会丢弃该次更新不崩溃；`updateAll` 下个周期自愈。不额外处理。

### 2.1 ReminderPlanner 纯函数（core:model，重点单测对象）

**`core/model/src/main/kotlin/com/nullclass/core/model/ReminderPlanner.kt`**：

```kotlin
data class UpcomingClass(
    val course: Course,
    val block: ScheduleBlock,
    /** 开课时刻（epoch millis，含时区换算——由调用方传入 zone） */
    val startAtMillis: Long,
    val endAtMillis: Long,
)

object ReminderPlanner {
    /**
     * 排算 [fromMillis, fromMillis + horizonDays] 内的全部上课时刻。
     * @param periodTimes 该学期节次表（含起止分钟）
     * @param zone 用于 epochDay→本地时间的换算
     */
    fun upcoming(
        term: Term,
        schedule: List<CourseWithBlocks>,
        periodTimes: List<PeriodTime>,
        fromMillis: Long,
        horizonDays: Int = 14,
        zone: ZoneId = ZoneId.systemDefault(),
    ): List<UpcomingClass>
}
```

**算法**（伪码，实现照此）：

```
fromDay = Instant.ofEpochMilli(fromMillis).atZone(zone).toLocalDate()
for (d in 0..horizonDays) {
    day = fromDay.plusDays(d)
    week = term.weekOf(day.toEpochDay()) ?: continue   // 学期外跳过
    for (cwb in schedule) for (block in cwb.blocks) {
        if (!block.occursInWeek(week)) continue
        if (block.dayOfWeek != day.dayOfWeek.value) continue
        startPeriod = periodTimes.find { it.periodIndex == block.startPeriod } ?: continue
        endPeriod   = periodTimes.find { it.periodIndex == block.endPeriod } ?: continue
        startAt = day.atStartOfDay(zone).toInstant().toEpochMilli() +
                  startPeriod.startMinuteOfDay * 60_000L
        endAt   = 同上 + endPeriod.endMinuteOfDay * 60_000L
        if (endAt <= fromMillis) continue              // 今天已结束的
        emit UpcomingClass(cwb.course, block, startAt, endAt)
    }
}
sortBy startAt
```

**必须覆盖的单测**（`core/model/src/test/.../ReminderPlannerTest.kt`）：
- 单双周过滤（ODD 周的课在 EVEN 周不出现）
- `fromMillis` 当天：已结束的课不出现、进行中/未开始的要出现
- 节次表缺 `startPeriod` 对应行 → 该 block 静默跳过不崩
- 学期边界（第 0 天/超 totalWeeks）
- 跨日排序、同时刻两门课都保留
- horizonDays 截断

### 2.3 提醒编排（app 层）

**`app/src/main/kotlin/com/nullclass/app/notification/ReminderScheduler.kt`**：

```kotlin
@Singleton
class ReminderScheduler @Inject constructor(
    private val context: Context,
    private val termRepository: TermRepository,
    private val courseRepository: CourseRepository,
    private val userPrefs: UserPreferencesRepository,
) {
    suspend fun reschedule() {
        val lead = userPrefs.reminderLeadMinutes.first()
        WorkManager.getInstance(context).cancelAllWorkByTag(TAG_CLASS_REMINDER)
        if (lead == 0) return
        val term = termRepository.getCurrent() ?: return
        val schedule = courseRepository.observeSchedule(term.id).first()
        val times = termRepository.getPeriodTimes(term.id)
        val now = System.currentTimeMillis()
        ReminderPlanner.upcoming(term, schedule, times, now, horizonDays = 14).forEach { up ->
            val remindAt = up.startAtMillis - lead * 60_000L
            if (remindAt <= now) return@forEach        // 已错过不补发
            WorkManager.getInstance(context).enqueueUniqueWork(
                uniqueWorkNameOfClassReminder(up),    // "class_reminder_{blockId}_{startAt}"
                ExistingWorkPolicy.REPLACE,
                OneTimeWorkRequestBuilder<ClassStartWorker>()
                    .setInitialDelay(Duration.ofMillis(remindAt - now))
                    .setInputData(workDataOf(
                        "courseName" to up.course.name,
                        "location" to (up.block.location ?: ""),
                        "startPeriod" to up.block.startPeriod,
                        "endPeriod" to up.block.endPeriod,
                        "startTimeLabel" to minuteLabel(...),
                    ))
                    .addTag(TAG_CLASS_REMINDER)
                    .build(),
            )
        }
    }
    companion object { const val TAG_CLASS_REMINDER = "class_reminder" }
}
```

**`ReminderController`**（Application 里常驻，驱动 reschedule 的时机）：

```kotlin
@Singleton
class ReminderController @Inject constructor(
    private val scheduler: ReminderScheduler,
    private val termRepository: TermRepository,
    private val courseRepository: CourseRepository,
    private val userPrefs: UserPreferencesRepository,
) {
    fun start(scope: CoroutineScope) = scope.launch {
        // 三个源任一变化 → 防抖 → 重排
        combine(
            termRepository.observeCurrent(),
            userPrefs.reminderLeadMinutes,
        ) { term, lead -> term to lead }
            .flatMapLatest { (term, _) ->
                if (term == null) flowOf(emptyList())
                else courseRepository.observeSchedule(term.id)
            }
            .debounce(800)
            .collect { scheduler.reschedule() }
    }
}
```

**每日维护 Worker**（与 1.5 的 WidgetDailyWorker 合并为一个 `DailyMaintenanceWorker`）：跨天后 horizon 窗口前移 + 14 天外的课还没入队；每 24h 跑一次 `reschedule()` + `updateAll`。`uniquePeriodicWork("daily_maintenance", KEEP)`。

### 3.2 SyncWorker

**`sync/src/main/kotlin/com/nullclass/sync/SyncWorker.kt`**：

```kotlin
@HiltWorker
class SyncWorker @AssistedInject constructor(
    @Assisted appContext: Context,
    @Assisted params: WorkerParameters,
    private val syncManager: SyncManager,
) : CoroutineWorker(appContext, params) {
    override suspend fun doWork(): Result = when (syncManager.sync()) {
        is SyncResult.Success -> Result.success()
        is SyncResult.NotConfigured -> Result.success()   // 配置被清了，正常结束
        is SyncResult.Error -> if (runAttemptCount < 3) Result.retry()
                               else Result.failure()
    }
}
```

注意 `SyncResult` 是 sealed interface 在 `:sync`，Worker 同模块 OK。

### 3.3 调度与设置

**`SyncSettingsRepository` 扩展**（复用现有 `syncDataStore`）：

```kotlin
enum class AutoSyncInterval { OFF, EVERY_6_HOURS, DAILY }   // 存字符串
val autoSyncInterval: Flow<AutoSyncInterval>                // 默认 OFF
suspend fun setAutoSyncInterval(v: AutoSyncInterval)
```

**调度函数**（`SyncScheduler.kt`，`@Singleton`）：

```kotlin
suspend fun apply(interval: AutoSyncInterval) {
    val wm = WorkManager.getInstance(context)
    if (interval == OFF) { wm.cancelUniqueWork(AUTO_SYNC); return }
    wm.enqueueUniquePeriodicWork(
        AUTO_SYNC,
        ExistingPeriodicWorkPolicy.UPDATE,    // 周期变化时替换
        PeriodicWorkRequestBuilder<SyncWorker>(interval.hours)
            .setConstraints(Constraints.Builder()
                .setRequiredNetworkType(NetworkType.CONNECTED).build())
            .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 10, TimeUnit.MINUTES)
            .build(),
    )
}
```

- 设置页「自动同步」区块：三档 SegmentedButton（关闭/每 6 小时/每天），改选即 `apply`
- **手动同步保留**现状不动
- 刚改配置立即跑一次一次性同步（enqueueUniqueWork 一次性 + 同 tag），体感更即时——可选加分项

### 3.4 Application 组装

`NullClassApplication`（见 1.5 骨架）补：`@Inject lateinit var syncScheduler`；onCreate 里 `appScope.launch { syncScheduler.apply(syncSettings.autoSyncInterval.first()) }`（持久化的周期在重启后重新入队，WorkManager 本身持久但 UPDATE 策略下重申无害）。
