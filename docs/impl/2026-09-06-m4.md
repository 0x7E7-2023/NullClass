## 目标

让课表数据**可携带、可分享、可从竞品迁移**，并发布第一个正式版：

1. **T0 共享格式统一重构**：`.nullclass` 文件格式与 WebDAV 同步快照统一为一套 DTO（M2 留下的两套格式债）

## T0：共享格式统一（先还债，其余任务都踩在上面）

### 现状

- `:importer` 有 `ScheduleDocument` v1（无审计字段，formatVersion=1，**没人用**）
- `:sync` 有 `SnapshotDto` v2（带审计字段，是 WebDAV 同步的活格式）

两套并存是 M2 有意为之的债。M4 的导入导出格式必须带审计字段（否则导入时 LWW 没法判新旧），所以：

### 方案

**把 `:sync` 的 `SnapshotModels.kt` 全家（SnapshotDto/TermDto/CourseDto/BlockDto/PeriodTimeDto/ManifestDto）搬到 `:importer`**，包名 `com.nullclass.importer`，文件名 `ScheduleDocument.kt`。改名映射：

| :sync 旧名 | :importer 新名 |
|---|---|
| `SnapshotDto` | `ScheduleDocument`（恢复这个名字，version=2） |
| 其余 XxxDto | 不改名 |

**依赖方向变更**：`:sync` 改为 `implementation(project(":importer"))`（`:importer` 是纯 Kotlin 模块，`sync` 依赖它没问题；反向不行）。`:sync` 内 `SyncEngine`、`SyncManager` 的 import 全部替换。

**编解码器**：`:importer` 的 `NullClassCodec` 重写——`encode(ScheduleDocument): String` / `decode(raw): ScheduleDocument`（Json 配置保持 `ignoreUnknownKeys = true`，**加 `encodeDefaults = true`**，保证新增默认字段的快照在旧版本可读、显式写出的字段跨版本行为一致）。删除 v1 遗留 DTO 字段差异说明，加文件头注释声明：**formatVersion=2 与 WebDAV snapshot 完全同构，`.nullclass` 文件 = snapshot.json 内容**。

**`.nullclass` MIME**：自定义 `application/x-nullclass`（Activity-alias / intent-filter 用它；SAF 导入时按扩展名兜底 `application/json` 也认）。

**单测**：ScheduleDocument round-trip（含墓碑/审计字段保真）、formatVersion 校验（v>2 拒绝并给出可读错误）、`encodeDefaults` 行为。

### 入口

课表页顶栏菜单加「导入 / 导出」→ 进入 `feature/settings` 里新增的 `TransferScreen`（或独立 `feature/transfer`？**决定：放 `feature/settings`，模块已有 DI 脚手架，避免新模块开销**）。页面三个区块：导出文件 / 二维码（T3 接入） / 从文件导入 / 从 WakeUp 导入。

### 导出实现

**`feature/settings/.../transfer/ExportUseCase.kt`**：

```kotlin
suspend fun exportDocument(): ScheduleDocument {
    // 复用 SyncManager.dump 的逻辑——但 dump 是 private。
    // 方案：把 dump/apply 从 SyncManager 抽成 @Singleton SnapshotCodec
    // (name: LocalSnapshotCodec)，导出和同步共用。见下。
```

**重构 `:sync`**：新增 `sync/src/main/.../SnapshotCodec.kt`：

```kotlin
@Singleton
class SnapshotCodec @Inject constructor(
    private val termDao: TermDao, courseDao: CourseDao, periodTimeDao: PeriodTimeDao,
    private val syncSettings: SyncSettingsRepository,
) {
    suspend fun dump(deviceId: String? = null): ScheduleDocument   // null → 取本机 deviceId
    suspend fun apply(doc: ScheduleDocument)                        // 现 SyncManager.apply 整体挪入（含 period_times deleteAll+全量 upsert）

```

`SyncManager` 改为委托 `SnapshotCodec`（行为不变，17 个既有测试继续绿）。

**UI 流程**：
1. 「导出课表」按钮 → 生成 JSON 字符串
2. 两个动作：

3. 导出成功 toast/snackbar「已导出 N 门课」

**注意**：导出包含**所有学期**（整个库 dump，含墓碑）还是仅当前学期？——**决定：全库导出**（和同步快照同构才可互换；单学期导出是子集需求，将来可加勾选）。

## T2：导入

### 文件进入的三个通道

1. 应用内按钮 → `ACTION_OPEN_DOCUMENT`（mime: `application/json` + `*/*` 兜底）
2. 系统「用其他应用打开」`.nullclass` → manifest intent-filter（`VIEW` + `application/x-nullclass` / `application/json` + `*.nullclass`）
3. 二维码（T3）解析后走同一条路

### 导入预览与执行

**`feature/settings/.../transfer/ImportViewModel.kt`**：

```kotlin
data class ImportPreview(
    val document: ScheduleDocument,
    val termSummary: List<TermSummary>,   // 每学期：名/周数/课程数/安排数
    val action: ImportAction,             // Merge（默认，唯一选项；替换导入不做——同步语义下「替换」=危险操作）
)

sealed interface ImportAction { data class Merge(val document: ScheduleDocument) : ImportAction }
```

**解析管线**（`ImportParser.kt`）：
1. 读全部字节 → `NullClassCodec.decode`；catch `SerializationException` → 错误「不是有效的空课文件」
2. 校验 `formatVersion > 2` → 「文件来自更新版本的应用，请升级空课」（**注意 formatVersion 混入 deviceId 生成的语义**：导入文档的 deviceId 不是本机——merge 相等时间戳时取本地，天然正确）
3. 产出 `ImportPreview`

**合并执行**：调 `SnapshotCodec.dump()` 得本地 → `SyncEngine.merge(local, imported, now)` → `SnapshotCodec.apply(merged)`。**复用即正确**：导入语义 = 一次单向同步，LWW/删除传播/period_times 整组取新全部免费得到。合并统计（新增 X 课程、更新 Y、删除 Z）复用 `countAdopted`（从 SyncManager 抽到 SnapshotCodec 或 Engine 伴生公开）。

**注意**：导入后不自动推 WebDAV（下次同步自然带上——manifest rev 不变，远端会被 merge 进来；**想清楚这点**：导入产生的变更 updatedAt=now，会自然赢过远端旧记录，符合预期）。

### intent-filter 接入

`MainActivity` 加 `onNewIntent` + launchMode `singleTask`；解析 `intent.data`（content:// 或 file:// URI）→ 读取流 → 存入一个 `PendingImportHolder`（简单 singleton/ViewModel sharedflow）→ 导航到 TransferScreen 预览。**trivial 实现**：不搞 deep link 组件，直接 intent 数据透传。

## T3：二维码

### 编码（分享方）

**依赖**：`com.google.zxing:core`（纯 Java，Apache-2.0，F-Droid 友好；版本查 Maven，3.5.x 系）。**不用** zxing-android-embedded 的生成侧（自己画 bitmap 就 30 行）。

```kotlin
// :importer  QrPayload.kt
object QrPayload {
    const val PREFIX = "NULLCLASS1:"     // 协议头；1=负载版本

    /** JSON → gzip → base64url，前缀 "NULLCLASS1:"。 */
    fun encode(doc: ScheduleDocument): String {
        val json = NullClassCodec.encode(doc)
        val gz = json.toByteArray(Charsets.UTF_8).let { gzip(it) }
        return PREFIX + Base64.getUrlEncoder().withoutPadding().encodeToString(gz)
    }

    fun decode(payload: String): ScheduleDocument { ... }   // 前缀/格式/解压三层校验
}
```

**大小预算**：QR Version 40 字节模式上限 2953B。典型 20 课 × 2 安排的全库快照 JSON ≈ 6-10KB → gzip 后 ≈ 1.5-3KB（UUID 和重复结构压缩率高）。**溢出策略**：`encode` 返回 null（或抛 `PayloadTooLarge`），UI 提示「课表过大无法生成二维码，请用文件分享」。**优化加分项**（做）：JSON 键缩写映射（uuid→u, startWeek→sw…）可再省 30%，但只有溢出时才值得——**首版不做**，记录 TODO。

**生成 UI**：TransferScreen「二维码分享」→ `QrShareScreen`（dialog 或页面）：`android.graphics.Bitmap`（zxing `QRCodeWriter().encode(text, QR_CODE, 1080, 1080)`，quiet zone 2 模块）→ Compose `Image(bitmap.asImageBitmap())` → 「保存到相册」（MediaStore API 29+；API 26-28 走 `WRITE_EXTERNAL_STORAGE`？——**不做保存**，M4 只做「截图分享」：`ACTION_SEND` 共享 cache PNG，省权限）。

### 解码（导入方）

**依赖**：`com.journeyapps:zxing-android-embedded`（封装相机 + CaptureActivity，Apache-2.0）。**注意**：新版（4.x）要求 minSdk 24+，我们 26 OK；它内置的 CaptureActivity 需在 manifest 注册 `com.journeyapps.barcodescanner.CaptureActivity`。

**流程**：TransferScreen「扫码导入」→ `rememberLauncherForActivityResult(ScanContract())` → 返回文本 → 前缀校验（不是 NULLCLASS 头则提示「不是空课二维码」）→ `QrPayload.decode` → 进入 T2 同一条 ImportPreview 管线。

**权限**：zxing-android-embedded 自动声明 CAMERA；`ScanOptions().setDesiredBarcodeFormats(QR_CODE)`。

**单测**：QrPayload round-trip（小课表）、超限抛错、错误前缀、损坏 gzip 数据。

## T4：WakeUp 课表导入

WakeUp 课表（WakeUp 课程表 App）导出文件 `.wakeup_schedule` 是 JSON。社区已知结构（以实际样本为准，**实现前先拿到真实样本核对**——让用户提供或用 WakeUp 导出）：

```json
{
  "default_term": {...},
  "term": {
    "startTime": "2026-09-07",       // 开学日
    "maxWeek": 20,
    "nodesPerDay": 12,                // 有的版本无此字段，取 courses 里最大 endNode
    ...
  },
  "courses": [
    {
      "courseName": "高等数学",
      "teacherName": "张三",
      "day": 1,                       // 1=周一
      "startNode": 3,
      "step": 2,                      // 连节数（大课天然支持！）
      "room": "A101",
      "startWeek": 1,
      "endWeek": 16,
      "type": 0,                       // 0=每周 1=单周 2=双周
      "color": "#FF5733",              // 十六进制，需映射到我们 12 色板
      "id": 3
    }, ...
  ]
}
```

**`importer/src/main/.../wakeup/WakeUpParser.kt`**：

```kotlin
object WakeUpParser {
    /** @throws IllegalArgumentException 带用户可读 message */
    fun parse(raw: String): WakeUpResult

    data class WakeUpResult(
        val termName: String,          // 无原始名时生成 "导入的课表"
        val firstDayEpochDay: Long,
        val totalWeeks: Int,
        val courses: List<CourseDto>,  // 映射为我们的 DTO，审计字段 createdAt=0/updatedAt=0
        val periodTimes: List<PeriodTimeDto>,  // WakeUp 不带时间表 → 用 DefaultPeriodTimes 生成
        val warnings: List<String>,     // day=7(周日)? 某些版本 0=周日——见下
    )
}
```

**映射规则**：
- `startNode + step` → `startPeriod = startNode, endPeriod = startNode + step - 1`
- `type`：0→ALL、1→ODD、2→EVEN
- `day`：WakeUp 大多数版本 1=周一…7=周日；**对 0 出现时按周日处理并记 warning**（版本差异防御）
- `color`：解析 hex → RGB → 找 `CoursePalette` 里最近色（欧氏距离）→ `colorIndex`
- 节次表：按 `max(nodesPerDay, maxEndNode)` 节 + DefaultPeriodTimes 模板扩展/截断
- 每条 course → 一条 CourseDto（一对一，WakeUp 没有「一门课多安排」概念，每行就是一块）+ 每行一条 BlockDto

**导入流程 UI**：TransferScreen「从 WakeUp 导入」→ OPEN_DOCUMENT 选 `.wakeup_schedule`（mime `*/*`，按扩展名过滤靠 `setType` + 手动检查文件名）→ 解析成功进 ImportPreview（复用 T2 界面，多显示 warnings 列表）→ 合并执行走 T2 同管线。**课表里已有学期时的行为**：WakeUp 自带 startTime/周数，作为新学期导入（new UUID），不与现有学期合并——**导入后提示「已导入为学期『导入的课表』，可在学期设置中改名」**。

**fixture**：`importer/src/test/resources/wakeup_sample1.json`（手工构造的最小样本 + 单周/双周/连堂/周日各覆盖）+ 解析单测 8+ 例。

## 风险与预案

| 风险 | 预案 |
|---|---|
| WakeUp 格式猜错（无真实样本核对） | Parser 防御式解析 + warnings；先向用户要一份真实导出文件 |
| 二维码超 2953B | 溢出即降级文件分享（已设计）；键缩写列 TODO |
| T0 大范围 import 改动引发回归 | 17 个 sync 单测是红线；SnapshotCodec 抽取保持行为等价，diff 审查重点看 |
| 扫码库体积/权限敏感 | zxing-android-embedded ~500KB 可接受；CAMERA 权限仅在扫码路径请求 |
| 模拟器无相机 | 雷电模拟器有虚拟摄像头（显示动画），扫码测不了真二维码——用「从剪贴板导入二维码内容」的 debug 途径验证解码链，真机最终验证 |
