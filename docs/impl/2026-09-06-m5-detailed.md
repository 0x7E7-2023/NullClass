## 目标

落地教务导入的**框架**：WebView 宿主 + 逐校适配器注册表 + 学校选择 UI + JS 注入提取 →
ScheduleDocument → **复用 M4 的 ImportPreview 合并管线**。

**本次交付范围**：框架 + 示例适配器（ExampleUniv，演示接口用法与可测性）。
**真实学校适配器不在本次范围**：概要文档明确「从用户自己的学校开始，实现前问用户哪个学校」；
用户明确指示完成全部任务前不询问，故首个真实适配器留待用户指认学校后另行开发。

## 架构（相对概要版的调整）

概要版设想 `:importer/jw/` 含 Activity；**实现调整**：`:importer` 保持纯 JVM——

```
:importer（纯 JVM）
  └─ jw/
      ├─ JwAdapter.kt          接口 + 公共工具
      ├─ JwAdapterRegistry.kt  注册表（内建适配器 + 提交学校入口元数据）
      └─ adapters/
          └─ ExampleUniv.kt    示例适配器（演示模式，可跑通全链路）

:feature:settings（Android）
  └─ jw/
      └─ JwImportActivity.kt   学校选择 + WebView 宿主 + 提取编排（结果回传 TransferScreen）
```

理由：WebView/Activity 是 UI 层的事，放 feature 模块；解析与提取脚本是纯逻辑，
放 :importer 可离线单测。这也避免把 :importer 转成 Android library（保持 F-Droid 友好的纯 Java 依赖面）。

## JwAdapter 接口

```kotlin
interface JwAdapter {
    val schoolName: String        // 展示名
    val schoolKey: String         // 稳定标识（issue 模板用）
    val loginUrl: String          // 登录页/课表页 URL
    /** 注入课表页的 JS（ES5）：从 DOM 提取数据，返回 JSON 字符串 */
    val extractScript: String
    /** 解析提取结果 → ScheduleDocument（纯函数，fixture 可测） */
    fun parseExtracted(extractedJson: String): ScheduleDocument
}
```

**凭证红线**（概要版锁定）：登录全程用户在 WebView 手工完成，应用不解析、不存储任何账号密码。
提取是纯前端 DOM 读取。README 与界面文案明示。

## 流程

JwImportActivity（选学校）→ WebView 打开 loginUrl → **用户手动登录并导航到课表页** →
用户点「提取课表」→ `evaluateJavascript(extractScript)` → JSON 字符串 →
`adapter.parseExtracted` → NullClassCodec.encode(ScheduleDocument) → setResult →
TransferScreen 解码 → **ImportPreview 管线（预览 + 合并，与文件/二维码导入同一条路）**。

## 示例适配器 ExampleUniv

- `extractScript`：通用表格抓取（`document.querySelectorAll('table')` → 行列文本 → JSON）
- `parseExtracted`：把行列 JSON 映射为 ScheduleDocument（演示映射：新学期 + 每行一门课）。
  实际学校适配器的 parse 逻辑按各校课表 DOM 定制。
- fixture 测试：`resources/jw/example_extracted.json` 驱动 parseExtracted 单测。

## 适配器贡献流程（M5 T5）

- README「求你的学校适配」章节 + `.github/ISSUE_TEMPLATE/jw-adapter-request.md`：
  要求附课表页「另存为 HTML」（脱敏）或 JS 提取结果 JSON。
- 贡献者 PR 加一个文件到 `adapters/` + 注册即可接入（框架价值大于初始覆盖）。
