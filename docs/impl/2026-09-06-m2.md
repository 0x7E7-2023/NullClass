# M2 实现文档：周视图课表 + 编辑 + 数据库 v2（同步就绪）+ WebDAV 同步

日期：2026-09-06 · 模式：完整（Large）· 状态：待用户确认 · 修订：v3（加大课/连堂与节次会话模型、点格加课、跨学期复制）

## 目标

用户从零开始可以：创建学期 → 添加带多时间安排的课程 → 周视图课表查看/翻周 → 编辑删除课程 → 配置 WebDAV 服务器并把课表**同步到云端/从云端合并**。全程落 Room，重启不丢，双端同步不冲突。

## 一、数据库设计（v2，本里程碑的根基）

> 设计原则：**同步就绪的冗余**。所有破坏性变更趁 v1 无用户一次到位。

### 1.1 主键与标识

- 所有业务表主键改为 **UUID 字符串**（客户端生成，`UUID.randomUUID()`），不用自增 Long。
  理由：多设备同步时自增 id 必然冲突；UUID 让记录在设备间天然可对齐。
- 领域模型 `id: String`，Entity 同。

### 1.2 全表统一审计三列（冗余之一）

| 列 | 类型 | 用途 |
|---|---|---|
| `createdAt` | Long (epoch millis) | 审计 |
| `updatedAt` | Long (epoch millis) | **同步冲突判定**：逐记录 LWW（新者胜） |
| `deletedAt` | Long? (epoch millis) | **软删除墓碑**：同步时让对方设备也删，本地查询一律过滤 `deletedAt IS NULL` |

### 1.3 表结构（schema version 2）

```
terms
  id TEXT PK          -- UUID
  name TEXT NOT NULL
  firstDayEpochDay INTEGER NOT NULL
  totalWeeks INTEGER NOT NULL
  isCurrent INTEGER NOT NULL DEFAULT 0
  createdAt / updatedAt / deletedAt
  索引: (deletedAt)

courses
  id TEXT PK
  termId TEXT NOT NULL FK→terms.id (CASCADE)
  name TEXT NOT NULL
  teacher TEXT?
  note TEXT?                       -- M2 就留字段，UI 后续用
  colorIndex INTEGER NOT NULL DEFAULT 0
  createdAt / updatedAt / deletedAt
  索引: (termId), (deletedAt), (termId, deletedAt)

schedule_blocks
  id TEXT PK
  courseId TEXT NOT NULL FK→courses.id (CASCADE)
  termId TEXT NOT NULL             -- ★ 冗余列：从 course 反规范化
                                   --   周视图直接按 (termId, dayOfWeek) 查块，免 join
  startWeek / endWeek / dayOfWeek / startPeriod / endWeek INTEGER
  weekType TEXT                    -- ALL | ODD | EVEN
  location TEXT?
  createdAt / updatedAt / deletedAt
  索引: (courseId), (termId, dayOfWeek, deletedAt), (deletedAt)

period_times
  termId + periodIndex 复合 PK
  startMinuteOfDay / endMinuteOfDay INTEGER
  session INTEGER NOT NULL DEFAULT 0   -- 0=上午 1=下午 2=晚上：驱动左列分组线
                                       --   （午休/晚休分隔）与大节标签
  updatedAt                            -- 随 term 快照整体同步，无需墓碑

### 1.3.1 大课/连堂模型

- **大节 = 两个连续小节**（第 1-2 节 = 大节 1，第 3-4 节 = 大节 2，…），由 periodIndex 派生，不落库
- 时间安排（block）的 `startPeriod..endPeriod` 天然支持任意连堂跨度：大课 = 跨 2 节的 block，渲染合并为单块，块内显示「课程名 + 首节开始~末节结束 + 教室」
- 编辑器提供**双模式选择器**：「按小节」直接选 3~4 节；「按大节」选大节 2 自动展开为 3~4 节（纯 UI 换算）
- 周视图左列节次栏：按 `session` 画上午/下午/晚上分组分隔线，设置里可切换「小节/大节」编号显示

sync_state (新表)
  key TEXT PK
  value TEXT                       -- deviceId、lastPushAt、lastPullAt、remoteSnapshotRev

settings (DataStore Preferences，不进 Room)
  webdav_url / webdav_username / webdav_password
  currentTermId 缓存（DB 的 isCurrent 为准，此为快速路由）
```

### 1.4 迁移与测试策略

- v1→v2 无存量用户，`fallbackToDestructiveMigration()` + 注释说明；**但流程不省**：`exportSchema` 继续入库，`schemas/` 目录随 git 走，从 v2 起每次改表必须写 Migration + `MigrationTestHelper` 单测（仓库 CI 把这个守起来）。
- 软删除的级联：删除 course → 自身置 deletedAt，其 blocks 同事务置 deletedAt（不用 Room CASCADE，因为要留墓碑）。

### 1.5 备份 = 同步格式（冗余之二，格式复用）

导入导出（M4 的 WakeUp 等除外）与 WebDAV 同步共用一套 JSON 快照：

```
ScheduleDocument v2
  formatVersion: 2
  deviceId: String                 -- 产生此快照的设备
  generatedAt: Long
  terms[] / courses[] / blocks[] / periodTimes[]
  每条记录携带: id, createdAt, updatedAt, deletedAt?
```

## 二、WebDAV 同步协议

### 2.1 传输层（新模块 `:sync`）

- 自实现轻量 WebDAV 客户端（OkHttp），不引第三方库：
  `PUT`（上传快照）、`GET`（下载）、`MKCOL`（建目录）、`PROPFIND` Depth:0（探测）
- Basic Auth，**强制要求 HTTPS**（明文密码；UI 上明示，http:// 仅允许 IP/局域网并二次确认）
- 依赖：`com.squareup.okhttp3:okhttp`（版本实现时查 metadata 锁最新稳定）

### 2.2 远端布局

```
{webdav_url}/nullclass/
  manifest.json      -- { formatVersion, deviceId, generatedAt, rev }
  snapshot.json      -- 最新合并快照（单文件，无历史版本）
```

单文件快照而非增量日志：课表数据量极小（<100KB），换实现极简；历史版本需求 M5+ 再议。

### 2.3 同步算法（Pull → Merge → Push，手动触发）

```
sync():
  1. local  = dump 本地库 → LocalSnapshot
  2. remote = GET manifest.json + snapshot.json（404 = 首次）
  3. merged = 逐记录合并（按 UUID 对齐）:
       - 只存在一侧 → 采用
       - 两边都有 → updatedAt 新者胜（LWW）
       - 一侧 deletedAt 非空 → 结果为墓碑（删除传播）
       - period_times 随所属 term 的 updatedAt 整体取新
  4. merged 写回本地库（触发 UI Flow 自动刷新）
  5. PUT snapshot.json + manifest.json（rev+1）
```

- 并发风险（两设备同时 push）：M2 接受最后写入覆盖整个远端文件；rev 检测冲突（pull 时 rev 比上次大 → 提示重拉）推 M3。
- 同步期间加应用级互斥锁，防手动同步重入。

### 2.4 UI（feature/settings，新模块）

设置页：
- WebDAV 服务器配置（URL / 用户名 / 密码，密码框）
- 「测试连接」：MKCOL 探测 + 读写试探，即时反馈
- 「立即同步」按钮 + 最近同步结果（时间 / 方向 / 合并记录数）
- 同步状态在课表顶栏出一个小图标（同步中/失败）

自动定时同步（WorkManager）留 M3，M2 只做手动。

## 三、任务拆分（串行，主代理实现）

依赖链：T1 是一切的地基，T2/T3 依赖 T1，T5 依赖 T1+T4。UI 与同步无共享文件，但为保串行审查节奏仍不并行。

### T1 数据库 v2 + 仓库层（最大任务）

- 四张表实体全部重写（UUID + 审计三列 + 冗余列/索引），schema v2
- period_times 增加 `session` 列；`DefaultPeriodTimes` 模板带会话分组：
  上午 4 节（8:00 起，45min+10min 休息）、下午 4 节（14:00 起）、晚上 4 节（18:30 起），共 12 节 6 大节
- `core/model` 增加大节换算纯函数（periodIndex ↔ sectionIndex，双向，带单测）
- `CourseWithBlocks` 关系查询（@Relation，过滤墓碑）
- `CourseRepository` 重写：`observeSchedule(termId)`、`upsertCourseWithBlocks`（事务 + 墓碑级联）、`deleteCourse`（软删）、`copyCoursesFromTerm(fromTermId, toTermId)`（跨学期复制：深拷贝课程+块，新 UUID，updatedAt=now）
- `TermRepository`：observeCurrent / upsert / setCurrent / 软删；首次建学期写默认节次模板
- `WeekLayout` 纯函数（week → 每天×节次的课块布局，跨节 span 合并；被 UI 与 widget 共用）
- 单测：WeekLayout、大节换算、墓碑过滤、默认模板、跨学期复制、merge 函数（见 T5 提前埋点）

### T2 周视图课表（feature/schedule）

- `ScheduleViewModel`：学期、自动周次、用户选定周、布局数据、同步状态透出
- 无学期 → 「创建学期」引导卡
- `WeekGrid`：HorizontalPager 按周翻页；表头（一~日+日期，今天高亮）；左列节次+时间+会话分组线（上午/下午/晚上分隔）；课块按列/行定位渲染，连堂大课合并为单块（名称 + 起止时间 + 教室）
- **点格加课**：点空白格子 → 跳课程编辑并预填星期/节次/默认连堂 2 节
- `CourseDetailSheet`：课程详情弹层（信息 + 全部安排 + 编辑/删除，删除带确认）
- 周次选择器弹层 + 「回到本周」

### T3 编辑界面（feature/edit）

- `CourseEditScreen`（新建/编辑复用，courseId 可选，支持预填星期/节次）：
  课名/教师/备注/12 色板 + 时间安排列表
- `BlockEditor`（单条时间安排）：
  - 周次范围（起-止周）+ 单双周（每周/单周/双周）
  - 星期选择（一~日）
  - **节次选择双模式**：按小节（第 3~4 节）/ 按大节（大节 2 ⇄ 3~4 节）即时互转
  - 教室；可增删多条安排
- `TermEditScreen`：学期名/开学日期/总周数 + 节次时间表编辑（每节起止时间 + 会话分组）+ 「从上学期复制课程」入口（无上学期则隐藏）
- 校验复用 model 的 require，错误就地提示

### T4 导航与设置页骨架（app + feature/settings）

- 路由：`course_edit?courseId`、`term_edit?termId`、`settings`
- 顶栏菜单 → 学期设置/设置页；FAB → 新建课程

### T5 :sync 模块 + WebDAV

- `WebDavClient`（OkHttp：PUT/GET/MKCOL/PROPFIND + Basic Auth）
- `SyncEngine`：dump / merge / apply，全纯函数可单测（merge 是重点测试对象）
- `SyncSettingsRepository`（DataStore：凭证 + deviceId + rev）
- 设置页接通：测试连接、立即同步、结果展示
- 单测：merge 各分支（新增/更新/删除传播/双方都改）、快照 round-trip、WebDavClient 用 MockWebServer 测
