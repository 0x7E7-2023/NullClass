# 多语言支持

当前仅提供简体中文。本文描述已经就位的机制，以及新增一种语言需要做什么 ——
目标是让「加一门语言」退化成纯粹的翻译工作，不必再改动任何业务代码。

## 一、文案存放在哪

| 位置 | 放什么 |
|---|---|
| `core/ui/src/main/res/values/strings.xml` | 全应用通用词条：按钮、通用状态、共享枚举名称 |
| `<module>/src/main/res/values/strings.xml` | 该模块界面自己的文案 |
| `app/src/main/res/values/strings.xml` | 应用名、通知渠道名、底部导航等应用级文案 |

各模块开启了非传递式 R 类（AGP 默认），引用本模块资源需显式 `import <模块 namespace>.R`；
引用通用词条则 `import com.nullclass.core.ui.R`，两者同时出现时给其中一个起别名。

**Kotlin 源码中不允许出现面向用户的中文字符串字面量**（只有全角标点的也算，如 `joinToString("、")`）。
例外仅三类，且都应写明原因：

1. 解析逻辑所依赖的中文关键词（教务页面里的「星期一」「节」等），它们是数据不是文案；
2. 写进数据库的数据（缺省学期名、补出的课名等）—— 会同步到其他设备，与界面语言无关；
3. 日志与异常消息中给开发者看的内容（含回填给适配器脚本的协议文本）。

登记位置分两档：

- **整文件**都不该有文案的，登记进 [`tools/check_hardcoded_text.py`](../tools/check_hardcoded_text.py)
  的 `ALLOWLIST`，逐条写明原因；
- 同一文件里既有界面文案、又有个别必须保留的中文（上面三类），在那行末尾写
  `// i18n-exempt: <原因>`，只豁免那一行。

这个脚本是本节的执法者：`python tools/check_hardcoded_text.py` 退出码 0 才算干净。

## 二、非界面层怎么办

ViewModel、仓库、引擎层没有 `Context`，也不该持有已经取好的文字 —— 语言切换后它们不会跟着变。
这些层返回 [`UiText`](../core/ui/src/main/kotlin/com/nullclass/core/ui/i18n/UiText.kt)：

```kotlin
// ViewModel 里
_state.update { it.copy(message = UiText.Res(R.string.transfer_import_done, count)) }

// 界面里
Text(state.message.resolve())
```

- `UiText.Res(id, vararg args)`：来自字符串资源，随语言切换而变，默认用它。
- `UiText.Dynamic(value)`：运行期才产生、无法预先翻译的内容 —— 课程名、服务器返回的错误详情、
  第三方适配器自带的说明文字。
- `UiText.Joined(parts, separator)`：几段连成一句。分隔符因语言而异，用 `:core:ui` 的词条：
  `common_list_separator`（列举名词，中文「、」）、`common_clause_separator`（并列分句，中文「；」）、
  `common_separator`（并列信息，「 · 」）。Compose 里直接 `joinToString(stringResource(...))` 即可。

### 异常转提示

`Throwable.toUiText(fallback)`（`ErrorText.kt`）会把**任何非空的异常消息原样展示**，
因为系统与服务器给的原文翻不了、但对反馈问题有用。所以自己抛给用户看的异常**不能**只写一句英文消息：

- 抛出点知道该怎么说的，继承 `UiTextException(text, debugMessage)`，`debugMessage` 只进日志；
- 或在 catch 处单独接住，给出专门的词条（如教务导入里的 `JwImageUnreadableException`）。

### 纯 Kotlin 模块

`:core:model` 与 `:importer` 是纯 Kotlin 模块，取不到 Android 资源，也不能依赖 `:core:ui`。
它们的处理方式是**只产出稳定的标识，不产出文字**：

- 枚举不带 `label` 属性，显示名称在 `:core:ui` 的 `EnumLabels.kt` 中映射
  （`ThemeMode.labelRes`、`WidgetFontSize.labelRes`、`AppLanguage.labelRes`）；
  新增枚举项时 `when` 会缺分支，编译器会报错，不会漏翻。
- 解析与导入失败返回带错误码的结果类型，错误码到文案的映射同样放在界面侧。
  已有的三套：
  - `:core:model` 的 `DataError` → `:core:ui` 的 `DataError.messageRes`（数据层拒绝写入）；
  - `:sync` 的 `SyncError` / `SyncFailure` → `:feature:settings` 的 `SyncErrorText.kt`（WebDAV 同步）；
  - `:importer` 的 `ScheduleFileError` / `ImportNotice` →
    `:feature:settings` 的 `ImportIssueText.kt`（用户选的文件 / 扫的码不合法，解析时
    「跳过了什么、替成了什么」的提示，以及教务图片 OCR / 页面文字还原表格时要用户核对的
    `OCR_*` 提示）。`:importer` 同时被 `:sync` 用到，文件级错误词条放在
    `:core:ui`（`error_import_*`），导入预览专属的提示词条放在 `:feature:settings`。

带参数的异常不写文案，把参数带上：`NullClassCodec.FutureVersionException(fileVersion, supportedVersion)`
只带两个版本号，词条里的 `v%1$d 高于 v%2$d` 由界面层代入。

## 三、语言如何生效

实现见 [`AppLocale`](../core/data/src/main/kotlin/com/nullclass/core/data/locale/AppLocale.kt)。
按系统版本分两条路径，互不叠加：

- **Android 13 及以上**：系统自带「应用语言」设置页，状态由 `LocaleManager` 保管。
  应用只负责写入 `LocaleManager`，资源切换与界面重建交给系统；应用**不得**再自行包装 Context，
  否则用户从系统设置页改的语言会被应用的旧值顶回去。
  可选语言清单来自 `app/src/main/res/xml/locales_config.xml`。
- **Android 12 及以下**：应用在 `Application.attachBaseContext` 与 `MainActivity.attachBaseContext`
  中包装 Context，并在偏好变更时重建 Activity。

语言选择持久化在 DataStore（`UserPreferencesRepository.appLanguage`）。
因为 `attachBaseContext` 早于依赖注入执行且不能挂起，另有一份 SharedPreferences 镜像供同步读取，
以 DataStore 为准。

通知、桌面小组件等在 Activity 之外取文案的路径走 Application Context，上面的包装已经覆盖。

## 四、新增一种语言

1. 在 `AppLanguage` 中确认或新增对应枚举项（填入 BCP-47 标记）。
2. 为下列每个模块补一份 `res/values-<qualifier>/strings.xml`：
   `core/ui`、`app`、`widget`、`feature/schedule`、`feature/exam`、`feature/edit`、`feature/settings`。
3. 翻译完成后：
   - 把该枚举项加入 `AppLanguage.TRANSLATED`；
   - 在 `app/src/main/res/xml/locales_config.xml` 中登记同一个标记。
   两处必须一致。
4. 当可选语言多于一种时，「应用设置」中的语言入口会自动出现
   （判据是 `AppLanguage.isSelectionMeaningful`）—— 只有一种译文时，
   「跟随系统」与该语言效果完全相同，展示选择项没有意义，因此默认隐藏。

## 五、翻译时的注意事项

- 占位符必须带位置（`%1$s`、`%2$d`）并保留原义，语序可自由调整。
- 数量相关用 `<plurals>`；中文只有 `other` 一档，英文等语言需要补 `one`。
- 词条中的 `\n`、`&#160;`（不换行空格）等转义原样保留。
- 品牌名与协议名不译：WebDAV、Material、WakeUp、NextCloud、坚果云、拾光课程表。
- 语言名称始终以该语言自身书写（简体中文、English），不随界面语言翻译 ——
  用户需要在看不懂当前语言时也能找到自己的语言。
