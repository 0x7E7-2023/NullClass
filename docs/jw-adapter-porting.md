# 教务适配器移植手册

把**上游社区已有**的教务适配器搬到空课的适配器规范里来。

上游指 [shiguang_warehouse](https://github.com/XingHeYuZhuan/shiguang_warehouse)（MIT，
拾光课程表社区的适配仓库，207 所学校 / 226 个适配器）。本手册只管「怎么搬」，搬来的东西
长什么样、有哪些字段、CI 怎么跑，看 [适配器规范](jw-adapter-spec.md)。

> **先读这一句**：移植的难点不在写代码，在**判断哪些值得搬**和**审它安不安全**。
> 代码本身大部分是机械转换，一个人一小时能搬一个；搬错一个的成本由用户承担。

---

## 1. 搬什么、不搬什么

上游 226 个适配器按教务平台分：

| 平台 | 数量 | 建议 |
|---|---|---|
| 正方 新版 `jwglxt` | 42 | **优先**。一个平台吃掉五分之一，页面结构收敛 |
| 强智（`jsxsd` 路径，30 + 其它写法 3） | 33 | **优先**。原来误标成「正方老版」——**实测反例见下** |
| 金智 `jwapp` | 18 | 优先。**我们已经有两个**（`dlutci` / 平台经验在 `ustc` 之外的这一支） |
| `for-std` 平台 | 7 | 优先。**我们已有 `ustc`，同平台** |
| 青果 / URP / 超星 / Struts2 `getDataList.action` | 7 / 5 / 5 / 3 | 单个搬，注意「课表是图片」的青果要先看是不是该走 OCR |
| **长尾自研** | **102** | **默认不搬**。一个学校一套接口，收益/成本比最差；这批交给通用适配器 + OCR |

> **平台标签别信。** 这张表是拿正则扫脚本正文扫出来的，错得比想象中多。两个实测反例：
> `HYNU` 走了 `jsxsd` 路径但其实**是湖南强智**（直接打开该校登录页可见「强智新一代综合教务」），
> 所以那 30 个 `jsxsd` 大概率整体是强智批次、不是正方；`MASU` 上游自称「青果/URP 金刚教务」，
> 实际是**强智 eams**（`/eams/login.action`），而且课表是真 `<table>`、不是青果那种 canvas。
> **聚类要按「脚本实际请求的接口路径 + 选择器结构」，不是按平台名，更不是按上游注释。**

**按平台搬，不按学校搬。** 搬完同平台的第一个，后面的边际成本会掉一大截（选择器、分页、
周次编码几乎一样）。真正的清单是 **≈8 个平台批次**，不是 226 个。

**不要搬的**：
- 上游的通用工具（`GLOBAL_TOOLS/`：组件测试、WakeUp 口令导入、星链分享码导入）——
  这些要么是我们已有的原生功能，要么是上游的交互演示，不是课表适配器。
- 上游的**通用**适配器（`zhengfang_jiaowu` / `chaoxing_jiaowu`）也**不要照搬**：
  它们和我们内置的 `universal` 是同一个定位（地址由用户现场输入），
  我们那条链路已经把识别交给表格结构层 + OCR，比在脚本里写死选择器更耐用。

**不移植的判据**（命中任一就跳过，别硬搬）：
- 脚本依赖页面上我们拿不到的东西（浏览器插件、原生 App 的私有接口、需要装证书）；
- 脚本请求的域名里有**非该校**的第三方（统计、CDN 上的业务接口、加速器）；
- 脚本读取课表页之外的内容（成绩、学籍、个人信息）—— 直接判不合格，见 §5。

## 2. 两份契约的差别

| | 上游（拾光） | 我们（空课） |
|---|---|---|
| 脚本形态 | 顶层语句，末尾自执行 `runImportFlow()` | **一个表达式**，或自己调 `__ncDone` |
| 结果交付 | **推**：`shiguangBridge*` 回调 + `notifyTaskCompletion()` | **拉**：`return` / `__ncDone(json)` |
| 输出粒度 | courses / timeSlots / config **三段独立** | 一个课表载荷（`terms[]`，学期内嵌课程与节次表） |
| 周次 | 显式数组 `weeks: [1,2,3…]` | `(startWeek, endWeek, weekType ∈ ALL/ODD/EVEN)` |
| 学期 | 无学期概念（一张课表 = 一个学期），**无学期名** | `terms[].name` 必填 |
| 开学日 | `config.semesterStartDate`，**可选**（166 个带 config 的里只有 102 个给） |
| 每周起始日 | `config.firstDayOfWeek`（1=周一…7=周日） | 隐含在 `firstDay` 的星期几（同一个值的两种说法） |
| 交互 | `showAlert` / `showPrompt` / `showSingleSelection` | `__ncSelect` / `__ncConfirm` / `__ncPrompt`（**移植时通常不需要**） |
| 网络 | 无白名单，脚本想请求谁就请求谁 | `allowHosts` 白名单 + 提取期闸门 |
| 语言级别 | ES6+（100% `async/await`、96% `const`、90% 箭头、89% 模板串） | **ES5**（CI 硬检查；Rhino 也不支持 async/await） |

**三处最容易搞错的语义**，都在下面 §4 有细则：周次数组怎么切、开学日怎么定、每周起始日怎么合。

## 3. 六步法

### 第 0 步：认平台，挑同批次里的第一个

```bash
grep -l "jwglxt" /tmp/sgw/resources/*/*.js      # 正方新版
grep -l "jsxsd"  /tmp/sgw/resources/*/*.js      # 正方老版
grep -l "/jwapp/sys/" /tmp/sgw/resources/*/*.js # 金智
grep -l "for-std" /tmp/sgw/resources/*/*.js     # for-std（我们 ustc 同平台）
```

先搬一个，把这一批的「取数方式、周次编码、学期接口」摸清，写进批次笔记，后面的照抄。

### 第 1 步：切两段 —— 这一步决定后面能不能验

**别把逻辑全塞进 `extract.js`。** 我们的 CI **只执行 `parse.js`**（`extract.js` 需要浏览器，
永远跑不到 CI 里）。所以按我们本来设计的两段切：

- **`extract.js`**：只做页面 / 接口访问，把**教务的原始数据原样**交出去
  （行对象、HTML、JSON 都行，别在脚本里算周次、别拼课程）。
- **`parse.js`**：纯转换，原始数据 → 课表载荷。**移植过来的核心逻辑应该落在这里。**

代价是多一个 fixture 对，收益是这段逻辑第一次有了真回归。

**交互怎么办**：我们的脚本没有「问用户」这一步（能用，但别依赖）。上游 `showSingleSelection`
选学期（74.7% 的适配器用它）在移植时改成 —— **自动取当前学期**
（上游脚本本来就会查「当前学期」接口，只是拿它当默认项）；需要历史学期时，
我们的载荷 `terms` 是数组，**一次返回多个学期**即可。两条路都比弹窗好，不是妥协。

### 第 2 步：降到 ES5

> **顺手检查字面 NUL 字节**：复合键常用「名字 + 空字符 + 教师」这种分隔法，但有些编辑工具
> 会把那个转义序列直接落成**真的 NUL 字节**（0x00），于是 `grep`/`diff` 把这个文件
> 当二进制看（我们自己的 `dlutci/parse.js` 中过招，本批次又有两个适配器踩到）。
> 源码里一律写成**转义序列**（反斜杠加 `u0000` 那种六字符形态），运行时值不变。写完自检：
> `python -c "print(open('parse.js','rb').read().count(bytes([0])))"` 必须是 0。

上游脚本 100% 用 `async/await`，96% `const`，90% 箭头函数，89% 模板串；
我们 CI 硬禁 `=>`、反引号、`let`、`const`，而 Rhino **根本不支持 async/await**。

```bash
npx @babel/cli --presets @babel/preset-env --targets "chrome>50" \
    upstream.js -o /tmp/es5.js
```

转译之后再手改桥调用（那部分不能自动）。**`Promise` 是允许的**（规范 §3.1），
所以 `async/await` 转成 `.then()` 链就够了，不用改成回调。

### 第 3 步：字段映射

见 §4。这一节的每一行都是踩过的。

### 第 4 步：安全审计（**内置适配器的门槛**）

见 §5。这是移植能不能进内置的唯一硬门槛 —— **正确性可以靠用户反馈修，安全性不行**。

### 第 5 步：写 manifest、fixture，跑门

```bash
./gradlew :importer:test --tests "*JwLibraryHarnessTest*"
```

### 第 6 步：台账

每个移植来的适配器**必须**在文件头写清出处，manifest 里写清作者：

```js
// <学校名>教务适配器（<平台> 平台）
// 移植自 shiguang_warehouse 的 <SCHOOL>/<file>.js
//   https://github.com/XingHeYuZhuan/shiguang_warehouse  （MIT，作者 <上游作者>）
// 移植改动：① … ② …
```

```json
"author": "上游 <上游作者>（MIT）；移植 <你的名字>",
"homepage": "https://github.com/XingHeYuZhuan/shiguang_warehouse"
```

上游是 MIT，搬进 GPL-3.0 的我们**合法**，但他们的社区公约明确要求保留贡献者记录。
照抄文件头，别让上游作者的名字在搬运中掉队。

## 4. 字段映射细则

### 4.1 周次数组 → `(startWeek, endWeek, weekType)`

上游给的是**显式周次数组**（`[1,2,3,…]`、`[1,3,5,…]`、`[2,5,9,10]` 都可能），
我们的是**极大段 + 单双周类型**。切法：排序去重后，从前往后取极大段 ——

| 数组里的形状 | 段 |
|---|---|
| 连续（步长 1） | `{startWeek: 首, endWeek: 尾, weekType: "ALL"}` |
| 隔周且都是奇数 | `{…, weekType: "ODD"}` |
| 隔周且都是偶数 | `{…, weekType: "EVEN"}` |
| 落单的一周 | `{startWeek: w, endWeek: w, weekType: "ALL"}` |

**一个上游 course 可能切出多个段** —— 那就写成该课程的**多个 block**，语义等价
（我们的 `blocks` 本来就是列表）。参考实现见 §7。

### 4.2 开学日：必填，但上游一多半没有

我们的 `firstDay` **必填**（它决定「现在第几周」，今日页/提醒/小组件/周视图列全挂在上面）。

- 有 `config.semesterStartDate` 就用它（先按 §4.3 对齐）；
- **没有就推算**（例如「最近的周一」），并且**必须在 `warnings` 里如实说**：

```json
{ "warnings": ["开学日期无法从教务获取，已按最近的周一推算，请在学期管理里核对"] }
```

这条不是客套：推算值和真值在库里长得一模一样，不说用户就没有任何机会发现。

### 4.3 每周起始日：上游的 `firstDayOfWeek` 与我们同义

上游 `AppSettingsRepository.getWeekIndexAtDate` 会先把开学日**回退到 `firstDayOfWeek`
那一天**再数周次；我们「第 1 周从 `firstDay` 的星期几开始」是同一个意思。所以映射是：

```
firstDay = semesterStartDate 往前回退到「星期几 = firstDayOfWeek」的那一天（含当天）
```

`firstDayOfWeek` 缺省 1（周一）。**别直接把 `semesterStartDate` 当 `firstDay` 用** ——
日期是周三、起始日是周一时，差了 2 天，整学期的课会偏。

### 4.4 自定义时间（`isCustomTime`，上游 23.5% 的适配器在用）

它的意思是「这门课的实际上下课时间与作息表对不上」。分两种情况：

- **同时还有 `startSection` / `endSection`**（多数情况）：按节次放进课表，
  自定义时间当作附加信息丢掉即可（可以进 `warnings` 提一句）；
- **只有自定义时间没有节次**：拿开始时间在节次表里找**最接近**的一节（差 ≤1 小时），
  找到就放进去并在 `warnings` 里说明「已按最近的第 N 节放入」；找不到就**跳过这门课**
  并写进 `warnings`。**不要**悄悄丢课。

### 4.5 上游自己会写错字段名

已经见过的：`saveCourseConfig` 传 `totalWeeks`，而上游模型定义的字段名是
`semesterTotalWeeks`（被 `ignoreUnknownKeys` 静默吃掉，学校总周数丢失）。
移植时**两个都认**，别信它文档里写的字段名，以它**实际发出来的 JSON** 为准。

### 4.6 想用 OCR / 提问就得真的写出全局名

宿主靠**源码里有没有出现 `__ncOcr` / `__ncOcrGrid`**（以及 `__ncSelect` 等）来判断
要不要等 OCR 引擎与桥就绪。所以 `if (__ncCapabilities.ocr) { __ncOcr(url) }` 没问题
（有 `__ncOcr`），但**只读 `__ncCapabilities` 不写全局名**的脚本拿不到该有的等待。
写适配器时按规范正常调用即可，不用刻意规避。

### 4.7 其他

- **学期名**：上游没有。用教务给的学期名（`MC` 之类的字段）最准；拿不到就用
  「学校名 + 学年学期」（`2026-2027学年第一学期`）这样的可读名字。**别用适配器名当学期名**
  ——用户看到「大连工程学院」会以为那是学期。
- **教师**：上游常写 `|| "未知"` 之类的兜底。我们的 `teacher` 允许为空，**空着比写「未知」好**
  （「未知」会当成真名显示）。
- **教室**：上游有些会把「教室（校区）」拼成一个串，原样带过去即可。
- **颜色**：不用管，归一化时会按课名关键词上色。

## 5. 安全审计清单（内置的硬门槛）

**审计的是安全性，不是正确性。** 我们拿不到上游学校的账号，没法验「解析得对不对」；
但「会不会碰凭据、会不会外发、读了什么」读脚本就能审完。逐条过：

| # | 检查项 | 不合格的表现 |
|---|---|---|
| 1 | **不碰凭据** | 读 `password` / `pwd` / 登录表单值 / `localStorage` 里的令牌并**外发**；读令牌用于本校接口是正常的，外发不行 |
| 2 | **不外发** | 除了本校教务接口，还有任何 `fetch`/`XHR`/`sendBeacon`/`WebSocket`/`new Image().src` 指向第三方域 |
| 3 | **请求域可控** | 逐一列出脚本请求的全部主机，写进 `allowHosts`；**通配要克制**（`*.edu.cn` 一律拒绝） |
| 4 | **只读课表** | 请求的接口里有成绩、学籍、个人信息、缴费…… 一律判不合格 |
| 5 | **不埋点** | 任何统计 / 上报 / 遥测（含「匿名」的） |
| 6 | **不 eval 远程代码** | `eval` / `new Function` 里塞了从网络取回来的字符串 |
| 7 | **不写页面** | 往教务页面写 DOM、改表单、触发提交（除上游「切到课表页」这种点击外） |
| 8 | **不依赖用户输入之外的秘密** | 硬编码的密钥、他人的学号、固定令牌 |

`allowHosts` 静态扫法：

```bash
grep -oE "https?://[A-Za-z0-9.-]+" /tmp/sgw/resources/<SCHOOL>/<file>.js | sort -u
grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*=" /tmp/sgw/resources/<SCHOOL>/<file>.js
```

上游 221 个脚本里只有 **11 个**引用超过一个域名，**100 个完全没有绝对 URL**，
所以这一条通常几分钟就过完。多出来的域多半是 CAS 登录域或学校自己的 WebVPN 网关。

**但「域是本校的」不等于可以放行**，三种情况要单独想清楚（都是本批次实测出来的）：

- **代理域（WebVPN）**：`webvpn.<校>.edu.cn` 是**代理**，放行它等于放行它背后能转发到的
  全校服务。这类学校的审计要盯「**脚本要了哪条路径**」，而不是域名归属。
  常见形态：网关子域、把内网地址重写成的子域（`zhjwxs-443.webvpn.…`）、深信服式
  `/http/<token>/…` 前缀 —— 脚本应当**请求当前页面同源**，别把主机名写死。
- **第三方托管域**：学校租的是 `<租户>.jw.chaoxing.com` 这样的租户子域，
  要放行的是**这台教务**。写成 `*.jw.chaoxing.com` 就放行了**该平台上所有学校的租户**，
  白名单形同虚设；而 `*.chaoxing.com` 我们的校验**根本不收**（通配后缀至少三段）。
  正确做法是 `allowHosts: []` + 相对路径，只放行 `loginUrl` 那一个同源主机。
- **通配 `*.` 拿不到桥**：`JwOriginRules` 会跳过通配项，所以 `allowHosts` 里写了 `*.x.edu.cn`
  的适配器，页面上 `__ncCapabilities.ocr` / `.ask` 都是 false。要用 OCR / 提问的学校
  **必须写精确主机名**（或者接受只走 DOM 解析）。

审计结论记在适配器目录下的 `AUDIT.md`（见规范 §7 的提交要求），写清：
请求了哪些域、读了什么、**移植者签名与日期**。

## 5.1 `minAppVersionCode` 写多少

规范对它的定义是「高于应用 versionCode 时明确报错而不是**行为诡异**」——
所以门槛应该卡在**结构性能力**上：

- 用了 `kind:"boxes"` / `kind:"image"` 这类**载荷种类**的 → 老版本整个不认，写对应版本
  （内置 `universal` 写 16 就是为此）；
- 只是多写了 `warnings`、用了提问桥这类**可加字段/可降级能力**的 → **写 11**。
  老版本会忽略未知字段、桥不在就跳过，导入照样成功，只是少一句提醒 ——
  这不是「行为诡异」，不该因此拒绝安装。

本批次 8 个移植件全部按后者写 11（与 `dlutci`/`ustc` 一致）。

## 6. 明确不做的

- **不自动批量转译 + 批量提交**。转译能自动化，§4 的字段映射和 §5 的审计不能。
  批量产物没有人真正读过，就不该发内置。
- **不为了凑数量搬长尾自研**（102 个）。它们交给通用适配器 + OCR。
- **不在移植适配器里加我们的私有能力**（小组件、提醒之类）——适配器只做「取课表」这一件事。
- **不搬上游的通用工具与通用适配器**，理由见 §1。
